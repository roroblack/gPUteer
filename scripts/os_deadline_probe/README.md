# 운영체제 시한 실측 도구

`허가증이 만료되면 그 노드의 작업이 정말 멈추는가` 를 잰다.

★ 이게 왜 중요한가 — `reservation_release.rs:85` 가 적어 뒀듯
  **fence 일치는 프로세스 종료의 증명이 아니다.** 만료를 근거로 예약을
  풀려면, 만료가 **추측**이 아니라 **우리가 만든 장치**여야 한다.

```text
deadline_probe.sh        시한이 띄운 놈과 무관하게 발동하는가
                         ★ D 시나리오가 핵심 — 띄운 프로세스를 SIGKILL 한 뒤에도
                           시한이 발동하는지. 이게 "운영체제가 강제" 와
                           "띄운 놈이 강제" 를 가른다
graceful_stop_probe.sh   규범이 요구한 "체크포인트 후 정지" 가 되는가
                         ★ B 시나리오가 핵심 — 여유를 넘기면 강제 종료되는지.
                           없으면 "여유가 있다" 와 "여유가 무한하다" 를 구분 못 한다
                         ★ C 시나리오 — 신호를 무시하는 작업도 죽는지.
                           CUDA 가로채기와 결정적으로 다른 점이다
windows_job_time_probe.ps1  Windows 에서 커널이 시한을 강제하는가
                         ★ B 시나리오가 핵심 — 작업 개체 손잡이를 **닫은 뒤에도**
                           커널 타이머가 발동하는지. `KILL_ON_JOB_CLOSE` 를
                           일부러 안 걸어야 "타이머가 죽인 것" 과 "손잡이가
                           닫혀 죽은 것" 을 구분할 수 있다
```

## 두 플랫폼의 차이

```text
                    Linux (systemd)   Windows (Job Object)
재는 것              벽시계             CPU 시간
정확도               정확               어림
감시 프로세스        불필요             불필요
정지 여유            있다               **없다** — 즉시 종료
권한                 **root 필요**      불필요
```

서로 다른 구멍을 덮는다 — 커널 CPU 시한은 "얼어붙은 감시" 를 덮고,
살아 있는 감시는 "계산 안 하고 VRAM 만 쥔 작업" 을 덮는다.

## 한 번 밟은 함정

첫 판은 손자 프로세스를 무한 루프로 만들었다. 그래서 **시한 없는
대조군의 범위가 영영 끝나지 않았고**, 그 프로세스가 파일을 붙들어
다음 업로드까지 실패했다. 손자에는 반드시 상한을 준다.
