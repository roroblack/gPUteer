# 만료 Lease 재접속 복원 거부 구현 리포트

- 계획: `docs/plans/2026-08-20_0136_만료_lease_재접속_거부_v1.md`
- 스트림: Coordinator · CLI selftest
- 수행: `CoordinatorLeaseStore::get_or_issue()`에 `now_unix_ms`를 추가하고,
  identity·revoked 검사 뒤 저장된 `expires_at_unix_ms`가 과거이면
  `LeaseStoreError::Expired`를 반환하도록 했다. `issue_lease()`는 이를
  기존 raw handshake 오류로 전파해 Grant 서명·전송 전에 종료한다.
  저장소 단위 테스트 2건과 selftest 시나리오 36을 추가했다.
- 시간 흐름: selftest 첫 프로세스 쌍에서 `--lease-ttl-ms 250`으로 정상 ACK를
  완료한 뒤 `thread::sleep(400ms)`로 실제 벽시계를 진행시키고, 새 프로세스
  쌍이 같은 SQLite DB로 재접속하도록 했다.
- 검증:
  - `cargo build --workspace --exclude gputeer-runtime-windows` 성공
  - `cargo test --workspace --exclude gputeer-runtime-windows` 성공
    (실패 0, 무시 1)
  - `coordinator-agent-selftest` 60초 하드 타임아웃 5회 연속 성공,
    매회 36/36
  - 만료 검사 뮤테이션(`if false && ...`)은 시나리오 36에서 실패했고,
    원복 후 최종 검증을 통과했다. 뮤테이션 상태에서는 Coordinator가
    만료 Lease를 전송하려다 Agent의 `Outcome(Expired)` 거부로 실패했다.
- 제한: `cargo fmt --all -- --check`는 현재 stable toolchain에 rustfmt
  component가 설치되지 않아 실행할 수 없었다(`cargo-fmt.exe` 부재가 아니라
  toolchain component 미설치). 코드 컴파일·테스트 검증은 완료했다.
