## 2. 재현(코드 대조) — 다섯 건

### 213 같은 보고의 재전송은 예약 해제를 다시 시도하지 않는다

```text
1. 해제 스위치 꺼짐(또는 관문 사유 — MANIFEST_UNVERIFIED 같은 고칠 수 있는 사유)으로 보고만 저장된다. Job 은 끝났고 예약은 남는다
2. 원인을 고치고(스위치 켬 · keyring 고침) Agent 가 같은 보고를 다시 보낸다
3. 저장소가 "이미 있는 같은 보고" 에서 곧바로 돌려준다 -> 해제 코드에 닿지 않는다
4. 그런데 정책 함수는 결과를 보지 않고 RESERVATION_RELEASED 를 찍는다(거짓 기록)
5. Job 은 이미 COMPLETED 라 장애 이어받기 대상도 아니다 -> 노드가 자동 경로로는 영구히 묶인다
```

### 214 STALE_COMPLETED 가 산출물 내구성 관문을 비껴간다

```text
정책 함수와 check_artifact_guard 둘 다 "완료" 를 outcome == COMPLETED 로만 본다.
attempt 저장소는 STALE_COMPLETED 도 완료(시도 COMPLETED · Job COMPLETED)로 적는다.
-> MIRRORED 를 요구한 작업이 STALE_COMPLETED 로 보고되면 Manifest 재검증 없이 NotApplicableNonCompleted 로 예약이 풀린다
```

★ 지금 이 저장소의 Agent 는 STALE_COMPLETED 를 보내지 않는다(`crates/agent/src/report.rs` 를 grep 해 COMPLETED · FAILED · INTERRUPTED 만
  찾았다 — 놓칠 수 있는 것: 다른 버전의 Agent). 그래도 수신 쪽 관문이 계약의 한 값을 빼고 보는 것은 결함이다.

### 215 INTERRUPTED 는 예약 해제와 Job 선점 전이가 두 트랜잭션이다

```text
1. 소유자 선점 INTERRUPTED 보고 -> 보고 저장 + 예약 해제가 먼저 커밋된다(INTERRUPTED 는 시도 종료 상태가 없어 Job 을 안 건드린다)
2. 그 뒤 별도 연결 · 별도 트랜잭션에서 failover::pause_for_owner_preempt
3. 그 사이 프로세스가 죽거나 2 가 실패하면 "예약 없음 + Job RUNNING" 이 남는다
4. 재전송은 정책 함수의 NO_RESERVATION 분기에서 먼저 돌아가 선점 전이를 다시 시도하지 않는다
```

★ 정책 함수 주석("같은 커밋")이 INTERRUPTED 에서는 사실이 아니었다.

### 216 RUNNING Job 의 시도가 "실행 전 실패" 로 끝나면 trigger 를 STAGING_FAILED 로 적는다

```text
선점 뒤 다시 배치된 Job 은 새 시도가 CREATED 인 채로 이미 RUNNING 이다(RESUMED).
그 시도가 Grant 거부(CANCELLED) 또는 기동 실패(FAILED, 종료 관측 없음)로 끝나면
follow_attempt_terminal 이 (Failed, StagingFailed) 를 고르고 walk 가 RUNNING -> FAILED 를 통과시킨다.
RUNNING -> FAILED 의 trigger 는 UNRECOVERABLE_ERROR 다. walk 는 상태 쌍만 보고 trigger 를 안 본다.
```

★★ **검수자 제안 중 받지 않은 것** — "CANCELLED 시도는 Job CANCELLED(USER_CANCELLED)로" 는 규범과 맞지 않는다.
  Agent 가 보내는 시도 CANCELLED 는 규범 Attempt 표의 `CREATED -> CANCELLED` 중 **GRANT_REJECTED**(Agent 검증 실패)이고,
  `JOB_CANCELLED` 쪽은 Job 취소를 **따라가는** 전이다. USER_CANCELLED 는 사용자의 Job 취소 요청이고 이 풀에는 그 입력이 없다.
  그래서 CANCELLED 시도는 전처럼 "실행 전 실패" 로 둔다 — 고칠 것은 RUNNING 에서의 trigger 뿐이다.

### 217 풀이 채울 수 없는 durability 를 요구한 작업이 끝나면 노드를 영구히 묶는다

```text
1. Manifest durability = MIRRORED(기본값이 LOCAL 이 아니면 흔하다)
2. 풀이 그 작업을 배치하고 작업이 COMPLETED 를 보고한다
3. 해제 관문이 ARTIFACT_DURABILITY_MIRRORED 로 예약을 남긴다 — 이 풀은 복제를 하지 않으므로 그 조건은 영영 안 채워진다
4. Job 은 COMPLETED 라 장애 이어받기 대상이 아니다 -> 사람이 release-lost-node 로 풀기 전까지 노드가 묶인다
```

★ 검수자는 "규범의 guard(최종 artifact COMMITTED 확인)가 성립하지 않는다" 고 적었다 — 규범 표에서 그 문구는 guard 칸이 아니라
  **effect 칸**이다(guard 는 "canonical attempt 확정"). 그러나 결과(노드가 묶인다)는 그대로 성립한다.
