# 종료 보고 outbox 가 이름을 바꾼 뒤 디렉터리를 sync 하지 않는다 — 주석의 근거가 틀렸다 (결함 561)

> **발견** 2026-09-28 11:24(코덱스 b5 — 단계 2 계약 초안 검수 중 곁가지로 짚음 · 브랜치 `fork-merge` · `12a465b`) · **상태** 수정함(아래 조치) ·
> **결함 번호** 561

## 위치

`crates/agent/src/lib.rs:2520~2556` `persist_report_to_outbox` — 임시 파일에 쓰고 `sync_all` → `rename` 으로 끝난다. 디렉터리 sync 가 없다. 주석(2522~2523):
"디렉터리 sync 는 하지 않는다 — Windows 에는 같은 수단이 없다(ADR-026). 전원이 끊기면 마지막 이름 바꾸기가 사라질 수 있다는 한계가 남는다".

**주석의 근거가 틀렸다.** 같은 저장소의 `gputeer_checkpoint::sync_dir`(`crates/checkpoint/src/atomic.rs` — `lib.rs:13` 에서 공개)가 Windows 에서도 디렉터리 핸들을
`FILE_FLAG_BACKUP_SEMANTICS` · 쓰기 권한으로 열어 `FlushFileBuffers` 한다(`atomic.rs:380` 부근 · `CLAUDE.md` §0.3 "sync_dir Windows 는 쓰기 권한 필요"). 체크포인트의
`write_once` 와 시작 기록(started-attempts)은 이미 그것을 쓴다(`atomic.rs:289`).

## 반례

```text
작업 종료 관측 → 서명한 AttemptReport 를 outbox 에 임시 파일 → sync_all → rename → (디렉터리 메타데이터가 아직 디스크에 없음) → 전원 차단
→ 재부팅 뒤 rename 이 사라져 임시 파일만 남거나 둘 다 없음 → 다음 회차 재전송이 보고를 찾지 못한다 → 그 시도의 종료가 Coordinator 에 영영 가지 않는다
   (주석 스스로 "보고는 다시 만들 수 없다 — 종료 관측이 메모리에만 있었다" 고 적었다)
```

## 위험도

**중간.** 전원 차단이라는 드문 조건에서만 나지만, 나면 종료 보고를 잃는다 — Coordinator 는 Lease 만료로만 알게 되고(이어받기), 예약 해제의 증거가 없다.

## 고칠 방향 (수정 전에 적는다)

rename 뒤 `gputeer_checkpoint::sync_dir(dir)` 를 부른다. 실패하면 `ATTEMPT_REPORT_OUTBOX_FAILED` 로 올린다 — 파일은 이미 새 이름으로 있으므로 다음 회차의 재전송이
줍는다(조용히 삼키지 않는다). 주석을 고친다. ★ Ack 뒤 outbox 파일 **삭제**도 디렉터리 sync 가 없다 — 전원 차단으로 삭제가 사라지면 같은 바이트를 다시 보내고,
Coordinator 는 같은 바이트를 멱등으로 받는다(`created=false`) — 해가 없어 이번에 고치지 않는다.

## 정정

- 단계 2 계약 초안 v1~v5 가 이 주석을 그대로 옮겨 "Windows 는 디렉터리 sync 가 없다" 고 적었다 — v6 에서 고쳤다.
