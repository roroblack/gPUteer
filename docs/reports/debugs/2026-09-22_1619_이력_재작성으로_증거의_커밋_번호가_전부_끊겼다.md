# 이력 재작성으로 증거 79건의 `commit` 번호가 저장소에서 사라졌다 — 새로 복제하면 재현 불가

> **발견** 2026-09-22 07:18 (리눅스 시험이 처음 전부 통과하자 그 다음 단계에서 드러났다) · **기록** 2026-09-22 16:19 ·
> **상태** CI 로그로 확인 · 로컬 대조 완료 · **결함 번호** 207 · ★ **내가 만든 결함이다**

## 1. 위치

```text
docs/evidence/*.md  frontmatter 의 commit: 필드 (79개 파일 전부)
scripts/verify_evidence.py:251 commit_exists()  git cat-file -t 로 존재를 확인한다
```

원인은 **2026-09-18 의 이력 재작성**이다. 원격 공개 저장소에 올라간 민감한 값(공인 IP · 계정 · 호스트)을
지우려고 `git filter-repo` 로 전 이력을 다시 썼고, 그때 **모든 커밋 번호가 바뀌었다.**
증거 문서들은 옛 번호를 가리킨 채로 남았다.

★ **개발 기계에서는 이 결함이 안 보였다.** filter-repo 가 옛 객체를 지우지 않고 남겨 둬서
`git cat-file` 이 여전히 찾아낸다 — 어느 가지에서도 **닿지 않는데도** 그렇다.
`git merge-base --is-ancestor <옛 SHA> main` 은 실패한다(확인함).
새로 복제한 CI 는 그 객체가 없으므로 정직하게 실패한다.

## 3. 실측 — 무엇이 깨졌고 무엇은 안 깨졌나

- **증거의 내용(claim · 측정값 · 원문 digest)은 그대로다.** 깨진 것은 "그 측정이 어느 코드 상태에서 나왔나" 를 가리키는 **포인터**다.
- 그래도 이건 **진짜 손실이다** — `ADR-029`·`RULE.md` 가 증거에 커밋을 적게 한 이유가 재현 가능성이다.
  포인터가 끊기면 "이 숫자가 어느 코드에서 나왔는지" 를 되짚을 수 없다.
- **복구 수단이 지금은 있다** — `.git/filter-repo/commit-map`(459줄, 옛->새 대응표). ★ **이 파일은 커밋되지 않고 이 기계에만 있다.**
  지우면 대응표가 사라져 복구가 불가능해진다. 그래서 **지금 고친다.**
- 이력 재작성 자체를 되돌리지는 않는다 — 그건 민감한 값을 다시 올리는 일이다.
