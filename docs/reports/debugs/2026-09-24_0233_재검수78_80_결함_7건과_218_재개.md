## 2. 재현(코드 대조)

### 233 ACK 를 적지 않았는데도 수신 확인을 보낸다 (검수 78, P1)

`record_grant_accepted` 는 NOT_CURRENT_ATTEMPT(시도가 이미 대체됨) · CLOCK_BEHIND_STAGING 에서 **아무것도 적지 않고** `Ok` 를 돌려주는데,
호출부는 결과를 로그에만 찍고 수신 확인을 보낸다.

```text
시도 A 의 Lease 가 짧다 -> A 가 ACK 전에 큰 체크포인트를 복원하는 동안 Lease 가 만료 -> 스케줄러가 A 를 되돌리고 B 를 다른 노드에 배치
A 의 늦은 ACK 는 서명 · 식별자 검사를 지나고 NOT_CURRENT_ATTEMPT -> 그래도 수신 확인 -> A 가 실행 -> B 도 실행(두 번 돈다)
```

★ 제안서 · signing.md · proto 주석의 "검증 · 기록한 뒤에만" 이 코드보다 강한 주장이었다.

### 218 재개 — 수신 확인 유실 시 한 번도 안 돈 작업이 FAILED · 노드 고착 (검수 78 · 80)

1차에서 "계약 변경이 필요하다" 며 한계로 뒀다. 두 검수자가 **"원인 설명이지 결함을 닫는 근거가 아니다"** 라고 짚었다. 그리고 계약을 바꾸지
않는 해법이 있었다 — Agent 가 워크로드를 띄우기 직전에 "이 시도를 시작했다" 를 노드 로컬에 영속으로 적고, 그 기록이 있는 시도에는 ACK 하지
않는다. 그러면 Coordinator 는 STARTING 에 멈춘 시도를 **같은 노드에** 다시 내줄 수 있다(안 돈 것은 다시 돌고, 돈 것은 다시 안 돈다).

★ 제안서의 호환성 문장("옛 Coordinator 조합에서 시도는 CREATED 로 남는다")도 틀렸다 — ACK 기록은 풀 밖 control DB lane 에도 이미 있었다.

### 234 공유 저장소 장애가 최초 종료 보고까지 롤백한다 (재검수 79 — 내 215 수정이 만든 결함)

선점 전이를 보고 트랜잭션 안에 넣었더니, 이어갈 지점 조회(`list_signed_manifests`)가 공유 저장소 장애로 실패하면 보고 INSERT 까지 롤백된다.
저장소가 계속 죽어 있으면 보고가 **영영 저장되지 않는다**(증거 보존 위반). 정책 함수 주석("보고까지 롤백되면 증거를 잃으므로 먼저 본다")과도 어긋난다.

### 236 PAUSED 비-LOCAL Job 이 FIFO 맨 앞을 영구 점유한다 (재검수 79)

거부 분기가 QUEUED 에서만 FAILED 로 내리고 PAUSED 는 오류만 반환한다. 다음 tick 도 같은 Job 을 고른다 — 뒤 LOCAL 작업이 영영 못 간다.

### 237 되찾음 판정이 벽시계 숫자 비교라, 시계가 뒤로 가면 되찾은 노드가 다시 후보가 된다 (재검수 80)
