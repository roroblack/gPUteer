# 관측된 종료의 실패를 "기동 실패" 경로로 골랐다

> **발견** 2026-09-23 18:40(신뢰망 남은 일 A — Job 이 시도의 끝을 따라가게 하는 시험) · **상태** 원인 확인 · **결함 번호** 210

## 1. 위치


## 2. 재현

```text
보고   outcome=FAILED · exit_observation=OBSERVED_WITH_CODE · exit_code=3   (돌다가 코드 3 으로 끝났다)
기대   Created -> Starting -> Running -> Failed      (WORKLOAD_EXITED_ERROR)
실제   Created -> Starting -> Failed                 (START_FAILED — 프로세스가 뜨지 못했다)
```

`normative_path()` 가 후보 경로를 **짧은 것부터** 시험하고 처음 통과한 것을 고른다.
`Starting -> Failed`(START_FAILED)가 규범에 있으므로, 종료가 관측됐어도 항상 그 경로가 먼저 뽑혔다.
관측이 **없을 때** Running 을 끼우지 않는 검사는 있었지만, 관측이 **있을 때** Running 을 요구하는 검사가 없었다.

## 3. 실측 — 무엇을 확인했고 무엇을 안 했나

- 확인: 새 시험 `each_outcome_moves_the_job_along_the_norm` 이 이 경우 Job 을 `STAGING_FAILED` 로 적어 실패했다
- DB 에 쓰는 **최종 Attempt 상태는 둘 다 FAILED** 라 저장된 값 자체는 틀리지 않았다 —
  2026-09-22 의 시험들이 못 잡은 이유다. 틀린 것은 **어느 전이로 거기 갔느냐** 였고,
  그 경로를 처음으로 소비한 코드(Job 종료 전이)가 드러냈다
