| # | 심각도 | 결함 | 반례 요지 |
|---|---|---|---|
| 509 | 높음 | 505 · 507 이 완결되지 않았다 — 설치기 **안의** `PATH` 고정은 설치기가 돈 뒤에야 효과가 있다. 런북이 안내하는 `sudo git …` · `sudo sh …` · `sudo install` · `sudo cp` 와 설치기가 찍는 `sudo sh $0 …` · `sudo systemctl restart …` 는 sudo 가 실행할 프로그램을 **부른 계정의 PATH** 에서 고른다(sudoers 의 `secure_path` 는 기본값이 아니다) | 노드 계정으로 돈 작업이 `$HOME/bin/sh` · `$HOME/bin/git` 을 둠 · 계정 PATH 가 `$HOME/bin:…` · `secure_path` 없음 → 운영자가 런북대로 `sudo sh …/install-node.sh` · `sudo git clone …` → 가짜 `sh` · `git` 이 UID 0 으로 돈다(설치기의 `/usr/bin/id` 검사 · PATH 고정보다 먼저) — 계정 경계를 넘는다 |

## 조치

| 무엇을 바꿨나 | 확인 |
|---|---|
| 런북 `--register` 절차의 root 진입 명령을 전부 절대 경로로 바꿨다 — `/usr/bin/sudo /usr/bin/git …` · `/usr/bin/sudo /usr/bin/install …` · `/usr/bin/sudo /bin/cp …` · `/usr/bin/sudo /bin/sh …/install-node.sh …`. 설치기가 찍는 안내(`INSTALL_AS_ROOT` · `RESTART_NEEDED` · `NOT_REGISTERED`)도 `/usr/bin/sudo /bin/sh` · `/usr/bin/sudo /usr/bin/systemctl` 로 바꾸고 옛 "sudo sh $0" 대신 root 소유 사본 절차를 가리킨다 | `sh -n` · `check_docs.py` · 런북 · `deploy/` 전체에서 `sudo ` 로 시작하는 root 진입 명령이 남지 않았는지 검색(`docs/runbooks` · `deploy` · `README.md` · `docs/manuals` — `docs/plans` 등 옛 기록 문서는 보지 않았다) |
| 런북에 **막지 못하는 것**을 적었다 — 명령을 치는 셸도 그 계정의 것이라, 그 계정의 작업이 셸 설정 파일을 바꾸면 절대 경로도 우회된다. 등록은 작업을 받기 전(처음 설치할 때)에 하고, 뒤에 다시 하려면 설정 파일을 읽지 않는 셸에서 하되 그 계정의 작업이 이미 돌았다면 보증이 없다. 근본 대책은 Agent 를 sudo 권한 없는 계정으로 두는 것 — 등록할 때만 주고 거둔다 | 문서 대조 |

★ 코드 시험이 없다 — 절차 · 안내 문구다. 진짜 root · 진짜 sudo 에서 돌리지 않았다.
