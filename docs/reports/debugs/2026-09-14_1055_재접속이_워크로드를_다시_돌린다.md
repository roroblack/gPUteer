# 재접속이 워크로드를 다시 돌린다 — 재접속 가능한 오류가 실행 뒤에도 난다

> **발견** 2026-09-14 10:55 · **발견 경위** 결함 ⑱ 설계 A(ACK 를 실행 전으로)를 준비하며 Agent 재접속 루프를 읽다가 ·
> **상태** 코드로 확인 · 실측 안 함

## 1. 위치

```text
crates/agent/src/lib.rs  run()               재접속 루프 — Retryable 이면 run_one_connection 을 **처음부터** 다시 부른다
crates/agent/src/lib.rs  run_one_connection  Grant 검증 -> 시작 마커(write_once, 같은 내용이면 Ok(false)) -> 실행
crates/agent/src/lib.rs  peer_closed_after_ack  보고 뒤 50ms peek — 닫혀 있으면 "RETRYABLE_CONNECTION"
```

## 2. 재현 (코드 경로)

재접속이 켜진 Agent(`--disable-reconnect` 없음) · 실행 opt-in · Manifest 가 실린 Grant ·
`--max-connections 2` 이상인 Coordinator.

```text
1  워크로드가 끝까지 돈다(지금은 ACK 전)
2  ACK · (보고) 전송
3  peer_closed_after_ack 가 닫힘을 본다 -> RETRYABLE_CONNECTION
4  run() 이 다시 연결 -> 같은 grant_id · attempt_id 로 Grant 검증 -> 시작 마커는 멱등이라 통과
5  워크로드 블록이 작업 디렉터리를 지우고 **다시 실행한다**
```

`crates/agent/src/lib.rs` 에서 "already" · "이미 실행" · "재실행" · "rerun" 을 grep 했고 재실행을 막는
검사가 안 나왔다. 이 검색은 다른 이름의 검사를 놓칠 수 있다.

## 3. 실측

**안 했다.** 지금 순서(ACK 가 실행 뒤)에서 3 은 Coordinator 가 50ms 안에 닫는지에 달려 있어 매번 나지
않는다(결함 ⑳ 과 같은 경쟁). ★ 설계 A 로 ACK 를 실행 전에 보내면 기본 Coordinator 는 ACK 직후 닫으므로
실행이 끝날 즈음엔 **거의 항상** 닫혀 있다 — 이 경로가 흔해진다. 그래서 A 와 같이 막는다.
