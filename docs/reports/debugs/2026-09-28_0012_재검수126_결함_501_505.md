| 502 | 높음 | `kill` 이 0 이면 멈춤을 확인하지 않고 멈춘 것으로 본다(`stop_and_confirm` · 종료 못 본 경로). 그래서 `logs_complete = stopped && saved`(496)의 `stopped` 가 약하다 | kill 이 신호만 접수하고 0 → init 이 아직 돔 → logs 는 그 순간까지 → stopped · 완결로 기록 → rm 이 실제로 끝냄 → 그 사이 출력 유실 · 표식 없음(start 실패 · 종료 못 봄 · 남은 컨테이너 정리 셋 다) |

| 504 | 중간 | 사건 표식이 "왜" 를 보존한다는 런북 주장보다 코드가 약하다 — 정상 종료 뒤 rm · logs 실패 사유는 `eprintln!` 으로만 나가고 표식에는 `종료 코드 · 로그 완결 · ContainerLeft` 만 남는다. agent-loop 는 `CONTAINER_NOT_REMOVED` · `CONTAINER_KEPT_FOR_LOGS` · `CONTAINER_INCIDENT_RECORDED` 를 옮겨 찍지 않는다 | rm 이 permission denied → 서비스 로그와 표식 어디에도 사유가 없고 표식에는 `컨테이너 Unknown` 만 |

## 조치

| # | 무엇을 바꿨나 | 확인 |
|---|---|---|
| 501 | 종료를 읽는 `inspect` 에 `{{.State.StartedAt}}` 를 더하고, 멈춰 있어도 시작 시각이 비었거나 `0001-01-01…`(docker · podman 의 "시작 안 함")이면 `INSPECT_NEVER_STARTED` 로 **관측 실패**로 센다 — 다섯 번이면 종료를 못 본 경로(멈춤 확인 → 로그 → 둘 다일 때만 삭제 · 결과는 "종료 코드 없음")로 간다. 멈춤 확인용 조회(`inspect_running` — `{{.State.Running}}` 만)는 따로 둔다(시작 안 한 컨테이너도 "돌지 않는다") | 단위 시험 `a_never_started_container_is_not_an_exit`(docker · podman 형식 · 시각 없음) · podman 시각의 공백 처리. 가짜 런타임 `start-noop`(start 가 0 인데 아무것도 안 띄움)으로 `a_never_started_container_is_never_read_as_exit_zero`(run → `Unobserved` · `execute` → 종료 코드 없음) |
| 502 | `stop_and_confirm` 이 `kill` 의 0 을 멈춤으로 보지 않는다 — kill 뒤 `inspect_running` 이 "돌지 않는다"(또는 "없다")고 할 때까지 최대 10번 · 200ms 간격으로 다시 본다. 종료를 못 본 경로의 `stop_confirmed`(kill 0 이면 멈춤)를 없애고 `stop_and_confirm` 을 쓴다. `ContainerStopper::stop` 의 "이미 끝났다" 판정도 `inspect_running` 으로 본다 | 가짜 런타임 `kill-noop`(kill 이 0 인데 안 멈춤) · `inspect-exit`(종료 상태 조회만 실패)로 `a_kill_that_does_not_stop_is_not_a_stop`(run → `stopped: false · logs_complete: false · Kept` · start 뒤 rm 없음 / 남은 컨테이너 정리 → Err · rm 없음) |
| 503 | `remove_container_fact` 가 `rm` 의 0 뒤에 `inspect` 로 **없어졌는지** 본다 — "없다" 일 때만 `Removed`, 아직 있으면 · 모르면 `Unknown`. 남은 컨테이너 정리도 같은 함수를 쓴다(지웠는지 확인하지 못하면 기동을 멈춘다) | 가짜 런타임을 "있는가" 모델로 바꿨다(없는 이름의 inspect · rm 은 `No such container`). `rm-noop`(rm 이 0 인데 안 지움)으로 `an_rm_that_leaves_the_container_is_not_a_removal`(정상 종료 → 종료 0 유지 · `Unknown` · 사람 필요 / 남은 컨테이너 정리 → Err) |
| 504 | `ContainerExit.note` 를 새로 두어 로그 받기 · 정리의 런타임 오류 문장을 싣고, 사건 표식 `detail` 에 넣는다. agent-loop 가 `CONTAINER_INCIDENT_RECORDED` · `…_OPEN` · `…_UNKNOWN` · `CONTAINER_NOT_REMOVED` · `CONTAINER_KEPT_FOR_LOGS` · `CONTAINER_LEFTOVER…` · `WORKLOAD_DIR_KEPT` · `WORKLOAD_MAY_BE_RUNNING` 을 서비스 로그로 옮겨 찍는다 | `a_cleanup_failure_keeps_the_observed_exit_and_records_an_incident` 에 표식 본문에 "rm 실패" 와 런타임 오류 문장이 있다는 단언 · `an_rm_that_leaves_the_container_is_not_a_removal` 에 `note` 단언 |
| 505 | `install-node.sh` 가 `/usr/bin/id -u` 로 root 를 보고, root 면 **첫 명령 전에** `PATH=/usr/sbin:/usr/bin:/sbin:/bin` · `IFS` 기본값으로 고정한다(사용자 단계는 그 계정 권한이라 그대로) | `sh -n` 구문 검사 · `IFS` 값이 공백 · 탭 · 줄바꿈인지 `od` 로 확인. ★ 진짜 root 에서 돌리지 않았다 — 전에 쓴 가짜 root(PATH 의 `id` 로 흉내)는 절대 경로 `/usr/bin/id` 를 속이지 못해 이 경로를 재지 못한다 |

기존 시험 기대값을 바꾼 곳 — 정상 종료의 호출 순서 끝에 `inspect`(지운 뒤 확인)가 붙었고, 종료를 못 본 경로의 시험은 `inspect` 전체 실패 대신 `inspect-exit` 를
쓴다(전체 실패면 이제 멈춤을 확인할 수 없어 지우지 않는 것이 맞다 — 그 경우는 `an_unconfirmed_stop_never_removes_the_container` 가 본다). 반쯤 만든 컨테이너의
rm 은 가짜 런타임이 "없다" 로 답해 `removed` 파일 단언을 뺐다(호출 여부는 그대로 본다).

★ 남는 것 — 멈춘 컨테이너의 `logs` 가 0 으로 끝나면 완결로 본다(런타임 밖에서 확인할 길이 없다). `inspect` 의 답 자체도 런타임의 것이다. 런북에 "런타임을 그대로
믿는 곳" 으로 적었다.
