## 2. 재현(코드 대조)

### 218 ACK 는 기록됐는데 수신 확인만 유실되면, 한 번도 안 돈 작업이 RUNNING 으로 묶인다

```text
1. Agent(--require-ack-receipt true)가 Grant 를 받고 ACK 를 보낸다
2. Coordinator 가 ACK 를 기록한다(시도 STARTING · Job RUNNING) — 그 직후 연결이 끊겨 확인만 유실된다
3. Agent 는 ACK_RECEIPT_MISSING 으로 **실행하지 않는다**
4. agent-loop 가 다시 FRESH 로 붙지만 시도가 STARTING 이라 Grant 를 다시 내주지 않는다. 확인을 다시 주는 경로도 없다
5. 장애 이어받기를 켜면 Lease 만료 뒤 NODE_LOST -> 체크포인트 없음 -> FAILED(NO_COMMITTED_CHECKPOINT), 예약은 만료 표시만 되어 운영자가 풀 때까지 묶인다
   켜지 않으면 Job 은 RUNNING 으로 남는다
```

★ `--require-ack-receipt` 를 **끄면**(기본값) 반대쪽 위험이 있다 — ACK 를 보낸 즉시 실행하므로, ACK 가 기록되기 전에 끊기면 시도는
  CREATED 로 남고 다음 FRESH 연결이 같은 시도에 새 Grant 를 내 **두 번 돈다.** 그래서 풀 운영에서는 켜야 한다(런북 · deploy 틀은 켠다).

### 219 같은 공개키를 여러 노드 ID 에 등록할 수 있다

```text
--pool-agents "A=K;B=K" 가 시작 관문을 통과한다(ID 중복만 거부). 키 K 를 가진 Agent 가 --agent-device-id B 로 붙으면
B 의 이름으로 서명이 검증되고 B 의 예약 Grant 를 받는다. 운영 실수 하나로 신원 경계가 사라진다
```

### 220 풀 모드가 생존 DB 를 control DB 와 같게 강제하지 않는다

```text
--liveness-db 를 안 주거나 다른 파일로 주면 Hello 관측이 스케줄러가 보는 control DB 에 없다.
scheduler-tick --silent-after-ms 가 모든 노드를 "소식 없음" 으로 빼 큐가 영영 배치되지 않는다
```

### 221 거부될 Hello 도 생존 관측으로 먼저 적는다

```text
서명은 맞지만 mode 가 풀이 받지 않는 값(RESUME · UNSPECIFIED)인 Hello 가 반복되면, 매번 session_seen 이 갱신되고 연결은 HELLO_REJECTED 로 끝난다.
스케줄러는 그 노드를 살아 있다고 보고 일을 준다 — 그 노드는 FRESH 세션을 못 만들어 Grant 를 못 받는다
```

### 222 `--accept-timeout-ms 0`(풀 모드 "끝없이") 이 실제로는 365일이다

```text
마지막 연결 뒤 365일 동안 연결이 없으면 accept timeout exceeded 가 run() 밖으로 나가 상시 Coordinator 가 끝난다.
주석은 "기다림에 끝이 없다" 고 적었다
```
