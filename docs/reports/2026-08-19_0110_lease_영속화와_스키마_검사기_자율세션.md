## 2. 스스로 찾은 함정 2건 (코덱스가 아니라 뮤테이션 테스트로)

### 2.1 `DoD-14` — 공허한(vacuous) restart-defense 시나리오

Agent 의 제어 흐름은 같은 프로세스 안에서 **최초 Grant 검증이 항상
갱신 검증보다 먼저** 실행된다. "갱신 경로 전용" restart-defense
시나리오를 짜면, 저장소가 진짜 영속인지와 무관하게 같은 프로세스의
최초 Grant 검증이 이미 판별에 쓰일 watermark 값을 써 버려서
**공허하게 통과**한다. `DurableFenceWatermark::open()` 을 뮤테이션으로
무력화해도 이 시나리오는 여전히 통과했다 — 설계·시나리오를
"최초 발급 단독"(`do_renew=false`) 형태로 다시 짜서 해소했다.
`docs/evidence/DoD-14_durable_fence_watermark.md` 에 상세.

이 교훈을 `DoD-16`(Coordinator 저장소)의 시나리오 20·21 설계에도
그대로 적용해 같은 함정을 두 번째로 피했다.

### 2.2 (자체 발견, 이번엔 문제 없음으로 판정) — `RESULT_OK_MARKER` 부분 문자열

`coordinator-agent-selftest` 시나리오 19(반복 갱신 3회)를 셀 때
`"RESULT ok=true"` 가 `"RENEW_RESULT ok=true"` 의 부분 문자열이라
`.matches().count()` 가 과다 계수됐다 — `.lines().filter(starts_with(...))`
로 고쳤다. 코덱스 검수 전에 직접 실행 결과를 보다가 스스로 발견.

## 3. 방법론 — 뮤테이션 테스트 총 14회

**통과하는 테스트는 아무것도 증명하지 않는다.** 새로 만든 가드는 전부
일부러 깨봤다. 전부 원복 후 재통과를 확인했다.

| 가드 | 뮤테이션 | 결과 |
|---|---|---|
| `DurableFenceWatermark::open()` | 경로 무시하도록 무력화 | restart-defense 시나리오가 §2.1 처럼 공허하게 통과 → 시나리오 재설계 |
| `derive_renew_nonce(lease_id, round)` | `round` 고정 | 2회차가 예측대로 `Replay` 로 거부 |
| `CoordinatorLeaseStore::get_or_issue()` | 반환값 무시하고 candidate 그대로 사용 | 시나리오 20 이 예측대로 Agent watermark 불일치로 실패 |
| Coordinator epoch 대조 | `expected_epoch` 를 `config.fence_epoch` 로 하드코딩 | 시나리오 21 이 "기대값 불일치" 로 예측대로 실패 |
| `RevokeLeaseNotice` 정상 테스트 | payload 필드 assert 제거 상태(수정 전) 유지 여부 확인 | 필드가 안 맞아도 통과함을 확인 → assert 추가로 수정 |
| `renew_existing_within_duration()` 초과 판정 | `false && ...` 로 무력화 | 시나리오 22 가 예측대로 outcome=1(정상 갱신)로 실패 |
| 위 함수의 "초과 시 UPDATE 안 함" | 초과해도 UPDATE 강행하도록 변경 | 저장소 불변 확인이 예측대로 실패(만료시각 실제 증가) |
| Agent `RenewOutcome` 매치 | `6 =>` 분기 제거 | 시나리오 22 가 "알 수 없는 outcome" 으로 예측대로 실패 |
| override-우선 수정(`DoD-18` §8) | 예전(결함 있는) 순서로 되돌림 | 신규 시나리오 24 가 예측대로 실패(override 인데 저장소 갱신) |
| `check_identity_conflict()` | attempt_id/holder_node_id/issuing_coordinator_id 검사 3개 제거 | 신규 테스트 3건이 각각 예측대로 실패 |
| `RenewLeaseResult` framed 테스트 | `detail` 기대값을 고의로 틀리게 | 정확히 그 이유로 실패 |
| `canonical_vectors.rs` domain 배열 | 타입(`map_ss`→`bytes`) 오염 | `check_schema.py` 가 field-type 오류로 검출 |
| 위 배열 | field number/이름 오염(2건 동시) | `check_schema.py` 가 각각 다른 오류로 검출 |
| `check_schema.py::SIGNATURE_FIELD_NUMBER` | `-1` 로 무력화 | 설계 단계에서 손으로 찾은 정확히 그 3건(field 90 실제 drift) 이 재현 |
| `check_schema.py::build_descriptor_set()` | 임시 파일 생성 실패를 mock | 수정 전 버전은 처리되지 않은 예외로 새는 것을 재현, 수정 후엔 정확히 `exit(2)` |
