## 독립 검수 후속 보강 (2026-08-20)

### 수정 내용

독립 검수가 지적한 대로 기존 후보들은 `holder_node_id` 외 값이 모두 같아
패자 값의 부분 덮어쓰기를 검출하지 못했다. 후보 생성에 A/B 표식을 도입해
다음 값을 구별했다.

- `holder_node_id`: `node-a` / `node-b`
- `fence_epoch`: `1000 + round` / `2000 + round`
- `issuing_coordinator_id`: `coordinator-a` / `coordinator-b`
- `coordinator_term`: `101` / `202`
- `issued_at_unix_ms`, `renew_after_unix_ms`, `expires_at_unix_ms`: 각각 기존
  기준 시각에 `1000 + round` / `2000 + round` 표식 오프셋
- `max_total_duration_seconds`: `60` / `61`

같은 lease의 holder 충돌을 재현하기 위해 `lease_id`와 identity 비교상
`holder_node_id`보다 먼저 검사되는 `job_id`·`attempt_id`는 동일하게
유지했다. 코드에서 비교 순서가 `job_id -> attempt_id -> holder_node_id ->
issuing_coordinator_id`임을 확인했으므로, 마지막 coordinator identity도
구별하면서 기존 `holder_node_id` 충돌 판정을 유지했다.
`revoked_at_unix_ms`는 최초 발급 SQL이 후보 값 대신 항상 `NULL`을 쓰는
lifecycle 상태라 두 후보 모두 `None`이다.

최종 raw SQLite 검증은 winner뿐 아니라 loser도 라운드별로 보존한다.
저장 행 전체와 winner의 `assert_eq!`에 더해, 구별 가능한 8개 필드를
loser와 각각 `assert_ne!`하여 패자 표식 혼입 위치를 직접 드러낸다.

### assertion 판별력 self-check

`complete_winner_assertion_rejects_each_loser_marker` 테스트를 추가했다.
winner 복제본의 `holder_node_id`, `fence_epoch`, `expires_at_unix_ms`,
`issuing_coordinator_id`, `coordinator_term`, `issued_at_unix_ms`,
`renew_after_unix_ms`, `max_total_duration_seconds`를 하나씩 loser 값으로
교체한 합성 행 8개를 만들고, 실제 최종 검증 helper가 매번 panic하는지
`catch_unwind`로 확인한다. 따라서 최종 assertion이 패자 필드의 단일 혼입을
실제로 거부함을 실행으로 검증했다.
