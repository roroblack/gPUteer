## 왜 필요한가 (이것 없이 막히는 것)

2026-09-30 규범 변경(`docs/protocol/state-machines.md` "STALE 의 의미" 신뢰망)으로 노드는 Coordinator 와 끊긴 채 **끊김 시한**이 지나면 작업을
스스로 멈춘다(`--disconnect-stop-margin-ms`). 노트북처럼 **끊길 것을 미리 아는** 노드(이동 · 네트워크 전환)도 그 시한에 멈춘다 — 사용자는
"통보했다면 계속 작업하는 게 맞다" 고 했다. 노드가 혼자 판단해 계속 돌면 Coordinator 는 Lease 만료 + 유예 뒤 다른 노드에 다시 맡긴다(두 벌).
그래서 **Coordinator 가 서명해 Lease 를 늘려 줄 때만** 계속 돈다 — 그 동안은 지금 규칙대로 재배치하지 않는다.

## 규칙 (MUST)

```text
Agent
  1  주인 화면에서 "N 분 뒤까지 끊긴다" 를 받으면 다음 갱신(곧바로 하나 보낸다)에 22 를 채우고 schema_version 2 로 서명한다
  2  계속 돌 자격은 **서명된 RenewLeaseResult 의 중첩 Lease 만료**로만 얻는다(알림을 보냈다는 사실이 아니다). 답을 못 받으면 원래 시한에 멈춘다
  3  알림을 실은 갱신이 실패하면 다음 갱신은 22 없이(v1) 보낸다 — 옛 Coordinator(최대 1)가 v2 를 SCHEMA_TOO_NEW 로 거부해도 갱신이 끊기지 않게
Coordinator
  4  schema_version < 2 인데 22 가 차 있으면 거부(검증 뒤 · 형식 오류)
  5  22 가 now 이하이거나 운영자 상한 `--planned-unreachable-max-ms` 가 0(기본 · 꺼짐)이면 **평소 연장**(renew_extension_ms)으로 답한다 — 거부하지 않는다
  6  그 밖에는 연장 = min(22 − now, 상한) 을 쓰되 평소 연장보다 짧게 주지 않는다. 그리고 마지막에 **작业 누적 상한**(issued_at + max_total_duration)
     까지로 자른다 — 알림이 없는 RENEW 세션 갱신에도 걸린다(검수 an1). 요청 시각을 검사 없이 그대로 주지 않는다
  6a FRESH 연결 안의 갱신은 알림을 다루지 않는다 — v1 만 읽고 22 가 차 있으면 거부한다(검수 an1)
  7  연장된 Lease 도 지금과 같이 서명 · 저장한다. 장애 판정은 저장된 만료 + 유예를 그대로 쓰므로 그 동안 재배치하지 않는다
```

## 영향받는 스트림

Protocol(스키마 · 벡터) · Coordinator(RENEW 세션 판정 · 운영자 스위치) · Agent(주인 화면 · 갱신 요청).

## 호환성 영향

- schema_version 증가 필요? **예** — 2. 알림이 없는 갱신은 1 그대로
- 기존 서명이 무효화되는가? **아니오** — 22 가 0 이면 canonical 이 전과 같다(규칙 b · 기존 벡터 무변경을 확인한다)
- 멀티 바이너리 스큐 창에 영향? **예** — 옛 Coordinator(최대 1)는 v2 갱신을 거부한다. 규칙 3 으로 Agent 가 다음 갱신을 v1 로 보내므로
  갱신은 이어지고 알림만 받아들여지지 않는다(화면에 그렇게 보인다). 옛 Agent 는 v2 를 보내지 않는다
- 테스트 벡터 재생성 필요? **예** — v45(v2 알림) · v45b(알림 시각만 다름 — canonical 이 달라야 한다) · v45c(22 = 0 인 v2 — v23 과 칸이 같다) 추가

## 남는 구멍(합의 기록 그대로)

- 계획된 끊김 중 노드가 실제로 죽으면 그 시각까지 재배치가 늦다 — 운영자 상한으로 제한한다
- 노트북 잠자기 동안 노드의 단조 시계 · 운영체제 시한이 흐르는지 **모른다**(재야 한다)
- 긴 Lease 뒤 늦게 반영되는 외부 부작용은 재배치 규칙으로 못 막는다
- 22 는 노드 벽시계다 — 시계가 어긋나면 요청이 어긋난다(상한이 막는다 · 런북 NTP)

## 되돌리는 방법

운영자 상한을 0(기본)으로 두면 Coordinator 가 알림을 무시하고 평소 연장만 준다. 코드를 되돌려도 22 가 0 인 v1 메시지는 전과 같다.
