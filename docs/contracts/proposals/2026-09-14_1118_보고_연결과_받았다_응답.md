## 흐름 (목표 B+E — `docs/plans/2026-09-10_2142_결함18_ACK_시한_설계_선택지.md` §7)

```text
FRESH 세션     Grant -> ACK(실행 전, 설계 A) -> 연결을 닫는다
RENEW 세션     실행 중 주기적으로. Hello(RENEW) -> RenewLeaseRequest(ProgressReport 포함, 이미 있다)
               -> RenewLeaseResult -> 닫는다. Coordinator 는 갱신 수신을 생존 관측으로도 쓴다
REPORT 세션    종료 뒤. Agent 는 AttemptReport 를 **먼저 디스크(보낼 보고 저장소)에 남기고**
               Hello(REPORT) -> AttemptReport -> AttemptReportAck -> 닫는다.
               Ack 를 받고 report_hash 를 재계산해 맞으면 저장소에서 지운다. 못 받으면 재시도한다.
               중복은 이미 있는 저장소 멱등성(같은 바이트면 created=false)이 막는다
```

## 왜 필요한가 (이것 없이 막히는 것)

설계 A(`391e49d`)가 남긴 것이 전부 이 조각을 기다린다.

```text
Lease 보다 긴 작업          실행 중 갱신이 없다 — RENEW 세션이 채운다
Agent 의 거짓 성공 출력     ACK · 보고가 응답 없는 전송이다 — AttemptReportAck 가 채운다
순차 Coordinator 가 한 Agent 를 대략 Lease 수명(최소 10초 · 무응답 시한)만큼 붙잡는다 — 세션이 짧아진다
⑳ 50ms peek 경쟁            REPORT 세션은 Ack 로 끝을 알 수 있어 peek 가 필요 없다
ACK 뒤 기동 실패의 보고     보낼 보고 저장소가 생기면 "무엇을 보고할지" 만 정하면 된다(아래 D3)
```
