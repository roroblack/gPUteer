## 흐름 (목표 B+E — `docs/plans/2026-09-10_2142_결함18_ACK_시한_설계_선택지.md` §7)

```text
FRESH 세션     Grant -> ACK(실행 전, 설계 A) -> 연결을 닫는다
RENEW 세션     실행 중 주기적으로. Hello(RENEW) -> RenewLeaseRequest(ProgressReport 포함, 이미 있다)
               -> RenewLeaseResult -> 닫는다. Coordinator 는 갱신 수신을 생존 관측으로도 쓴다
REPORT 세션    종료 뒤. Agent 는 AttemptReport 를 **먼저 디스크(보낼 보고 저장소)에 남기고**
               Hello(REPORT) -> AttemptReport -> AttemptReportAck -> 닫는다.
               Ack 를 받고 report_hash 를 재계산해 맞으면 저장소에서 지운다. 못 받으면 재시도한다.
               중복은 이미 있는 저장소 멱등성(같은 바이트면 created=false)이 막는다
```

## 왜 필요한가 (이것 없이 막히는 것)

설계 A(`391e49d`)가 남긴 것이 전부 이 조각을 기다린다.

```text
Lease 보다 긴 작업          실행 중 갱신이 없다 — RENEW 세션이 채운다
Agent 의 거짓 성공 출력     ACK · 보고가 응답 없는 전송이다 — AttemptReportAck 가 채운다
순차 Coordinator 가 한 Agent 를 대략 Lease 수명(최소 10초 · 무응답 시한)만큼 붙잡는다 — 세션이 짧아진다
⑳ 50ms peek 경쟁            REPORT 세션은 Ack 로 끝을 알 수 있어 peek 가 필요 없다
ACK 뒤 기동 실패의 보고     보낼 보고 저장소가 생기면 "무엇을 보고할지" 만 정하면 된다(아래 D3)
```

## 영향받는 스트림

- Protocol: proto 두 파일 · signing.md §5 · 서명 대상 등록 · 상수(MODE_RENEW · MODE_REPORT)
- Crypto: FrameType 17 · ingress dispatch
- Coordinator: Hello 로 세션 가르기 · RENEW/REPORT 처리 · Ack 서명
- Agent: 실행 중 갱신 흐름 · 보낼 보고 저장소 · Ack 검증 · 재시도
- QA: 벡터(AttemptReportAck · 새 mode 의 Hello) · 음성 테스트

## 호환성 영향

- schema_version 증가 필요? **AgentSessionHello 는 아니오**(필드 불변, enum 값 추가). **AttemptReportAck 는 새 메시지 1**.
  ★ enum 값 추가가 schema_version 증가 대상인지는 `02_변경_제안_절차.md` 체크리스트가 "새 필드" 만 적어 둬 **판단이 필요하다**
- 기존 서명이 무효화되는가? 아니오
- 멀티 바이너리 스큐 창에 영향? **예** — 새 Agent + 옛 Coordinator 면 RENEW/REPORT Hello 가 거부된다(옛 Coordinator 는
  mode 가 RESUME 가 아니면 거부한다). Agent 는 옛 흐름으로 **몰래 되돌아가지 않고** 명시적으로 실패한다(RULE.md §3.2)
- 테스트 벡터 재생성 필요? 예

## 사용자가 정할 것

```text
D1  Lease 만료 뒤 REPORT 세션으로 온 보고를 받는가
      규범은 STALE 뒤 완주 · 재접속 제출을 허용한다(state-machines.md §3 STALE_WORKLOAD_FINISHED ·
      RECONNECTED_WITH_RESULT). 받으면 규범과 맞고, 거부하면 긴 단절 뒤의 결과를 버린다.
      ★ 지금 Agent 는 STALE_COMPLETED 를 만들지 못한다(report.rs — 단절을 관측할 수단이 없다)
D2  FRESH 세션도 Hello 를 먼저 받게 하는가
      지금 FRESH 는 Coordinator 가 먼저 Grant 를 쓴다. 한 리스너에서 세 종류를 가르려면 Agent 가 먼저 말해야 한다.
      제안: 설정으로 켤 때만 Hello 우선(기본은 지금 그대로) — 켜진 Coordinator 와 옛 Agent 는 서로 거부한다
D3  ⑲ — "종료는 관측했는데 산출물 확정이 실패" 한 보고의 outcome
      규범의 WORKLOAD_EXITED_OK 는 HASH_VERIFIED 를 요구하므로 COMPLETED 는 아니다. FAILED 로 둘지는 규범 판단이다
```
