## 왜 — 계약 없이 닫지 못한 둘

```text
288  Agent 는 상대 Coordinator 가 풀인지 모른다. 그래서 "수신 확인 없이 풀에 붙은 Agent" 는 실행 전 확인 관문이 서지 않아 한 번 더 돌 수 있다.
     지금은 런북의 설정 규칙(풀 = 수신 확인 필수)으로만 막는다 — 코드가 강제하지 않는다
     (docs/reports/debugs/2026-09-25_0220_재검수90_결함_288_292.md · 0240_재검수91)
301  스케줄러의 신선도 검사는 inventory 의 observed_at(= 운영자가 import-inventory 한 시각)을 본다. 노드의 인사는 이 값을 바꾸지 않는다 —
     등록 하루 뒤(런북의 86400000)부터 모든 노드가 SnapshotNotFresh 로 떨어져 배치가 멈춘다(fork 세션이 시험으로 확인 · 결함 301).
     운영 완화: fork 가 가입 파일을 6시간마다 다시 넣는 예약 작업을 더했다(fork-install-gpu 3c25cb2). 그러나 그건 "운영자가 다시 적었다" 일 뿐
     노드가 실제로 그 GPU 를 갖고 있다는 관측이 아니다
```

## 선택지

### 288 — Grant 에 풀 신호

| 안 | 무엇 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A(권장)** | `ExecutionGrant` 에 서명 필드 `pool_mode`(bool) 추가 — 풀 Coordinator 만 true. Agent 는 true 인데 수신 확인 · 실행 중 갱신이 꺼져 있으면 ACK 전에 거부 | 설정 오류를 코드가 막는다. 서명 필드라 위조 불가 | Grant 스키마 한 단계(벡터 · 참조 구현 · 지문 · signing.md 갱신) |
| B | 계약 그대로 · 런북 규칙만 | 변경 없음 | 설정 오류가 두 번 실행으로 이어질 수 있다(지금 상태) |

### 301 — 노드 관측을 서명해 싣기

| 안 | 무엇 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A(권장)** | FRESH `AgentSessionHello` 에 선택 필드로 **노드가 NVML 로 잰 GPU 목록**(uuid · 총 VRAM · 모델)과 관측 시각을 싣고 서명한다. Coordinator 는 등록된 선언과 **맞을 때만** 그 노드의 관측 시각을 갱신한다(선언은 바꾸지 않는다 — 운영자 선언과 노드 관측을 섞지 않고 "선언이 지금도 사실이다" 의 증거로만 쓴다) | 신선도가 실제 관측에 묶인다. GPU 가 빠지면(선언과 다르면) 갱신이 멈춰 자연히 배치에서 빠진다 | Hello 스키마 변경 · NVML 이 없는 노드(CPU 전용)는 갱신 근거가 없다 — 그 노드는 지금처럼 운영자 재선언에 기댄다 |
| B | 서명된 FRESH 인사(생존)만으로 observed_at 을 갱신 | 계약 변경 없음 | 생존과 하드웨어 사실을 섞는다 — GPU 가 빠져도 "신선" 하다(fork 가 지적한 바로 그 섞임) |
| C | 신선도 검사를 선언에 적용하지 않고 `--silent-after-ms` 만 쓴다 | 가장 단순 | 선언이 틀려져도 알 방법이 없다 |

## 권장

288-A 와 301-A 를 **한 번의 스키마 변경**으로 묶는다(Grant · Hello 둘 다 서명 대상 · 벡터 · 참조 구현을 한 번에 갱신). 순서: 계약(proto · canonical ·
signing.md) → Coordinator(관측 대조 · 갱신) → Agent(관측 싣기 · 풀 관문) → 시험(가짜 NVML 로 선언 일치 · 불일치 · CPU 전용) → 독립 검수.

★ 적용 전까지: 288 은 런북 §5(풀 = 수신 확인 필수), 301 은 fork 의 재선언 예약 작업(§9a)으로 운영한다.

## 적용 설계 (2026-09-25 17:15 확정)

### 288-A — `ExecutionGrant.pool_mode`(27, schema v4)

```text
ExecutionGrant
  27  bool pool_mode      ★ v4 에서만. 풀 Coordinator(--pool-mode true)가 발급하는 Grant 만 true
  schema_version          pool_mode 가 true 면 4 · 아니면 지금처럼 재개 지점이 있으면 3, 없으면 2
  domain_tag              그대로 "gputeer/v2/grant"(v3 와 같은 방식 — 버전은 schema_version 이 가른다)

Agent (Grant 서명 · replay 검사 뒤, ACK · 체크포인트 마커 · 실행 전)
  1  schema_version < 4 인데 pool_mode 가 true 면 거부(MUST)
  2  pool_mode 인데 --require-ack-receipt 가 꺼져 있으면 거부 — POOL_GRANT_NEEDS_ACK_RECEIPT(MUST)
  3  pool_mode 인데 실행하면서 실행 중 갱신(--renew-during-execution-ms)이 0 이면 거부 — POOL_GRANT_NEEDS_RENEW(MUST)
  거부는 되풀이하지 않는 오류(Fatal)다 — 설정을 고치기 전에는 다시 붙어도 같다
```

- 구버전 Agent(최대 3)는 v4 Grant 를 `SCHEMA_TOO_NEW` 로 거부한다(fail-closed). 풀은 Agent 를 먼저 올린다.
- 풀이 아닌 Coordinator 의 Grant 는 바뀌지 않는다(v2/v3, 벡터 무변경).

### 301-A — `AgentSessionHello.gpu_observation`(8, schema v2)

```text
NodeGpuObservation                     ★ 최상위 메시지(지문 파서가 중첩 선언을 못 읽는다 — signing.md §7.3)
  1  uint64 observed_at_unix_ms        노드 시계로 NVML 을 읽은 때
  2  repeated ObservedGpu gpus         uuid 오름차순 · 중복 없음 · 1~64 개
ObservedGpu
  1  string uuid                       NVML UUID
  2  string model                      NVML 이름
  3  uint64 total_vram_bytes           NVML 총 VRAM(0 이면 거부)

AgentSessionHello
  8  NodeGpuObservation gpu_observation   ★ v2 에서만 · FRESH 에서만. Hello 서명(node_signature)이 묶는다
```

Coordinator(Hello 서명 · replay 검사 뒤):

```text
구조 규칙(어기면 Hello 거부)   v1 인데 관측이 있다 · FRESH 가 아닌데 관측이 있다 · 형식(정렬 · 중복 · 개수 · 빈 값 · VRAM 0)
시각 규칙(어기면 갱신만 안 함)   observed_at <= Hello.issued_at 이고 issued_at - observed_at <= 60초
대조(풀 모드에서만)             등록된 선언의 GPU 마다 **서로 다른** 관측 GPU 하나씩을 짝지을 수 있어야 한다:
                                  선언 model 이 있으면 같아야 하고, 선언 available_vram_bytes 가 있으면 관측 total 이하,
                                  선언 gpu_id 가 UUID 모양(GPU- · MIG-)이면 그 UUID 의 관측 GPU 하고만 짝짓는다 — 관측에 없으면 짝이 없다
                                  (★ 결함 409 — 처음엔 "관측에 그 UUID 가 있을 때만" 묶어, 빠진 GPU 를 같은 모델의 다른 GPU 가 대신했다)
                                선언 GPU 가 비었거나(CPU 전용) 관측 칸이 없으면(gpus 미관측) 근거가 없다 — 갱신 안 함
결과                           맞으면 **확인 기록**(node_id · 그 선언의 inventory_revision · 확인 시각)을 따로 저장한다.
                                확인 시각 = min(관측 시각, Coordinator 지금). 선언 자체(observed_at 포함)는 바꾸지 않는다
스냅샷                         pool_snapshot() 이 확인 기록의 revision 이 **지금 선언의 revision 과 같을 때만**
                                observed_at = max(선언 observed_at, 확인 시각) 으로 접는다 — 새 선언을 넣으면 옛 확인은 무효다
```

- 짝짓기를 UUID 로 하지 않는 이유: 설치 자동화(fork)의 가입 파일이 `gpu_id` 를 `<노드>-gpu-<번호>` 로 적는다 — 선언의
  `gpu_id` 는 스케줄러 식별자이지 NVML UUID 가 아니다(`scheduler/src/scope.rs` 가 같은 말을 한다). 모델 이름은 가입 파일이
  nvidia-smi 이름을 그대로 적으므로 NVML 이름과 같다.
- Agent: `--attest-gpus true` 일 때만 FRESH Hello 에 싣는다(기본 끔 — 구버전 Coordinator 는 Hello v2 를 거부하므로).
  NVML 을 못 읽으면 관측 없이 v1 Hello 를 보내고 `GPU_ATTESTATION_UNAVAILABLE` 을 찍는다 — 그 노드는 갱신 근거가 없어
  운영자 재선언에 기댄다(조용히 지어내지 않는다).
- ★ 한계: 관측은 노드 자기보고다(`WORKER_REPORTED`) — 노드 키를 가진 소유자는 거짓 관측을 서명할 수 있다. 막는 것은
  "GPU 가 빠졌는데 선언이 계속 신선한 것"(실수 · 고장)이지 작정한 거짓이 아니다. CPU · RAM · 작업 공간 값은 관측하지 않는다 —
  GPU 가 맞으면 선언 전체를 신선하다고 본다.
