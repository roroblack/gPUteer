# 01 · 스트림 소유권

> 규범: `RULE.md` §4
> **이 문서는 `proto/` 를 복제하지 않는다.** 누가 무엇을 소유하고 어떻게 바꾸는지만 담는다.

## 1. 왜 디렉터리 소유권만으로는 부족한가

Python 단일 서비스에서는 "이 폴더는 A 가, 저 폴더는 B 가" 로 충돌을 막을 수 있다.
**Rust workspace 는 다르다.** 다음이 모든 스트림의 충돌점이다.

```text
Cargo.toml (workspace members)
Cargo.lock
build.rs
생성된 protobuf 코드
공용 trait
테스트 벡터
```

두 스트림이 각자 자기 크레이트만 건드려도 위 파일에서 만난다.
그래서 **디렉터리 소유권 + 공용 인터페이스 변경권**을 따로 정의한다.

## 2. 스트림별 소유 디렉터리

| 스트림 | 소유 | 책임 |
|---|---|---|
| **Protocol** | `proto/`, `crates/protocol/` | 스키마 · canonical 인코딩 · 프로토콜 상수 |
| **Crypto** | `crates/crypto/` | Ed25519 · BLAKE3 · nonce 캐시 · 키 보관(K0~K2) |
| **Control** | `crates/control-store/` | `ControlStore` trait · SingleNodeStore · RaftStore |
| **State** | `crates/state-machine/` | Node/Job/Attempt/Checkpoint/Lease 전이 |
| **Runtime** | `crates/runtime-container/`, `crates/runtime-windows/`, `crates/runtime-policy/` | 샌드박스 · Job 실행 · 자원 강제 |
| **Checkpoint** | `crates/checkpoint/`, `crates/cas/` | durability contract · CAS · delta 동기화 |
| **Network** | `crates/p2p/`, `crates/relay/`, `crates/hub/` | direct / hole-punch / relay / hub |
| **Coordinator** | `crates/coordinator/` | 스케줄러 · lease 발급 · reconciliation |
| **Agent** | `crates/agent/` | 워커 에이전트 · 텔레메트리 · owner presence |
| **CLI** | `crates/cli/` | `gputeer` 명령 |
| **UI** | `apps/console/` | React 컴포넌트 · Tauri 셸 |
| **Python** | `python/gputeer_ml/` | PyTorch 어댑터 · checkpoint hook · calibration 러너 |
| **QA** | `tests/vectors/`, `tools/` | **독립 검증. 다른 스트림이 수정하지 않는다** |

★ **2026-08-16 정정 (독립 검수).** 원래 "`tests/` 전체" 라고 적었으나
실제 테스트는 `crates/<이름>/tests/` 에 있다(Rust 관례). 루트 `tests/` 에는 **벡터만** 있다.
규칙대로 따라간 사람이 테스트 위치를 잘못 찾게 되는 불일치였다.

★ **2026-08-17 추가 — `crates/runtime-policy/`.** `runtime-container`/`runtime-windows`
는 아직 없고 자원을 실제로 강제하는 샌드박스 계층이다. `runtime-policy` 는
그보다 먼저 필요했다 — `Verified<M>` 에서 나온 정책 필드(`network` ·
`artifact_scope` · `Lease.scope`)가 **강제 가능 / 억제만 가능 / 강제 불가**
중 어디에 속하는지 판정하는 순수 함수 계층이다(TODO_VISION V-06).
실제 강제(OS 방화벽 호출 · 파일시스템 핸들 차단)는 여전히 없다 —
이 크레이트는 "무엇을 할 수 있다고 주장해도 되는지" 를 가른다.

★ **위 표의 크레이트 중 상당수는 아직 존재하지 않는다.**
`control-store` · `state-machine` · `runtime-*` · `cas` · `p2p` · `relay` · `hub` ·
`coordinator` · `agent` · `cli` · `apps/console` · `python/gputeer_ml` 은 **미착수**다.
현재 존재하는 것은 `protocol` · `crypto` · `checkpoint` 셋뿐이며,
`crates/protocol/tests/stream_ownership.rs` 의 `every_crate_is_covered_by_ownership_rules`
가 그 목록을 고정한다 — 새 크레이트가 생기면 실패한다.

### 규칙

- **한 스트림은 자기 소유 디렉터리 밖을 수정하지 않는다.**
- 다른 스트림의 코드가 바뀌어야 하면 **변경 제안**을 만든다(§4).
- ★ **다른 스트림의 테스트를 통과시키려고 assertion 이나 계약을 완화하지 않는다.**

### ★ 이 경계는 테스트가 강제한다 (2026-08-16 추가)

```text
crates/protocol/tests/stream_ownership.rs
```

문서에만 있는 경계는 지켜지지 않는다. **실제로 어겼다.**

> `crates/protocol/src/signing.rs` 가 `ed25519-dalek` 을 직접 썼다.
> 위 표는 Ed25519 를 Crypto 스트림 소유로 정하는데,
> **테스트 100건이 전부 통과했고 아무도 알아채지 못했다.**

`cargo add` 한 줄이면 경계가 무너지고 테스트는 여전히 초록색이다.
그래서 `Cargo.toml` 의존성을 코드로 검사한다.

| 검사 | 막는 것 |
|---|---|
| `protocol_does_not_depend_on_crypto_libraries` | 계약 크레이트에 암호 라이브러리가 새어 들어오는 것 |
| `crypto_depends_on_protocol_not_the_reverse` | 순환 의존 — 계약이 구현을 따라가는 것 |
| `protocol_is_a_leaf_crate` | 계약 크레이트가 다른 스트림에 얽히는 것 |
| `every_crate_is_covered_by_ownership_rules` | 새 크레이트가 검사망을 빠져나가는 것 |

★ **BLAKE3 는 `crates/protocol` 에서 예외로 허용한다.** canonical 인코딩
(§6 Merkle · `sig_input` 다이제스트)의 일부라서 프로토콜 정의 자체에 들어간다.
위 표의 "BLAKE3" 항목은 **키 유도·MAC 용도**를 가리킨다.

#### 해소 방식 — trait 는 protocol, 구현은 crypto (`RULE.md` §4.3)

```text
crates/protocol   Signable · SignatureVerifier · Verified<M> · VerifyOutcome
                  = 무엇을 서명하는가 · 어떤 순서로 검증하는가

crates/crypto     Ed25519Verifier · sign() · InMemoryKeyring
                  = 그 서명을 실제로 만들고 확인하는 법
```

`crates/protocol` 은 암호 라이브러리를 **알지 못한다.**
그래야 서명 알고리즘을 바꿔도 프로토콜 규범이 흔들리지 않는다.

## 3. 공용 파일 — 어느 스트림도 임의 수정 금지

```text
Cargo.toml (workspace)          Cargo.lock
proto/*.proto                   생성된 protobuf 코드
build.rs                        docs/protocol/*
tests/vectors/*                 crates/protocol/src/constants.rs
릴리스 매니페스트 스키마
```

이 파일들은 **통합 책임자만** 수정한다.

### 왜 `constants.rs` 가 공용인가

`clock_skew_tolerance = 60s` · `lease_duration = 10m` · `fragmentation_factor = 1.20` 같은 값이
코드 두 곳에 나타나면 그 자체가 결함이다(`RULE.md` §3.1).
여러 스트림이 같은 상수를 쓰므로 **단일 출처**여야 한다.

### 왜 `tests/vectors/` 가 QA 소유인가

구현자가 자기 구현에 맞춰 벡터를 고치면 검증이 무의미해진다.
벡터는 `tools/canonical/reference_canonical.py` 가 생성하며, **손으로 고치지 않는다.**

## 4. 변경 제안 절차

공용 파일 또는 다른 스트림 영역을 바꿔야 할 때:

```text
1. docs/contracts/02_변경_제안_절차.md 의 양식으로 제안 작성
2. 영향받는 스트림 식별
3. 영향받는 스트림이 검토
4. 통합 책임자가 승인 후 적용
5. schema 변경이면 schema_version 증가 + 테스트 벡터 재생성
6. docs/reports/ 에 기록
```

**프로토콜 변경은 코드보다 먼저다** (`RULE.md` §3.5).

---

## 5. Rust 충돌 방지 규칙

- 공용 trait 는 `crates/protocol` 에서 **먼저 확정**한다.
  구현 크레이트는 trait 정의를 수정하지 않고 구현만 한다.
- **생성된 protobuf 코드를 직접 수정하지 않는다.**
- `Cargo.lock` 변경은 통합 책임자가 수행한다.
- `cargo fmt` 는 **변경 크레이트 범위**로 실행한다.
  workspace 전체 fmt 는 최종 통합에서만 한다 (전체 fmt 는 diff 를 오염시킨다).
- 통합 테스트와 golden vector 는 QA 스트림이 소유한다.

## 6. 작업 단위 예시

"Coordinator 구현" 처럼 넓게 주면 `control-store` · `scheduler` · `lease` · 상태기계를
동시에 건드려 충돌한다. 다음처럼 쪼갠다.

```text
P0-03 · Checkpoint Durability
  Contract        checkpoint 상태표(docs/protocol/state-machines.md §4)
                  durability 의미(기준선 §18.2)
                  ReplicaAck 서명(proto/artifact.proto)
  Implementation  crates/checkpoint/
  Test            crates/checkpoint/tests/kill_chaos.rs (QA 소유)
  Evidence        docs/evidence/P0-03_checkpoint_durability.md
```

각 작업은 **Contract · Implementation · Test · Evidence 네 칸이 채워져야** 착수 가능하다.
