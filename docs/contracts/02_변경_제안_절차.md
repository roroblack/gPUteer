# 02 · 변경 제안 절차

> 규범: `RULE.md` §3.5 · §4.2
> 공용 파일 또는 다른 스트림 영역을 바꿀 때 이 양식을 쓴다.

## 언제 필요한가

```text
필요   proto/*.proto 수정
필요   docs/protocol/* 수정
필요   crates/protocol/src/constants.rs 수정
필요   Cargo.toml workspace / Cargo.lock 수정
필요   tests/vectors/* 재생성
필요   공용 trait 시그니처 변경
필요   다른 스트림 소유 디렉터리 수정

불필요 자기 스트림 소유 디렉터리 안의 구현 변경
```

---

## 양식

파일명: `docs/contracts/proposals/YYYY-MM-DD_HHmm_<제목>.md`

```markdown
# 변경 제안 · <제목>

- 제안자 스트림:
- 대상 파일:
- 유형: schema | protocol | constant | workspace | trait | cross-stream

## 무엇을 바꾸려는가
## 왜 필요한가 (이것 없이 막히는 것)
## 영향받는 스트림
## 호환성 영향
  - schema_version 증가 필요?          예 / 아니오
  - 기존 서명이 무효화되는가?          예 / 아니오
  - 멀티 바이너리 스큐 창에 영향?      예 / 아니오
  - 테스트 벡터 재생성 필요?           예 / 아니오
## 되돌리는 방법
## 검토 (영향받는 스트림이 채운다)
## 승인 (통합 책임자)
```

---

## 절차

```text
1. 제안 작성
2. 영향받는 스트림 식별 (01_스트림_소유권.md §2)
3. 각 스트림이 "검토" 절을 채운다
4. 통합 책임자 승인
5. 적용 — 반드시 이 순서로
     proto/protocol 수정
       -> schema_version 증가
       -> 테스트 벡터 재생성
       -> 구현 수정
       -> negative test 추가
6. docs/reports/ 에 기록
```

★ **5번 순서를 뒤집지 않는다.** 코드를 먼저 고치면 계약이 코드를 따라가게 되고,
그 순간 계약이 계약이 아니게 된다.

## 스키마 변경 체크리스트

`proto/*.proto` 를 건드릴 때 반드시 확인한다.

- [ ] field number 를 **재사용하지 않았다**
- [ ] 기존 필드의 **타입·의미를 바꾸지 않았다**
- [ ] 삭제한 필드를 `reserved` 로 표시했다
- [ ] 새 필드를 추가했다면 `schema_version` 을 올렸다
- [ ] **float / double 을 추가하지 않았다** (ppm 정수 · 밀리초 정수)
- [ ] 새 서명 대상 메시지라면 `signing.md` §5 `domain_tag` 표에 등록했다
- [ ] 서명 필드 번호가 **90** 이다
- [ ] `tests/vectors/canonical_v1.json` 을 재생성하고 cross-check 를 통과했다
- [ ] 구버전 검증자가 `SCHEMA_TOO_NEW` 를 반환하는 테스트를 추가했다

## 프로토콜 동결 중이라면

`RULE.md` §10 의 동결 상태를 확인한다.

```text
schema freeze 중       field number / semantic 변경 불가
protocol freeze 중     기존 버전의 검증 의미 변경 불가
release freeze 중      보안 · 데이터 손실 · 호환성 버그만
```

★ **schema freeze 중에도 호환성 패치는 허용된다.** 단일 서비스와 다른 점이다.
