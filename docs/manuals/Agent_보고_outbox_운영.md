# Agent 보고 outbox 운영 — 경로를 정할 때 지킬 것

> **최종 갱신** 2026-09-17 · **성격** 운영 안내(규칙의 근거는 결함 리포트) ·
> **근거** `docs/reports/debugs/2026-09-10_0900_검수가_찾은_결함_5건.md` 결함 107 · 125 · 128 · 129 · 146 · 157 · 162 · 163 · 169 · 181 · 187 · 188 · 189 · 190 · 194 ·
> **검사** Agent 가 기동할 때 `report_outbox_dir` 가 아래 대부분을 거부한다 — **마운트 별칭만은 못 알아챈다**

## 무엇인가

`--report-over-session true` 로 켠 Agent 는 종료 보고를 서명해 **outbox 디렉터리**에 먼저 남기고, REPORT 연결로 보낸 뒤 서명된 "받았다" 응답을 받으면 지운다.
보내지 못한 보고는 다음 기동이 outbox 에서 다시 보낸다. 그래서 **outbox 는 기동을 넘어 같은 자리에 남아 있어야 하고, 무엇도 그 자리를 지우면 안 된다.**

## 경로 정하기

```text
기본        --report-outbox 를 안 주면 <체크포인트 루트>.report-outbox (루트의 형제)
            ★ --checkpoint-root 도 안 주면 루트가 기동마다 새로 만들어져 outbox 도 바뀐다 — REPORT 세션은 둘 중 하나를 반드시 준다
명시        --report-outbox <경로>
```

★ **부팅 GC 는 이 브랜치의 Agent 시작 경로에 아직 연결되지 않았다**(결함 85 · 194 — 기동 때 outbox 는 재전송만 한다). 아래의 "부팅 GC 가 지운다" 는
  `startup_gc` 가 돌 때의 동작이다 — 기동 GC 연결(별도 브랜치)을 합친 Agent 에서는 기동마다 돈다. 그 전에는 Agent 재기동만으로 GC 삭제가 일어나지 않는다
  (그러니 남은 `.report.tmp` 도 재기동만으로는 정리되지 않는다). 작업 정리(그 작업의 출력 디렉터리 재귀 삭제)는 지금도 워크로드를 실행할 때마다(실행 전 · 후) 돈다.

## 거부되는 경로 — 기동 전에 오류로 알려 준다

```text
체크포인트 루트 · 작업 출력 루트(<루트>.workload-run) 자신이거나 그 안인 경로          부팅 GC · 작업 정리가 지울 수 있는 자리다
                                                                                      (실제로 어느 깊이가 지워지는지는 아래 "알아채지 못하는 경로" 표 — 결함 189)
(unix) 그 안의 **하위 디렉터리를 지나** `..` 로 나가는 경로(예: <루트>/sub/../../x)    sub 가 지워지면 경로가 끊긴다
경로의 어느 구성 요소든 링크(symlink · Windows junction · 볼륨 마운트 지점)인 경로    링크 너머 자리가 지워질 수 있다
```

★ 루트에서 **곧바로** `..` 로 되돌아 나오는 경로(예: `<루트>/../x`)는 받는다 — 지워지는 자리를 지나지 않는다(결함 181).
★ **Windows 의 일반 경로는 `..` 를 검사 전에 글자로 접는다**(절대 경로로 바꿀 때 — `C:\r\cp\sub\..\..\x` 는 `C:\r\x` 로 검사된다). 그래서 위 "(unix)" 줄은
  Windows 일반 경로에서 거부되지 않고 받는다 — Windows 도 일반 경로를 열 때 `..` 를 글자로 접으므로 `sub` 를 지나지 않는다(결함 187). 이 차이의 거부 시험은 unix 에서만 돈다.
  ★ **`\\?\` 로 시작하는 verbatim 경로는 접지 않는다**(`std::path::absolute` 가 그대로 돌려준다 — Rust 문서의 플랫폼 예외). 검수가 같은 `..` 경로에
    `\\?\` 를 붙이면 Windows 가 열기를 오류 123 으로 거부하는 것을 봤다. verbatim + `..` 경로로 Agent 를 기동한 결과는 재지 않았다 — `..` 를 쓸 거면 verbatim 을 쓰지 않는다(결함 188).
★ 링크 거부는 **부모 경로의 링크에도** 걸린다. 예: macOS 의 `/tmp -> /private/tmp` 아래, junction 으로 옮긴 사용자 프로필 아래의 outbox.
  **해결: 링크를 풀어 쓴 실제 위치가 두 루트 밖이면 그 실제 경로를 `--report-outbox` 로 준다**(예: `/tmp/x` 대신 `/private/tmp/x`).
  **실제 위치가 루트 자신이거나 그 안이면**(예: `/safe/alias -> /data/cp` 에서 루트가 `/data/cp`) 풀어 써도 다시 거부된다 — 두 루트와 겹치지 않는 **별도 디렉터리**를 준다(결함 181).

## 알아채지 못하는 경로 — 운영자가 지킨다

```text
마운트 별칭   Linux bind mount 로 체크포인트 루트나 작업 출력 루트(또는 그 안)를 다른 자리에 붙이고 그 자리를 outbox 로 쓰는 것
```

경로로는 같은 디렉터리의 다른 이름인지 알 수 없어 **오류 없이 통과한다.** 그러면 outbox 의 보고가 겹친 자리에서도 보여, **겹친 위치와 그 자리의 삭제 대상에 따라** 지워질 수 있다:

```text
체크포인트 루트 **바로 아래** 디렉터리와 겹침   그 디렉터리에 매니페스트가 없으면 부팅 GC 가 그 디렉터리 바로 안의 파일(보고)을 지운다
                                               매니페스트가 있으면 (a) 매니페스트에 등록 안 된 `.tmp` 와 (b) "매니페스트가 있고 등록된" 것이 아니면서
                                               잠금을 얻을 수 있는 `.write_once.lock` 만 지운다 —
                                               완료된 `<hash>.report` · 격리된 `.report.rejected` 는 해당 없지만,
                                               쓰다 끊겨 남은 `<hash>.report.tmp` 는 (a) 라 지운다(결함 190 — outbox 쓰기가 `.report.tmp` 를 만든 뒤 `.report` 로 바꾼다)
체크포인트 루트의 **더 깊은** 디렉터리와 겹침   부팅 GC 는 루트 바로 아래 디렉터리 안의 파일만 보고 그 아래 디렉터리로 들어가지 않는다 —
                                               현재 부팅 GC 로는 지워지지 않는다(결함 189)
체크포인트 루트 **자체**와 겹침                보고 파일은 루트 바로 아래에 놓이는데 부팅 GC 는 루트 바로 아래 파일을 건너뛴다 —
                                               현재 부팅 GC · 작업 정리로는 지워지지 않는다(결함 187 · 189)
작업 출력 루트의 작업 디렉터리(또는 그 안)와 겹침   작업 정리가 그 작업 디렉터리를 통째로(재귀) 지운다 — 깊이와 무관하다
작업 출력 루트 **자체**와 겹침                  작업 정리는 <작업 출력 루트>/<checkpoint_id> 만 지운다 — 루트 바로 아래의 보고 파일은
                                               현재 작업 정리로는 지워지지 않는다(작업이 그 자리에 무엇을 쓰고 지우는지는 이 표 밖이다)
```

(마운트 실행으로 재지 않았다 — 코드 경로 근거다. "지워지지 않는다" 는 GC · 작업 정리에 한한 말이다 — ACK 를 받은 보고를 Agent 가 지우는 정상 삭제는 별개다.
 지워지지 않는 경우도 운영 계약상 권하지 않는다 — GC · 정리 규칙이 바뀌면 달라진다.)
→ **체크포인트 루트 · 작업 출력 루트를 다른 자리에 마운트하지 않는다.** 마운트가 필요하면 outbox 는 그와 겹치지 않는 별도 디렉터리로 준다.

## 이 문서가 보장하지 않는 것

- 검사 뒤 누군가 경로를 링크로 바꿔치기하는 경쟁(TOCTOU) — Agent 는 핸들로 고정하지 않는다. outbox · 루트와 그 부모를 다른 프로세스가 바꾸지 않게 한다
- Windows 의 name-surrogate 가 아닌 reparse point(CLOUD · WOF 등)는 링크로 보지 않는다 — 우회 반례는 아직 없다
- 리눅스에서 실행해 확인하지 않았다(이 문서의 리눅스 서술은 코드 · 문서 근거다)
