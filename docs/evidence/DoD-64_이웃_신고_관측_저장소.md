decision: >
  `ADR-033` §7 이 나눈 두 층(관측·판정) 중 **관측을 모아 두는 곳**만 만든다.
  판정은 `reassignment.rs` 가 이미 하고 있고, 이 저장소가 세면 §7 이 금지한
  "관측을 판정으로 승격" 이 저장 계층에서 일어난다.

  **정족수를 세지 않는다.** 행을 돌려줄 뿐이고, 각 행에 서명 장치를 함께 실어
  보낸다 — 장치 하나가 여러 기계 ID 를 주장할 수 있다는 사실(이 저장소가 막지
  못하는 것)을 호출부가 **값으로 보게** 하기 위해서다. 저장 상한을 강제하려고
  행 수는 세지만 그건 판정이 아니다.

  **`DoD-63` 이 남긴 수신자 대조를 여기서 닫는다.** 이 저장소가 그 첫 소비자다.
  ★ 쓰기에서만 대조하면 부족하다 — 이미 행이 든 파일을 다른 Coordinator 가
  열면 남에게 보낸 신고를 자기 것으로 읽는다. 읽기 경로에서도 대조한다.

  **이력이 아니라 (신고자, 대상)당 최신 한 행.** 노드가 연락이 안 되는 동안
  신고는 계속 온다 — 전부 남기면 남의 PC 를 채운다(`CLAUDE.md` §0.5).

  **기계→장치 결합은 그 기계의 모든 행에 대해 강제한다.** 정족수 단위가 기계
  (§8 조건 3)이므로 결합도 기계 단위여야 한다. 쌍 단위로 걸면 다른 대상으로
  남의 기계 ID 를 주장할 수 있고, `LIMIT 1` 로 보면 이미 섞인 상태를 통과시킨다.
  그리고 **검증해서 읽은 뒤** 결합을 본다 — 안 그러면 손상이 충돌로 가려진다
  (원인이 다르면 대응도 다르다, `CLAUDE.md` §3).

  **저장 상한은 거부가 아니라 축출로 지킨다.** 거부만 하면 상한을 채운 정당한
  이웃이 새 노드를 영영 신고 못 한다 — 그건 관측 계층의 기능 실패다. 단
  **더 오래되거나 같은 관측으로 밀어내지는 않는다**(이 모듈의 다른 신선도
  경계와 같은 `<=` 규칙). 밀려난 관측은 **검증된 전체 행**으로 보고한다 —
  조용히 버리지 않고(`CLAUDE.md` §3), 지워진 뒤에는 다시 읽을 수 없으므로.

  ★ **상한은 증상 억제이지 해결이 아니다.** 다른 장치 ID 를 계속 만들면 각각
  64행씩 늘어난다. 진짜 경계는 여기가 아니라 **멤버십**에 있다.

  - "★ 한 기계에 두 장치 행이 이미 섞여 있으면 정렬상 첫 행과 같은 장치의 신고도 거부(`LIMIT 1` 로는 통과했다)"
  - "★ 손상은 **충돌로 가려지지 않는다** — 장치 컬럼만 변조하면 `ReporterDeviceMismatch` 로 보고"
  - "자기 자신을 연락 두절이라 신고하는 것은 거부 — DB 불변 확인"
  - "빈 식별자 4종을 각각 그 필드 이름으로 거부 — 네 번 거부 후 행 수 0 확인"
  - "손상 4종(몸통 해시·인덱스 컬럼·시각·장치)을 각각 **행 식별 필드까지** 대조해 거부"
  - "★ 손상된 축출 후보는 조용히 지워지지 않고 `Corrupt` 로 거부 — 저장소 전체 불변 확인"
  - "★ 시각 컬럼이 손상된 행이 후보에서 숨지 못함 — 멀쩡한 행이 대신 밀려나지 않음"
  - "상한 초과 상태에서 밀려날 집합보다 새롭지 않은 신고는 거부 — 오류 전 필드 대조 + DB 불변"
  - "`:memory:` 는 durable 이 아님"
  - "빈 Coordinator ID 로는 저장소를 열 수 없음"
  - "★ 한 장치가 여러 기계 ID 를 주장할 수 있다는 **열린 구멍**을 통과하는 테스트로 고정 — 닫히면 실패해서 알린다"
  - "★ 골든 벡터 — 실제로 기록한 뒤 raw SQL 로 저장된 몸통 바이트·다이제스트를 고정값과 대조"

limitations:
  - "★ **신고자가 정당한 풀 이웃인지 확인하지 못한다.** 멤버십 해소가 이 저장소에 없다 — `DoD-63`·`DoD-61` 과 같은 한계다"
  - "★ **장치→기계 결합이 검증되지 않는다.** 서명은 장치를 인증할 뿐이다. 이 저장소는 기계당 **하나의** 장치만 허용해 일관성은 지키지만, **그 장치가 그 기계의 진짜 주인인지는 모른다** — 먼저 주장한 쪽이 이긴다"
  - "★ **저장 상한은 저장소 전체 상한이 아니다.** 다른 장치 ID 를 계속 제시하면 각각 64행씩 늘어난다. 저장소 크기는 '이 DB 에 현재 행을 가진 서로 다른 장치 ID 수 × 64' 이고 그 장치 수에는 코드상 상한이 없다 — 진짜 경계는 멤버십에 있다"
  - "★ 상한은 **이 API 로 만든 상태**에만 성립한다. 외부 쓰기·구버전 DB 로 이미 넘어 있으면 그 상태 자체는 막지 못하고 **다음 새 행 기록 때** 안쪽으로 되돌린다 — 기존 쌍 갱신만 계속되면 넘은 채로 남는다"
  - "축출 정책(가장 오래된 것부터)과 상한값 64 는 **규범이 정한 값이 아니다** — `CLAUDE.md` §0.5 를 지키기 위한 로컬 자원 방어다"
  - "시간 기반 만료(TTL)를 하지 않는다 — 보존 정책이 규범에 없다"
  - "읽기에서 **서명을 재검증하지 않는다.** 돌려주는 것은 서명 미검증 decoded row 다(protobuf 디코드와 해시·인덱스 일치는 검사한다) — 판정에 쓰기 전에 그때의 권위 있는 key directory 로 다시 검증해야 한다(`DoD-50`~`53` 과 같은 계약)"
  - "★ **production 소비자가 없다.** wire 수신부에서 이 저장소를 호출하는 경로를 만들지 않았다 — `ADR-033` §8 조건 2 의 강제 수단(만료 시 PAUSE)이 없는 한 재배정 경로 전체를 켜면 안 된다(`DoD-62` 참조)"
  - "★ 골든 벡터는 인코딩·서명·해시의 **공통 의존성**을 고정할 뿐, 프로덕션과 테스트가 같은 `prost` 인코더를 쓴다는 사실 자체를 없애지는 못한다"

# DoD-64 · 이웃 신고 관측 저장소

## 무엇을 만들었나

`ADR-033` §7 이 층을 둘로 나눠 뒀다.

```text
관측(신고)   같은 풀의 이웃이 "저 노드에 연락이 안 된다" 고 서명해 보고한다
판정(결정)   Broker 가 그 보고를 **모아** 노드 상태를 정하고 재배정을 결정한다
```

신고 메시지는 `DoD-63` 이, §8 판정 관문은 `DoD-61` 이 만들었다. 비어 있던 것은
그 사이 — **"모아" 두는 곳**이다. 신고가 도착해도 남지 않으면 여러 이웃의 관측을
함께 볼 수가 없다.

## 이 조각에서 배운 것

### 1. 방어 하나가 여섯 개의 새 표면을 열었다

`CLAUDE.md` §0.5("남의 PC 를 채우지 않는다")를 지키려고 장치당 저장 상한을
넣었다. 그 하나가 이렇게 번졌다.

```text
상한 도입
  -> 상한을 채운 **정당한** 이웃이 새 노드를 영영 신고 못 함        (1R)
  -> 축출로 해결
     -> 삭제 키에 신고자가 빠져 여러 행이 함께 삭제됨               (2R)
     -> 키를 고쳐 해결
        -> 손상된 축출 후보가 조용히 사라짐                         (3R)
        -> 지우기 전 검증으로 해결
           -> **후보를 고르는 단계**가 손상에 속음                  (4R)
           -> 전수 검증으로 해결
              -> 이미 상한 넘은 DB 를 복구 못 함                    (5R)
```

각 수정이 다음 결함을 만들었다. **프로덕션 결함 11건 중 6건이 직전 수정의
산물**이다. 방어를 넣을 때는 그 방어가 만드는 표면도 함께 세야 한다.

### 2. 내 테스트가 여덟 라운드 내리 같은 방식으로 느슨했다

```text
개수만 본다          rows.len() == 3   -> 대상·시각·해시가 틀려도 통과
존재만 본다          is_some()         -> 유효하게 변조된 행을 놓침
오류를 뭉갠다        Corrupt { .. }    -> 어느 행이 손상됐는지 잘못 전해도 통과
반환값만 본다        DB 를 다시 안 읽음 -> 오류를 내면서 행도 쓰는 구현을 놓침
★ DB 로 DB 를 검사   기대값을 get_report() 로 만듦
                     -> **저장과 조회가 함께 틀리면 통과**
```

마지막 것이 가장 나빴다. 저장소를 검사하는데 **그 저장소가 준 답을 정답지로**
썼다. 이제 기대 행을 테스트 입력만으로 만들고(`expected_row()`), 프로덕션과
테스트가 같은 인코더를 쓴다는 남은 위험은 **골든 벡터**로 못박았다.

### 3. 서술 오류 15건이 전부 같은 방향이었다

한 건도 빠짐없이 **코드가 하는 것보다 강하게** 썼다. 실제보다 약하게 쓴 것은
하나도 없었다.

```text
"두 축을 함께 묶는다"          다른 장치 ID 를 쓰면 각각 64행씩 또 쓴다
"세지 않는다"                  상한 강제하느라 행 수는 센다
"하나의 트랜잭션 안에서"        수신자 대조는 트랜잭션 밖이다
"검증된 서명자"                읽을 때 서명을 재검증하지 않는다
"어떤 행이든"                  LIMIT 1 이라 첫 행만 봤다
"다음 기록 때 복구된다"         **새 행** 기록 때만 돈다
테스트 이름 never_more_than_one 초과 복구는 의도적으로 7행을 지운다
```

★ 마지막 것은 **테스트 이름 자체가 거짓말**이었다. 이름이 코드보다 강하게
주장하면 다음 사람이 그 이름을 믿는다.

이건 `DoD-61`·`DoD-63` 이 이미 "한계를 적었다고 정확한 것은 아니다" 로 남긴
패턴의 **세 번째** 사례다. 한계 절을 쓰면서도 그 위 문장에서 보장을 부풀리는
일이 반복된다.

### 4. 검수가 제안한 것을 받아들인 자리

9라운드가 이렇게 지적했다 — 기대값을 입력에서 만들어도, 프로덕션과 테스트가
**같은** `prost` 인코더와 같은 서명 fixture 를 쓰므로 둘이 함께 바뀌면 나란히
틀린 채 통과한다. 그래서 신고 하나의 몸통 바이트와 BLAKE3 다이제스트를
고정값으로 못박았고, 10라운드 지적을 받아 **실제로 기록한 뒤 raw SQL 로 저장된
바이트까지** 대조하도록 넓혔다.

★ 이 값이 바뀌면 그건 wire 형식이 바뀌었다는 뜻이다 — 고쳐서 통과시키기 전에
왜 바뀌었는지부터 확인해야 한다.

## 이 실험이 증명하지 않는 것

★ **신고자가 정당한 풀 이웃이라는 것.** 멤버십 해소가 이 저장소에 없다.
  누구든 key directory 를 통과하는 장치면 신고를 남길 수 있다.

★ **주장한 기계 ID 의 진짜 주인이라는 것.** 서명은 **장치**를 인증할 뿐이다.
  이 저장소는 기계당 **하나의** 장치만 허용해 일관성은 지키지만, 그 장치가
  그 기계의 실제 소유자인지는 모른다 — **먼저 주장한 쪽이 이긴다.**

★ **저장소 전체 크기가 묶인다는 것.** 상한은 **장치당**이다. 다른 장치 ID 를
  계속 제시하면 각각 64행씩 늘어나고, 그 장치 수에는 코드상 상한이 없다.
  진짜 경계는 여기가 아니라 **멤버십**에 있다.

★ **읽은 행의 서명이 지금도 유효하다는 것.** 읽기에서 서명을 재검증하지
  않는다 — 돌려주는 것은 서명 미검증 decoded row 다. 판정에 쓰기 전에 그때의
  권위 있는 key directory 로 다시 검증해야 한다.

★ **이 재료로 재배정을 해도 된다는 것.** 이 저장소를 소비하는 production
  경로를 만들지 않았다. `ADR-033` §8 조건 2 의 강제 수단(만료 시 PAUSE)이
  없는 한 재배정 경로를 켜면 안 된다(`DoD-62`).

★ **골든 벡터가 인코더의 정확성을 증명한다는 것.** 그것이 고정하는 것은
  "지금 이 바이트" 이지 "이 바이트가 옳다" 가 아니다. 프로덕션과 테스트가 같은
  `prost` 인코더를 쓴다는 사실 자체는 그대로 남는다 — canonical 참조 구현과의
  교차검증은 `DoD-63` 이 이미 별도로 했다.

★ **축출 정책이 규범이라는 것.** 상한값 64 도, "가장 오래된 것부터" 도
  `ADR-033` 이 정한 값이 아니다. `CLAUDE.md` §0.5 를 지키기 위한 **로컬 자원
  방어**이며, 규범이 생기면 그쪽을 따라야 한다.

## 다음

이 저장소를 **소비하는 production 경로는 만들지 않았다.** wire 수신부에서
호출하려면 `ADR-033` §8 조건 2 의 강제 수단(만료 시 PAUSE)이 먼저 있어야 한다
— 그 전까지 재배정 경로를 켜면 안 된다는 것이 `DoD-62` 의 결론이고, 이 조각도
그 선을 넘지 않는다.
