## 주요 지적

1. **[중대] signer 간 키쌍 바꿔치기가 가능합니다.**

`51bf255:crates/crypto/src/keyring.rs:612`는 signer 정보 없이 개인키를 봉인하고, Linux의 모든 키가 동일한 `LINUX_CREDENTIAL_NAME`을 사용합니다(`:871`). 로드 시 개인키와 공개키의 일치만 검사합니다(`:351-365`).

따라서 키링 파일을 수정할 수 있는 공격자는:

- signer A와 B의 공개키와 봉인 blob을 함께 교환하고
- 키가 없는 BLAKE3 파일 체크섬을 다시 계산하면
- 두 blob 모두 같은 credential name으로 복호되므로 검사를 통과시킬 수 있습니다.

blob만 교환하면 공개키 검사가 막지만, 키쌍 전체를 교환하면 못 막습니다. signer별 credential name으로 묶어야 하며, 같은 문제는 Windows DPAPI에도 있으므로 optional entropy에 signer 문맥을 넣어야 합니다. systemd 문서도 credential name이 용도 간 재사용 방지 경계라고 명시합니다. [systemd-creds 공식 문서](https://github.com/systemd/systemd/blob/main/man/systemd-creds.xml)

2. **[중대] `rebind_device()`가 새 장치에 바인딩하지 않습니다.**

`51bf255:crates/coordinator/src/node_liveness_store.rs:219-241`에서 `new_device_id`는 빈 값 검사에만 쓰이고, 실제 동작은 기존 `node_id` 행 삭제뿐입니다.

그 뒤에는 “지정된 새 장치”가 아니라 **먼저 정상 서명 heartbeat를 보낸 등록 장치**가 해당 노드를 차지합니다. 즉 운영자가 A→B 교체를 승인한 순간 C가 먼저 보고하면 C가 노드를 인수할 수 있습니다.

또한 이 함수의 호출 진입점과 부정 테스트가 없습니다. 커밋 메시지의 “사람이 부르는 안전한 복구 경로”는 실제 운영 코드로 연결되지 않았습니다. `node_id → expected new_device_id`의 pending binding을 영속적으로 기록하고, 정확히 B의 첫 heartbeat만 원자적으로 허용해야 합니다.

3. **[중대] `gputeer-` 접두사 검사는 조상 cgroup 우회를 막지 못합니다.**

`51bf255:crates/runtime-linux/src/lib.rs:569-576`은 정규화된 경로의 **마지막 이름만** 검사합니다. 따라서 다음처럼 시스템 계층 아래에 있으면서 마지막 이름만 맞는 경로는 통과합니다.

```text
/sys/fs/cgroup/system.slice/gputeer-agent.service
/sys/fs/cgroup/other-service/gputeer-workloads
```

존재하는 디렉터리이고 memory controller 조건도 맞으면 `Explicit` 경로로 받아들여집니다. 이는 막으려던 “다른 서비스 subtree 사용”을 그대로 우회합니다. bind mount 한계는 문서에 밝혔지만, 이 단순 조상 우회는 누락됐습니다.

테스트 `:767`도 `system.slice` 자체 등 마지막 이름이 틀린 경우만 검사합니다.

4. **[보통] subprocess 오류 경로에서 자식이 회수되지 않습니다.**

`write_all()` 사용(`51bf255:crates/crypto/src/keyring.rs:952`)은 짧은 쓰기를 반복하므로 **부분 쓰기 자체는 안전합니다**. 정상 종료와 non-zero 종료도 `wait_with_output()`으로 회수합니다.

하지만 `write_all()`이 실패하면 즉시 반환하여 child를 kill/wait하지 않습니다. Rust의 `Child`는 Drop 시 자동 회수되지 않으므로 자식이 계속 돌거나 종료 후 좀비로 남을 수 있습니다. `wait_with_output()` 오류도 같은 문제가 있습니다. [Rust `Child` 문서](https://doc.rust-lang.org/std/process/struct.Child.html), [`write_all` 문서](https://doc.rust-lang.org/std/io/trait.Write.html#method.write_all)

추가로:

- timeout이 없어 helper가 멈추면 Agent도 무기한 멈춥니다.
- 모든 `spawn()` 실패를 `UnsupportedPlatform`으로 바꿉니다(`:946`). `NotFound`뿐 아니라 권한 거부·프로세스 한도 초과도 “지원 안 함”이 됩니다.
- stdin 쓰기와 wait 오류는 `OsProtectionFailed`가 아니라 `Io`입니다.

따라서 커밋이 주장하는 “없음과 있는데 실패를 구분”은 일부 non-zero exit에만 성립합니다.

## 요청 항목별 결론

- Linux K1 경계 설명은 대체로 맞습니다. host key는 root만 접근 가능하고, TPM 없이 디스크와 host secret을 함께 가져가면 보호되지 않는다는 설명도 맞습니다.
- 다만 **Agent가 host secret에 접근할 권한, 사실상 root 권한이 필요하다는 운영 전제**가 빠졌습니다. 비-root Agent에서는 `systemd-creds`가 설치돼 있어도 K1이 실패할 수 있습니다.
- 개인키는 명령줄·임시 파일로 전달되지 않습니다. 그러나 plaintext가 Agent 메모리 외에 커널 pipe와 `systemd-creds` 프로세스 메모리에도 한 번 더 존재합니다. “누출이 없다”가 아니라 “명령줄·임시 파일 누출을 피했다”가 정확합니다.
- `DeviceChanged`를 `Legacy`로 내린 방향은 맞습니다. `Legacy → Protocol`로 분류되어 남은 connection budget이 있으면 다음 accept로 갑니다(`coordinator/src/lib.rs:504`, `:415-421`, `:795`). 저장 손상은 계속 fatal입니다.
- 다만 기본 `max_connections=1`이고 마지막 허용 연결에서 protocol 오류가 나면 Coordinator는 여전히 `Err`로 종료합니다. 따라서 “항상 그 세션만 거부되고 나머지는 계속 돈다”는 주장은 과장이고, “남은 연결 예산 동안 계속 돈다”가 정확합니다.
- `--heartbeat-interval-ms` 파싱 실패를 `unwrap_or(0)`으로 조용히 바꾸는 새 폴백도 있습니다(`agent/src/lib.rs:1917-1921`). 잘못된 값은 명시적으로 거부해야 합니다.

읽기 전용 제약 때문에 빌드 산출물을 만드는 `cargo test`는 실행하지 않았습니다. 커밋 객체의 diff·호출 경로·테스트 소스를 직접 추적했고 `git diff --check 51bf255^ 51bf255`는 통과했습니다. 현재 작업 트리의 커밋 이후 미커밋 변경은 판정에서 제외했습니다.
