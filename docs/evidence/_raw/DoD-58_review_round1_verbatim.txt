### 4. [중간] `derive_replay_nonce`는 수학적으로 단사가 아니다 — `4c97a61`

새 입력 직렬화는 올바르게 경계를 분리합니다.

```text

```

따라서 기존의 이어붙이기 반례는 제거됐습니다. 그러나 마지막에 BLAKE3 결과를 16바이트로 자릅니다.

- [nonce.rs:43](C:/Users/playdata2/Documents/test_workspace/gPUteer/gputeer/crates/protocol/src/nonce.rs:43)

입력 공간은 무한하고 출력은 \(2^{128}\)개이므로 함수 자체는 반드시 충돌합니다. 즉:

- “해시 입력 인코딩이 단사다”는 맞습니다.
- “derive_replay_nonce가 단사다”는 틀립니다.
- 현실적인 BLAKE3-128 충돌 반례는 계산상 찾기 어려우며 이번 검수에서도 발견하지 못했습니다.
- 보장 표현은 “128비트 충돌 저항에 의존하는 결정적 nonce”가 정확합니다.

세 호출부가 공통 함수를 쓴다는 주장은 맞습니다. Agent, Coordinator, selftest의 로컬 wrapper가 모두 `gputeer_protocol::nonce::derive_replay_nonce()`를 호출합니다.

## 질문별 결론

1. 별도 `lease_store`/`replay` Mutex 사이에 저장소 안전성을 깨는 TOCTOU는 없습니다. `issue_grant()` 전체가 lease-store 잠금 안에서 실행되고 SQLite도 `BEGIN IMMEDIATE`를 사용하므로 두 발급이 저장소를 동시에 변경하지 않습니다. 다만 replay 잠금을 네트워크 `read_frame()` 동안 잡아 모든 ingress 읽기를 직렬화하며, 느린 Agent 하나가 최대 타임아웃 동안 다른 Agent의 검증을 막습니다. 이는 안전성보다는 동시성·가용성 문제입니다.

2. 32비트 `short_tag` 분리는 불충분합니다. 실제 충돌 반례가 있으며, 저장소 미사용 경로에서는 충돌하는 서명된 Lease가 생성됩니다.

3. `declare_domains!`는 “enum variant를 추가하고 `ALL`이나 tag match에서 빠뜨리는” 정확한 구멍은 닫았습니다. Rust enum variant를 다른 곳에서 추가할 수는 없습니다. 다만 새 `Signable` 메시지가 기존 `Domain`을 재사용하는 것은 여전히 가능하므로 “모든 서명 대상이 고유 Domain을 갖는다”까지 강제하지는 않습니다.

4. 기존 직렬화 충돌은 해결됐지만 128비트 해시 출력 때문에 함수 자체는 단사가 아닙니다. 세 호출부의 단일 함수 사용은 확인됐습니다.

5. 시나리오 88은 순차 서버에서도 통과합니다.

6. 코드가 뒷받침하지 않는 핵심 주장:

   - “mode 차이로 multi-agent와 Resume lane이 분리된다.”
   - “Agent마다 식별자가 확실히 분리된다.”
   - “derive_replay_nonce가 단사다.”
   - “device_id와 coordinator_device_id 대조 모두 negative test로 보호된다.”

읽기 전용으로 검수했으며 파일은 변경하지 않았습니다.
