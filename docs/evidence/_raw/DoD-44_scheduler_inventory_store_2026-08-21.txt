=== 구현·검증 기록 — scheduler 로드맵 조각 3a ===

완료 범위는 scheduler 로드맵 조각 3 전체가 아니라
**single-Coordinator durable Agent inventory repository kernel(3a)**이다.
실제 다중 연결, heartbeat wire, enrollment/signature 검증, active-session
owner/fencing, Raft/ControlStore, reservation/dispatch는 구현하거나 입증하지 않았다.

`crates/coordinator/src/inventory_store.rs`를 신설해
`CoordinatorInventoryStore`를 구현했다. `register_agent()`는 동일한 정규화
registry payload만 멱등 처리하고 node/device/key/owner 충돌을 기존 행 무변경으로
거부한다. `update_inventory()`는 한 `BEGIN IMMEDIATE` transaction에서 parent와
GPU/workload child 전체를 교체한다. 낮은 revision과 같은 revision의 다른 payload는
fail closed하고, 같은 revision의 byte-equivalent normalized payload만 멱등 성공한다.
`pool_snapshot()`은 한 read snapshot을 기존 `gputeer_scheduler::PoolSnapshot`으로
투영하고 node ID 순으로 Rust `sort_by()` 한 곳에서만 정렬한다.

=== 자체 재검토 — 수정·확인 5건 ===

1. 공개키 입력을 `[u8; 32]`에서 `Vec<u8>`로 바꾸고 API 경계와 DB read에서
   정확히 32-byte인지 명시 검사했다. 31-byte 입력과 손상 DB key는 fail closed한다.
2. 두 connection 경쟁 후보의 GPU/workload/third-party opt-in을 포함한 모든 필드를
   서로 다르게 만들어 parent/child 혼합을 최종 구조체 전체 비교로 잡도록 보강했다.
3. registry SQL의 중복 `ORDER BY`를 없애고 projection의 Rust sort 한 곳만 node
   결정성의 권위로 남겼다. 이 sort 제거 뮤테이션이 실제 테스트를 깨뜨린다.
4. 최대 revision/time/resource, stale/future 관측 시각, unknown 대 명시적 zero,
   손상 enum/key/revision/child row와 기존 Coordinator/Agent/Lease API 회귀를 재확인했다.
5. write는 `BEGIN IMMEDIATE`, snapshot은 upgrade 없는 read transaction이고 wire/session
   대기 루프를 추가하지 않았음을 추적해 새 교착 경로가 없음을 확인했다.

=== negative·경계·경쟁 검증 ===

- Agent 2개 저장·reopen과 삽입 순서 무관 node/GPU 결정 정렬.
- registry 10회 멱등 retry, node/device/key/owner 충돌과 기존 행 무변경.
- 동일 revision normalized payload 멱등, payload 차이와 낮은 revision 거부.
- parent 기록 뒤·GPU child 교체 중·workload child 교체 중 오류 주입 시 이전
  parent/GPU/workload 전체 rollback.
- 공백 identity, 31-byte key, 빈/중복 GPU ID, 공백 GPU model, 미등록 node 거부.
- unknown과 명시적 zero/empty/false 구분, stale/future 시각 보존과 scheduler 거부.
- 별도 SQLite connection 두 개의 같은 next revision 경쟁에서 정확히 한 완전 payload.
- 손상 enum/key/revision/GPU child/redundant payload/marker boolean을 `CorruptData`로 거부.

=== 뮤테이션 검증 ===

1. `pool_snapshot()`의 유일한 node 정렬을 제거하면
   `multiple_agents_reopen_and_project_in_node_order`가 실제 `[node-b, node-a]`,
   기대 `[node-a, node-b]`로 실패했다. 원복했다.
2. revision 비교를 `<`에서 `<=`로 바꾸면 동일 revision 멱등 테스트가
   `LowerRevision { stored: 8, requested: 8 }`로 실패했다. 원복했다.

=== 범위 결론 ===

scheduler 로드맵 조각 3을 전부 완료한 것이 아니다. 완료한 것은 검증·정규화가
끝난 복수 Agent inventory를 single-Coordinator SQLite에 원자·영속 기록하고 기존
`PoolSnapshot`으로 결정 투영하는 저장소 kernel(3a)이다. 실제 다중 연결·heartbeat
wire·session owner/fencing과 조각 4~9는 후속이다.
