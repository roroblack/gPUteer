   않았는데 Agent 가 거부하지 않았다." → 원복 → 재통과.
3) crates/agent/src/lib.rs — epoch 상승 거부 검사를
   `if false && new_lease.fence_epoch > held_lease.fence_epoch` 로 무력화 →
   시나리오 15 가 정확히 예상대로 실패: "epoch 상승(0 -> 5) 갱신을 Agent 가
   거부하지 않았다 — 계획서는 이를 범위 밖 정책 거부로 명시했다." → 원복 →
   재통과.
4) crates/coordinator/src/lib.rs — 요청 fence_epoch 대조 검사를
   `if false && renew_req.fence_epoch != config.fence_epoch` 로 무력화 →
   시나리오 16 이 정확히 예상대로 실패: "요청의 fence_epoch(99) 이
   Coordinator 가 기억하는 값(0)과 다른데 거부되지 않았다." → 원복 → 재통과.
모든 무력화는 백업(cp)→edit→cargo build→selftest 실행→원복(mv)→touch(mtime
갱신)→재빌드→재통과 순서로 진행했다. 마지막 재통과 확인은 위 5회 연속
실행(정상 상태)이 대표한다.
