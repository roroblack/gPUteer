동의가 아니라 **반박**을 원한다. Coordinator 파서가 모르는 플래그를 받아
두던 것(재검수 14)을 고치면서, Agent 파서도 같은 모양이라 같은 방법으로
고쳤다. 이 수정이 **멀쩡한 호출을 막는지**, 그리고 **여전히 조용히 사라지는
플래그가 있는지** 봐 달라.

# 배경

```text
전     parse_flags 가 아무 이름이나 HashMap 에 넣고, 설정 파서가 필요한 것만
       flags.0.get(...) 으로 골라 읽었다. `--send-attempt-reprot true` 같은
       오타는 조용히 사라지고 운영자는 보고를 켰다고 믿는다
지금   Flags 가 **읽은 키를 기록**한다. 설정을 다 만든 뒤 한 번도 안 읽힌
       키가 있으면 STARTUP_REFUSED: UNKNOWN_FLAGS
★     Coordinator 쪽에서 정규식이 새 `get` 메서드의 본문까지 바꿔 자기 재귀가
       났었다. Agent 쪽은 치환을 먼저 하고 메서드를 뒤에 넣었다
★     전제 — 설정 파서가 **모든 플래그를 조건 없이 한 자리에서** 읽는다.
       이 전제가 깨지면 멀쩡한 플래그가 "모르는 이름" 으로 거부된다
```

수정 쪽이 잰 것: Agent 테스트, selftest, 뮤테이션. 믿지 말고 구조로 판정하라.

# 물을 것 — 네 가지

1. **전제가 성립하나.** `parse_config_from_args` 안에서, 또는 거기서 부르는
   도우미 안에서 어떤 플래그가 **조건부로만** 읽히나(`if`·`match` 가지,
   `and_then` 안, 다른 플래그 값에 따라)? 그렇다면 그 조건이 아닐 때 준
   그 플래그는 거부된다 — 구체적 인자로 보여라.

2. **여전히 조용히 사라지는 것이 있나.** 읽기는 하는데 값을 버리는 플래그,
   또는 Flags 를 거치지 않고 인자를 직접 보는 경로.

3. **selftest 가 Agent 에 넘기는 인자 중 거부될 것이 있나.** 수정 쪽은
   selftest 를 돌렸다고 한다 — 그 결과를 믿지 말고 인자 목록으로 대조하라.

4. **새 테스트가 관문을 고정하나** — 관문을 끄면 실패하고, "전부 거부" 로
   바꾸면 대조 테스트가 실패하는 구조인가.
