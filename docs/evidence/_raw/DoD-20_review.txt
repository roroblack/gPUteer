## `.proto` 파서 대안 비교

### descriptor 방식 — 권장

장점:

- 주석과 문자열 내부의 `message`, `=`를 무시함
- import, enum, map, oneof, nested message를 구조적으로 해석함
- `uint32`와 `uint64`, enum과 message를 정확히 구분함
- `FileDescriptorSet`과 `descriptor_pb2`는 protoc의 정규 출력 형식임
- `--include_source_info`로 `proto/control.proto:314` 같은 위치를 출력할 수 있음

단점:

- `protoc` 실행 파일이 필요함
- 임시 descriptor 파일 생성이 필요함
- protoc 버전 관리가 필요함

### 정규식 파싱

장점:

- 외부 실행 파일이 필요 없음
- 구현이 작음

단점:

- multiline 선언, 주석, map synthetic entry, oneof, nested message에 취약함
- enum인지 message인지 별도 symbol table이 필요함
- protobuf 문법이 확장될 때 계속 parser를 고쳐야 함

따라서 정규식은 오류 메시지 보조용으로도 권장하지 않고, descriptor 방식을 정식 구현으로 삼는 것이 맞습니다.

`reference_canonical.py`는 import 시 CLI를 실행하지 않고, 실제 CLI 진입점은 하단의 `if __name__ == "__main__"`입니다 (`reference_canonical.py:1769-1809`). 따라서 `SCHEMAS`, `DOMAIN_TAGS`, `DERIVED_HASH_FIELDS`를 import하는 것은 안전합니다.

```text
check_schema.py
```

CI에서는 다음 순서를 권장합니다.

```text

python tools/canonical/reference_canonical.py --self-test
python tools/canonical/reference_canonical.py --verify tests/vectors/canonical_v1.json
```

`check_schema.py`가 `--self-test`나 `--verify`를 내부 호출할 필요는 없습니다. 실패 원인을 분리하는 편이 낫습니다.

## 이 개발 기계에서 완결 가능한가

부분적으로는 가능하지만, “현재 read-only 감사 환경에서 descriptor 생성까지 완주했다”고 말할 수는 없습니다.

확인된 환경:

- `protoc`: `C:\Users\playdata2\anaconda3\Library\bin\protoc.exe`
- 버전: `libprotoc 25.3`
- Python: `C:\Users\playdata2\anaconda3\python.exe`
- `google.protobuf`: `7.35.1`
- `descriptor_pb2.FileDescriptorSet` import 가능

`protoc --descriptor_set_out`와 `--include_imports`, `--include_source_info` 옵션도 존재합니다. 다만 현재 샌드박스는 read-only라 descriptor 출력 파일을 만들 수 없었습니다. `--descriptor_set_out=NUL` 시도도 파일 권한 오류로 끝났습니다. 이는 `.proto` 문법 오류가 아니라 감사 환경의 쓰기 제한입니다.

추가 함정은 protoc 이중화입니다.

- `check_schema.py`는 PATH의 system/anaconda `protoc 25.3`를 사용할 수 있음
- Rust `build.rs`는 `protoc_bin_vendored`로 별도 vendored protoc를 사용함 (`crates/protocol/build.rs:9-11`)

따라서 모든 환경에서 동일한 compiler를 쓴다고 보장할 수는 없습니다. 다만 검사 대상이 descriptor의 메시지·field number·name·type뿐이고, descriptor 출력에서 source info와 순서를 정규화하면 protoc 버전 차이의 영향은 작습니다. CI에서는 `protoc --version`을 출력하고, 최소 지원 버전을 명시하는 것이 안전합니다.

결론적으로 설계와 구현은 저장소 코드만으로 완결 가능하지만, 현재 read-only 세션에서는 descriptor 파일 생성·파싱의 end-to-end 실행만 외부 writable 환경에서 한 번 더 검증해야 합니다.
