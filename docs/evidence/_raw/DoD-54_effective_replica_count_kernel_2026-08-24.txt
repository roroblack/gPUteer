=== 규범 경계 ===

- `docs/protocol/state-machines.md:220-223`은 signed `ReplicaAck` 수신 때 유효 replica
  수를 갱신하고, `REPLICATED -> COMMITTED` guard를 “유효 replica 수 >= 요구치”로 둔다.
  `docs/protocol/`에는 `MIRRORED`의 수치 의미를 직접 정의한 문장이 없다.
- `proto/common.proto:148-153`의 protobuf 계약은 `DURABILITY_MIRRORED`를
  `REPLICATED(1)`, `DURABILITY_REPLICATED`를 서로 다른 failure domain의
  `REPLICATED(2)`로 정의한다.
- `proto/artifact.proto:135-152`는 유효 holder 서명, 같은 failure-domain 중복 제거,
  ephemeral node의 local copy 제외, submitter/worker가 같은 device인 복사본 중복 제거 뒤의
  수를 `effective_replica_count`로 정의한다.
- `docs/protocol/signing.md:514-527`은 Ed25519 검증 뒤 signer의 팀 membership/승인을
  확인하고 그 뒤에야 필드 값을 신뢰하도록 규정한다.
- replica count 규범에는 holder가 현재 `ONLINE`이어야 한다는 조건이 없다. 이번 구현은
  규범에 없는 liveness gate를 추가하지 않았다.

=== 구현 ===

- `crates/checkpoint/src/durability.rs:24-127`에 `ReplicaKind`, `FactResolution`,
  `HolderValidation`, `ResolvedHolderObservation`, `EffectiveReplicaReport`,
  `ReplicaEvaluationError`와 report 구성 타입을 추가했다.
- `crates/checkpoint/src/durability.rs:178`의 `evaluate_effective_replicas()`는
  `&[ResolvedHolderObservation]`과 `Durability`만 받는 순수 kernel이다. system clock,
  ACK TTL, I/O, filesystem, DB, network, 난수, membership 조회 또는 전역 상태를 읽지 않는다.
  입력 검증, 정렬과 `BTreeMap`/`BTreeSet` 집계만 수행한다.
- resolver가 holder별로 선택한 관측은 `selected=true`로 들어온다. kernel은 timestamp 최댓값을
  고르거나 TTL을 적용하지 않는다. selected 관측만 후보로 쓰고 superseded 관측은 정렬된
  report에 보존한다.
- selected 관측은 canonical 정렬한 뒤 current signature/membership 승인, 필요한 authority fact,
  ephemeral local 규칙을 평가한다. 유효 후보는 resolved failure domain별로 하나만 세며,
  counted/excluded/superseded 목록 전체를 결정적으로 반환한다.
- 동일 holder의 selected 관측이 둘 이상이면 `validate_observations()`가 후보 계산 전에
  `MultipleSelectedObservations`를 반환한다. 조용히 첫 행이나 최신 행을 고르는 경로가 없다.
- empty checkpoint/root/holder/domain과 mixed checkpoint/root는 typed error로 fail closed한다.
- `crates/checkpoint/src/lib.rs:11`은 신규 타입과 함수를 additive re-export한다.

=== 결정성과 freshness 경계 ===

`crates/checkpoint/tests/effective_replica_kernel.rs`의 재귀 `permutations()`는 4개 관측의
실제 4! = 24개 순열을 모두 생성한다. `report_is_identical_for_every_input_permutation`은
각 순열의 count만 비교하지 않고 `EffectiveReplicaReport` 전체를 `assert_eq!`로 비교한다.

`selected_old_observation_wins_over_newer_superseded_without_ttl_or_latest_rule`은
`acked_at_unix_ms=1`인 오래된 관측을 selected로, `u64::MAX`인 최신 관측을 superseded로
제공한다. 결과가 오래된 selected 관측 하나를 세고 최신 관측을 superseded에 보존하므로,
kernel에 timestamp 최대값 또는 TTL freshness 판정이 없음을 고정한다.

=== 자체 재검토와 legacy 주석 ===

초안은 `is_ephemeral` 해석이 unresolved/ambiguous이면 replica kind와 무관하게 모든 관측을
제외했다. 그러나 `proto/artifact.proto:141`은 ephemeral node의 local copy만 제외한다.
이에 ephemeral 해석을 `ReplicaKind::WorkerLocal`일 때만 요구하도록 production 분기를 수정하고,
`non_local_kind_does_not_require_irrelevant_ephemeral_resolution` 회귀 테스트를 추가했다.
독립 검수는 unresolved/ambiguous ephemeral non-local이 세어지는 방향과 ephemeral local이
제외되는 반대 방향을 모두 확인해 과잉 제외와 누락 모두 없다고 판정했다.

기존 `ReplicaSet`의 “규칙 1~4 적용” 주석은 타입이 holder freshness, kind, current membership을
표현하지 못하는 실제 한계와 맞지 않았다. 실행 코드를 바꾸지 않고 legacy 한계와 신규 결정
경로가 `evaluate_effective_replicas()`임을 주석으로 명시했다.

=== negative test와 뮤테이션 판별력 ===

- 4개 관측의 24개 순열에서 report 전체 동등성.
- 같은 holder의 selected 두 행은 후보 계산 전에 `MultipleSelectedObservations`.
- 오래된 selected/최신 superseded 조합은 kernel이 freshness 정책을 발명하지 않음을 고정.
- 동일 failure domain의 서로 다른 holder는 canonical holder 하나만 count.
- invalid signature, 미승인 holder, unresolved/ambiguous membership은 count하지 않음.
- unresolved/ambiguous failure-domain과 `WORKER_LOCAL` ephemeral fact는 count하지 않음.
- ephemeral non-local kind에는 불필요한 ephemeral 해석을 요구하지 않고, ephemeral
  `WORKER_LOCAL`만 제외.
- 같은 device의 서로 다른 kind는 별도 replica로 세지 않음.
- `LOCAL=0`, `MIRRORED=1`, `REPLICATED=2` threshold와 empty input 경계.
- mixed checkpoint/root와 빈 checkpoint/root/holder/domain은 typed error.
- 뮤테이션 1: production duplicate-selected 검사를 제거하자
  `duplicate_selected_holder_fails_closed_instead_of_counting`이 같은 holder가 count 2로 계산되는
  것을 검출했다. guard 원복 뒤 재통과했다.
- 뮤테이션 2: production `kind == WORKER_LOCAL` guard를 제거하자
  `only_ephemeral_worker_local_is_excluded`가 ephemeral non-local까지 제외된 기대 count 1,
  실제 0을 검출했다. guard 원복 뒤 재통과했다.

=== 범위 밖과 잔여 위험 ===

- authoritative membership/failure-domain resolver와 durable ACK consumer가 아직 없다.
- 결과는 resolver가 제공한 평가 시점의 count이며 현재 holder liveness를 증명하지 않는다.
- `MIRRORED` 판정 적용과 checkpoint 상태 전이는 범위 밖이다.
- freshness 판정은 kernel 밖 resolver 책임이다. kernel은 holder당 selected가 둘 이상이면
  fail closed할 뿐 어느 관측이 fresh한지는 고르지 않는다.
- `ONLINE` 조건은 replica 규범에 없어 추가하지 않았다.
- raw ACK load/reverify, Job durability projection, durable count 저장, production routing,
  liveness/degraded 복구는 범위 밖이다.
