문서에 적어 두기만 하면 누군가는 켠다. 그래서 조건 2 는 만료 시각만 보지
않고 [`PartitionPauseEnforcement`] 를 **함께** 요구한다. 기본값이 없으므로
호출부는 반드시 값을 쓰고, 오늘 정직하게 쓸 수 있는 값은
`NotEnforcedYet` 하나다 — 나머지 조건이 완벽해도 거부된다.

```text
todays_honest_caller_is_always_refused
  나머지가 전부 채워진 요청 -> Refused { [PartitionPauseNotEnforced] }
  막는 이유가 정확히 그 하나여야 한다

with_the_missing_enforcement_asserted_the_rest_does_pass
  같은 요청에 EnforcedByCaller 만 넣으면 -> Allowed { fence_epoch: 105 }
  이게 없으면 위 테스트는 공허하다 — 아무 이유로나 거부해도 통과한다
```

## 검수가 10라운드 동안 찾은 것 중 무거운 셋

**1. 이미 쓴 105 보다 낮은 104 를 허용했다**(3라운드).

초안은 예비 범위의 **시작**이 원래 번호보다 크기만 하면 통과시켰다.
`original=100`, 범위 `101..=110`, 이미 쓴 `{105}` 에서 `104` 가 허용됐다 —
105 가 이미 돌았는데 104 로 되돌아가는 것이고, 그건
`crates/protocol/src/fenced_operation.rs` 가 `StaleFence` 로 거부하는 바로
그 상황이다. 게다가 정직하게 현재 번호를 `original=105` 로 넣으면 범위
시작 101 이 그보다 낮아 입력 오류가 났다 — `ADR-033` §8 의 "범위를 다 쓸
때까지 재할당" 과 정반대였다.

이제 제안 번호가 **원래 번호와 이미 쓴 번호 전부보다** 커야 한다.

**2. "이웃 N 대" 를 멤버 수로 셌다**(5라운드).

`ADR-033` §8 조건 3 은 "이웃 N **대**" 다. 멤버 수로 세면 한 멤버의 기계
두 대가 한 표가 되고, 한 기계에 멤버 ID 가 둘이면 두 표가 된다. 신고에
`reporter_node_id` 를 추가하고 기계 수로 센다.

**3. 내가 "어느 계층도 ULID 를 강제하지 않는다" 고 썼는데 거짓이었다**(3라운드).

`crates/protocol/src/fenced_operation.rs` 가 정확히 job/attempt ID 를 26자로
거부한다. 확인하지 않고 쓴 문장이었다. job/attempt ID 는 이제 여기서도
26자를 강제하고, node/member ID 는 scheduler 의 다른 커널과 어긋나지 않게
최소 형태 검사만 한다는 경계를 명시했다.

## 내가 반복해서 과장했다

10라운드 중 **6개 라운드**가 코드 결함이 아니라 **내 서술이 사실보다 강한
것**을 지적했다.

```text
"타입으로 강제한다"          -> 확인 못 한다. 요구할 뿐이다
"아무것도 허용하지 못한다"    -> 테스트는 오늘도 Allowed 를 받는다
"정본과 같은 규칙을 쓴다"     -> membership.rs 의 Ambiguous 와 다른 상황이다
"다른 기록을 못 붙인다"       -> 값이 어긋난 기록만 거른다
"담합한 다수와 같은 종류"     -> 다른 공격 모델이다
"같은 멤버는 한 표"          -> 같은 기계가 한 표다
```

전부 고쳤다. 남길 교훈은 **한계를 적었다고 정확한 것은 아니다** 는 것이다 —
한계를 적으면서도 그 위 문장에서 보장을 부풀리고 있었다.
