## 3. S1 — Windows 파일시스템 원자성 조사

### 왜 Rust 보다 먼저인가

기준선 §18.2 와 `docs/protocol/state-machines.md` §4 는 다음을 규범으로 요구한다.

```text
1. <name>.tmp 에 기록 -> fsync(file) -> rename(name) -> fsync(dir)
2. 매니페스트는 데이터 파일이 모두 확정된 뒤 마지막에 쓴다
3. 매니페스트 없는 데이터 파일은 PARTIAL 로 간주하고 부팅 시 GC
```

**그런데 규칙 1 의 `fsync(dir)` 은 POSIX 개념이다. Windows 에는 디렉터리 fsync 가 없다.**
Rust 구현을 시작하기 전에 **Windows 에서 이 규범이 실제로 성립하는지** 확인해야 한다.
성립하지 않으면 규범 문서를 먼저 고쳐야 한다(`RULE.md` §3.5 — 계약이 코드보다 먼저).

### 조사 항목

- [ ] `os.replace()` (Windows `MoveFileEx` + `REPLACE_EXISTING`)가 기존 파일 위로 원자적인가
- [ ] 디렉터리 핸들에 `FlushFileBuffers` 가 가능한가 — 불가하면 대안은 무엇인가
- [ ] 쓰기 도중 프로세스 강제 종료 시 `.tmp` 만 남고 확정 파일은 온전한가
- [ ] 매니페스트 없는 데이터 파일을 GC 로 식별할 수 있는가
- [ ] NTFS 외 파일시스템(exFAT 등)에서 동작이 달라지는가

### DoD

- [ ] 위 5개 항목에 **실측 결과**가 있다 (추측 금지)
- [ ] Windows 에서 `fsync(dir)` 대안이 확정되었거나, **불가능함이 확인되고 규범 문서 수정안이 제시**되었다
- [ ] `docs/evidence/P0-03a_windows_fs_atomicity.md` 가 `verify_evidence.py` 를 통과한다

## 4. S3 — P0-03 Checkpoint Durability

기준선 §32 P0-03 의 체크리스트를 그대로 따르되, **GPU 가 필요한 항목은 제외**한다.

```text
포함   tmp -> fsync -> rename 원자적 쓰기
포함   쓰기 도중 프로세스 강제 kill -> partial file GC 확인
포함   BLAKE3 해시 검증
포함   delta 청크 동기화 전송량 측정
포함   durability 상태 전이 (WRITING -> ... -> COMMITTED)

제외   PyTorch 학습 (GPU 없음)  -> 동등한 크기의 더미 텐서 파일로 대체
제외   실제 GPU 간 restore      -> 프로세스 간 restore 로 대체
```

★ **대체한 항목은 evidence 의 `limitations` 에 반드시 적는다.**
"PyTorch 실학습으로 검증하지 않았음" 이 빠지면 그 증거는 반려된다.

### DoD

- [ ] 마지막 `COMMITTED` 체크포인트에서 자동 재개
- [ ] **partial file 이 절대 `COMMITTED` 로 승격되지 않음**
- [ ] delta 동기화가 full 대비 전송량을 실제로 줄이는지 수치 확인
- [ ] negative test (`RULE.md` §6): 쓰기 중 kill · partial file · 해시 불일치 · COMMITTED 후 replica 유실
