## 0. 왜 v2 가 필요한가

**v1 의 범위가 소진되었는데 작업이 계속되고 있었다.**

```text
v1 범위      S0 환경실측 · S1 파일시스템 · S2 툴체인 · S3 P0-03 · S4 canonical
             -> 2026-08-16 08:10 에 전부 완료

이후 수행     DoD-02 (prost 연동) · DoD-03 (서명 완전성) · P0-08 (스키마 진화)
             DoD-04 (Ed25519) · 스트림 소유권 시정
             -> 전부 **계획 밖**이다
```

계획 밖 작업은 나쁘지 않다 — `DoD-01` 이 스스로 지목한 공백을 따라간 결과다.
그러나 **계획 없이 계속 가면 "왜 이것을 하는가" 가 흐려지고 범위가 샌다** (`RULE.md` §3.3).

★ 이 계획은 **되돌아보며 쓰는 것이 아니라 앞을 정하기 위해** 쓴다.
이미 한 일은 §1 에 현재 상태로만 적고, 단계표에는 **남은 것만** 넣는다.

## 2. 범위

### In


### Out

```text

    -> Agent 실행 계층이 없다. TODO_VISION V-06. **v0.1 필수이나 이 계획 밖**

crates/coordinator · agent · scheduler · cli · UI
    -> T1~T4 가 끝나기 전에 착수하지 않는다

    -> TODO_VISION V-05. 트리거가 오지 않았다
```

**Out 항목의 코드가 들어오면 되돌린다** (`RULE.md` §3.3).

### 순서 근거

```text
T1  가장 싸고 가장 확실하다. 기존 도구(field_number_audit · 벡터)가 이미 있다
T2  T1 다음. §9 의 죽은 코드 문제를 실메시지로 확인해야 결론이 난다
T5  T1 과 함께. 같은 감사 도구를 확장하는 일이다
T3  T4 의 선행 — 키가 없으면 replay 캐시의 namespace 키를 정할 수 없다
T4  저장소 계층이 필요해 가장 무겁다
T6  D-3 이 풀려야 시작 가능. **차단 중이지만 v0.1 필수다**
```

★ **T6 이 이 계획의 최대 위험이다.** v0.1 주 타깃이 Linux 컨테이너 워커인데
지금까지 **한 번도 Linux 에서 돌려본 적이 없다.**
Windows 에서 105건이 통과한다는 사실은 Linux 에 대해 아무것도 말하지 않는다
(`CLAUDE.md` §4 — "한 플랫폼 통과를 다른 플랫폼 통과로 세지 않는다").

## 4. 완료 기준 (DoD)

각 항목은 `docs/evidence/` 기록이 있어야 통과로 센다.

- [ ] **T1** — `signing.md` §5 domain_tag 17종 전부에 대응하는 `ToCanonicalFields` 가 있다.
      `every_impl_is_audited` 와 `every_unsigned_field_is_declared_in_unimplemented_list` 가
      17종 전부를 덮는다
- [ ] **T2** — `Lifetime::ShortLived` 실메시지가 3종 이상 있고, 각각 skew · 만료 · nonce
      경계 테스트를 갖는다. §9 의 "TTL == skew 로 미래 방향 skew 가 죽는" 문제가
      **해소되었거나 ADR 로 수용 근거가 기록되었다**
- [ ] **T3** — 키 폐기 후 그 서명자가 `UnknownSigner` 가 되는 것을 테스트로 확인.
      `InMemoryKeyring` 이 운영 경로에서 **쓰이지 않음**을 코드로 강제
- [ ] **T4** — 같은 nonce 재사용 거부. **상한 도달 시 축출이 아니라 거부**(§10)임을 확인.
      미만료 nonce 가 축출되지 않음을 확인
- [ ] **T5** — 중첩 메시지의 각 필드를 기본값으로 되돌렸을 때 canonical 이 변한다
- [ ] **T6** — Linux 에서 `cargo test --workspace` 전건 통과.
      **Windows 결과를 Linux 통과로 계상하지 않았다**
- [ ] 모든 항목에 **negative test** 가 있다 (`RULE.md` §6)
- [ ] `ENVIRONMENT-BLOCKED` 가 `PASS` 로 계상되지 않았다
