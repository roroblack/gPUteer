# Resume 프로토콜 v1 — 로드맵 조각 3

## 범위

이 문서는 `2026-08-20_0300_자동_재접속_루프_전체_설계_v1.md`의 자동 재접속 7조각 중 조각 3 구현을 기록한다. 조각 1·2의 최소 재접속 경로와 `DoD-35`의 기존 server-first Grant/ACK 동작을 전제로 하며, 기존 경로를 변경하지 않는다.

이번 조각은 명시적으로 opt-in한 호출자만 사용하는 Hello-first Resume lane을 추가한다. 같은 포트에서 wire 순서를 자동 탐지하지 않으며, 기본값은 기존 묵시적 FRESH(Grant-first) handshake다. `SESSION_MODE_FRESH`는 proto 예약값으로만 정의하고 실제 새 FRESH lane은 구현하지 않는다.

## 설계

- `SessionMode`, `AgentSessionHello`, `ResumeLeaseRequest`, `ResumeLeaseResult`, `ResumeOutcome`을 proto에 추가한다. 기존 field number는 유지하고 세 새 메시지는 모두 서명 대상이다.
- Hello와 요청은 node signer와 CSPRNG nonce를 포함하는 `ShortLived` 메시지로, 결과도 `RenewLeaseResult`와 같은 짧은 검증 lifetime으로 서명한다.
- canonical domain은 `gputeer/v1/session-hello`, `gputeer/v1/lease-resume`, `gputeer/v1/lease-resume-result`를 사용한다. 기존 25개 domain은 보존하고 총 28개가 된다.
- Coordinator는 `read_frame()` 후 서명/schema/time/replay 검증, Hello·Request 상관관계 검증, 읽기 전용 `classify_resume()` 판정, 서명된 결과 전송 순으로 처리한다.
- `classify_resume()`는 unknown lease → identity conflict → revoked → expired(`<=`) → lower epoch(SUPERSEDED) → higher epoch(EPOCH_AHEAD) → same epoch(RESUMED) 순서다. RESUMED에서도 저장된 만료시각은 연장하지 않는다.
- Agent는 `--resume-protocol`이 있을 때만 Resume lane을 선택하고, 기본값에서는 기존 Grant-first 경로를 그대로 사용한다. Resume 결과의 terminal outcome을 받은 뒤 같은 연결에서 추가 frame을 기다리지 않는다.

## 검증 방법

- Python reference canonical self-test와 기존 vector verify를 실행하고, 새 3개 vector 및 schema fingerprint를 재생성한다.
- protocol/crypto/coordinator/agent 단위 테스트와 전체 workspace build/test를 실행한다.
- Coordinator/Agent process-boundary selftest 53~60에서 각 시나리오별 독립 임시 SQLite DB를 사용해 RESUMED, UNKNOWN_LEASE, IDENTITY_CONFLICT, REVOKED, EXPIRED, SUPERSEDED, EPOCH_AHEAD, UNAVAILABLE을 검증한다. 기존 1~52는 같은 실행에서 그대로 회귀 검증한다.
- `classify_resume()`의 revoke 우선순위와 epoch 방향을 임시 mutation으로 바꿨을 때 대응 테스트가 실패하는지 확인하고 구현을 원복한다.
