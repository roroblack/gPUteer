# Agent Resume 통합 v1 — terminal outcome 명시화

- **일시:** 2026-08-20 14:10 (Asia/Seoul)
- **근거:** `docs/plans/2026-08-20_0300_자동_재접속_루프_전체_설계_v1.md` 조각 6, `docs/evidence/DoD-36_resume_프로토콜.md`, `docs/evidence/DoD-37_coordinator_dispatcher_정교화.md`
- **범위:** Agent Resume 응답의 terminal outcome 오류 문자열 구분과 기존 selftest 53~59 검증 강화

## 구현 계약

`crates/agent/src/lib.rs`의 `run_resume_connection()`은 기존 성공·재시도 경로를 유지한다.

| Resume outcome | Agent 처리 |
|---:|---|
| `RESUMED=1` | 기존 Lease 검증 후 성공 |
| `REVOKED=2` | `RESUME_REFUSED:REVOKED`로 즉시 실패 |
| `EXPIRED=3` | `RESUME_REFUSED:EXPIRED`로 즉시 실패 |
| `SUPERSEDED=4` | `RESUME_REFUSED:SUPERSEDED`로 즉시 실패 |
| `UNKNOWN_LEASE=5` | `RESUME_REFUSED:UNKNOWN_LEASE`로 즉시 실패 |
| `IDENTITY_CONFLICT=6` | `RESUME_REFUSED:IDENTITY_CONFLICT`로 즉시 실패 |
| `UNAVAILABLE=7` | 기존 `RETRYABLE_RESUME`로 bounded reconnect 대상 |
| `EPOCH_AHEAD=8` | `RESUME_REFUSED:EPOCH_AHEAD`로 즉시 실패 |

Renew 경로의 `RENEW_REFUSED:<OUTCOME>` 패턴과 같은 직접 `match` arm을 사용한다. 알려진 terminal outcome의 오류 문자열만 구체화하며, 재시도 분류 조건인 `RETRYABLE_RESUME`은 변경하지 않는다.

## selftest 보강

기존 `crates/cli/src/coordinator_agent_selftest.rs`의 시나리오 53~59 공통 assert를 강화한다.

- terminal outcome 54~59는 Agent stdout/stderr에서 해당 `RESUME_REFUSED:<OUTCOME>` 문자열을 정확히 확인한다.
- 53의 `RESUMED` 성공 검증은 기존대로 유지한다.
- 모든 53~59에 대해 Coordinator stdout의 `CONNECTION_ATTEMPT`가 정확히 1회인지 확인해 두 번째 연결이 accept되지 않았음을 검증한다.
- Coordinator dispatch/lease 판정 코드와 proto는 수정하지 않는다.
