# 2026-08-19_1517_lease_revoke_최소_조각_v1

- **기준선:** `docs/plans/2026-08-19_2350_max_total_duration_seconds_갱신_차단_v1.md`
  (Coordinator 영속 Lease 저장소·같은 연결 반복 갱신·durable
  FenceWatermark 위에 `RevokeLeaseNotice` 업무 경로를 얹는다).
- **대상 단계:** v0.1
- **선행 게이트:** DoD-14~18에 해당하는 현재 Coordinator/Agent
  handshake, Lease 발급·갱신·durable 저장소·`RevokeLeaseNotice`
  framed ingress 배선.

## 왜 지금 이 조각인가

`RevokeLeaseNotice` 는 이미 `proto/lease.proto` 와
`crates/protocol/src/signable.rs` 에 서명 대상 메시지로 정의돼 있고,
`FrameType::LeaseRevoke -> IngressMessage::LeaseRevoke` dispatch 도
있다. 그러나 Coordinator 는 통지를 만들거나 보내지 않고 Agent 는
수신 후 보유 Lease 를 폐기하지 않는다. 이 공백을 닫지 않으면
서명된 revoke 명령이 실제 보유 상태에 아무 영향도 주지 않는다.

## 핵심 설계 결정

1. **같은 TCP 연결의 순차 경로를 선택한다.** 기존 DoD-13~18과 같은
   Grant/ACK 뒤 연결을 유지하고, `--revoke-after-round N` 을 준
   Coordinator 가 N회 갱신 결과 뒤 `RevokeLeaseNotice` 를 서명해
   보낸다. `N=0` 은 ACK 직후를 뜻한다. 재접속·failover는 아직
   별도 조각이므로 이번에는 만들지 않는다.
2. **Agent가 검증된 통지 뒤 즉시 상태를 `revoked`로 바꾼다.**
   `read_frame()` 의 `Verified<pb::RevokeLeaseNotice>`만 사용하며,
   `lease_id`와 `fence_epoch`가 현재 보유 Lease와 정확히 일치하고,
   현재 시각에 Lease가 아직 만료되지 않았을 때만 적용한다. 불일치나
   이미 만료된 보유 Lease는 명시적 오류로 거부한다. 통지의 서명 키는
   기존 DoD-17의 V-08 계약(`signer_id() == lease_id`)에 맞춰 Agent의
   Coordinator 공개키를 해당 `lease_id`에도 등록한다.
3. **revoke 뒤 갱신을 전송하지 않는다.** Agent의 고정 갱신 루프는
   다음 회차 진입 시 revoked 상태를 먼저 확인하고
   `RENEW_BLOCKED: lease revoked`를 출력한 뒤 종료한다. 정상 selftest는
   `renew_rounds=2`, ACK 직후 revoke와 양쪽 `do_renew=true`를 사용해
   교착 없이 종료하고 Agent의 로컬 차단 경로와 양쪽의 renew 결과 부재를
   확인한다. 이 stub selftest는 Coordinator가 revoke 뒤 읽기를 하지 않으므로
   wire상 추가 프레임 부재 자체까지 직접 증명하지는 않는다. 일반적인 재발급·Job
   취소·스케줄러 정책은 이 조각에서 정하지 않는다.

## 범위

### In

- Coordinator `RevokeLeaseNotice` 생성·서명·`LeaseRevoke` 프레임 전송.
- CLI `--revoke-after-round` 트리거(완료된 갱신 회차 기준, 0 가능).
- Agent의 revoke 프레임 검증, `lease_id`·`fence_epoch`·만료 상태 대조,
  보유 Lease의 revoked 상태 전이.
- revoked 이후 갱신 시도 차단(요청을 만들거나 보내기 전 차단).
- `coordinator-agent-selftest` 전체 29개 시나리오: 위조 서명, 잘못된 lease_id,
  잘못된 fence_epoch, 이미 만료된 보유 Lease.
- `crates/coordinator` 및 `crates/agent` 단위 테스트와
  `coordinator-agent-selftest` 프로세스 경계 시나리오.

### Out (명시하지 않으면 범위가 샌다)

- 새 `lease_id` 발급, `SUPERSEDED`/`QUARANTINED` 정책 결정,
  revoke 원인 선택 정책, Job 실행 취소·scheduler·다중 Agent.
- 재접속 후 revoke 전달, TLS/HA, revoke replay 방어(기존 메시지의
  Evidence lifetime/멱등성 계약을 바꾸지 않는다).
- `proto/`, `docs/protocol/`, `crates/protocol/`, `Cargo.toml` 수정.
- `docs/evidence/` 작성 및 `CLAUDE.md` 수정. 독립 검수 세션이 담당한다.
