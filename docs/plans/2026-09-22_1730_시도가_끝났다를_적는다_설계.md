# 시도 기록이 "끝났다" 를 말할 수 있게 한다 (§A1 4c · 신뢰망 P1 첫 조각)

> **작성** 2026-09-22 17:30 · **성격** 실행계획 · **논의** 코덱스 72(읽기 전용)
> **선행 결정** 예약 가시성 `B′`(2026-09-08 사용자) · 만료는 지우지 않고 기록만(2026-09-09 검수) · 143(2026-09-21)
> ★ **예약 정책은 이 문서에서 다시 정하지 않는다.** 여기서 정하는 것은 **시도 상태를 어떻게 적는가** 하나다.

## 1. 무엇이 막혀 있나

```text
staging_store.rs:605  Attempt 를 'CREATED' **문자열로 박아** INSERT 한다
staging_store.rs:653  fetch_attempt 는 'CREATED' 가 아니면 손상으로 거부한다
staging_store.rs:673  반환 상태도 무조건 Created 다
attempt_report_store  종료 보고를 저장하지만 **Attempt 상태는 건드리지 않는다**
```

그래서 "이 시도는 끝났다" 를 적을 곳이 없고, 대신 **예약 행의 부재**가 그 역할을 한다.
예약 행은 증거 저장소들의 외래키라 지울 수 없으니(2026-09-09 검수) 예약이 영구히 남는다.

## 2. 결정 — 증거가 증명하는 경로만 적는다 (코덱스 72 권고 C)

```text
원칙  보지 않은 중간 상태를 **합성하지 않는다.**
      경로는 메모리에서 규범 전이로 검증하고, **DB 에는 최종 상태만** 보고 INSERT 와 같은 트랜잭션에서 쓴다
      (중간 상태를 굳이 DB 에 순서대로 쓸 이유가 없다 — 같은 커밋 안이라 관측 순간이 따로 없다)
```

보고 -> 최종 상태 대응. **판단 근거를 같이 적는다**:

```text
COMPLETED · STALE_COMPLETED         -> Completed   경로 …-> Running -> Completed.
                                                   완료 보고는 워크로드가 돌았다는 뜻이다(계약)
OUTPUT_FINALIZATION_FAILED          -> Failed      규범 표가 Running -> Failed 의 trigger 로 이 이름을 적어 뒀다
FAILED + 종료를 관측했다             -> Failed      Running -> Failed. exit_observation 이 OBSERVED_* 면 돌았다는 증거다
  (exit_observation = OBSERVED_WITH_CODE · OBSERVED_NO_CODE)
FAILED + 관측 없음/정보 없음(v1)     -> Failed      ★ Starting -> Failed 로 적는다(보수적).
                                                   **한계** — 실제로 돌다가 실패한 v1 보고도 기동 실패처럼 보인다.
                                                   실행 실패율을 과소계상한다. 이 한계를 코드 주석과 이 문서에 남긴다
CANCELLED                           -> Cancelled   Created -> Cancelled(JOB_CANCELLED)
INTERRUPTED                         -> 적지 않는다  ★ 규범 Attempt 표에 INTERRUPTED 상태가 **없다**(그건 Job 쪽이다).
                                                   상태를 바꾸지 않고 보고만 저장한다 — 규범에 없는 상태를 만들지 않는다
```

★ 왜 `Starting` 을 거치나 — 규범 표에 `Created -> Completed` 나 `Created -> Failed` 가 없다.
`Created -> Starting` 의 trigger 는 `GRANT_ACCEPTED`(Agent 검증 통과)이고, **보고가 왔다는 것은 Grant 가 수락됐다는 뜻**이다.
이건 합성이 아니라 보고가 증명하는 사실이다.

## 3. 한 변경으로 묶을 것 (코덱스 72 권고 3)

```text
1  저장소 AttemptState 를 규범 정본(protocol)과 **하나로** 합친다 — 두 enum 이 갈라질 여지를 없앤다
2  SQLite 문자열 <-> 상태 codec 을 11개 상태 전부에 만든다(왕복 시험)
3  fetch_attempt 의 'CREATED' 전용 거부를 **모든 알려진 상태의 명시적 파서**로 바꾼다
4  상태 변경은 `transition()` 으로 검증하고 **CAS**(UPDATE … WHERE state = <읽은 값>)로만 쓴다
5  보고 저장 경로에 **보고 outcome <-> Attempt 상태 대조**를 넣는다 — 완료 보고인데 FAILED 인 행 같은 어긋남을 막는다
6  이미 있는 행(보고는 있는데 CREATED 인 Attempt)은 **backfill** 한다 — 새 경로만 고치면 옛 행이 조용히 남는다
```

## 4. 하지 않는 것

- 예약 해제 자체(다음 조각) · 만료 기록(그다음) · 후보 선택 접기 · 데몬 루프
- `Paused` · `Stale` · `Reconciling` · `Canonical` · `Superseded` 로의 실제 전이 — 관측 경로가 아직 없다.
  codec 은 만들되(왕복 가능) **쓰는 곳은 만들지 않는다**
- v1 보고의 기동/실행 구분 — 계약에 정보가 없다. 위 한계로 남긴다

## 5. 완료 기준

```text
· 종료 보고를 저장하면 같은 트랜잭션에서 Attempt 가 종료 상태가 된다(재조회로 확인)
· 규범에 없는 전이는 거부된다(음성 시험)
· 완료 보고 <-> FAILED 같은 어긋남이 거부된다(음성 시험)
· 옛 행 backfill 이 실제로 옛 행을 고친다(시험)
· 뮤테이션 — CAS 나 대조를 빼면 시험이 실패한다
```
