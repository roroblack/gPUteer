# 결정 — "끝을 못 본 작업" 해제를 사람 대신 시스템(대체 통지 + 기계 증거)으로

정한 것: 노드가 "시작했지만 끝을 못 본 작업" 을 가졌을 때 누가 · 어떻게 푸는가
결론: **D** — 사용자 제안(대체 통지)을 채택하고, 부작용 등급으로 재배치 시점을 가른다
합의 방식: **1회차 일치**(Claude · Codex 본계정 gpt-6-sol · Codex 보조 계정 gpt-6-sol — 셋 다 D, 확신 high)

## 설계 요지(세 의견의 공통분모)
1. Coordinator 가 시도를 다른 노드로 넘길 때(대체 · 회수) 옛 시도에 대한 **서명된 통지를 영속**한다(우편함). 지금 RevokeLeaseNotice 는 열린 연결에서만 간다.
2. 옛 노드는 다시 붙으면 **새 작업을 받기 전에** 통지를 처리한다(순서를 강제). 통지 수신만으로 원장 행을 닫지 않는다 —
   스스로 정지(런타임 → 안 되면 단계 4 의 런타임 밖 정지)하고 **기계 증거**(정지 · 부재 확인)가 나올 때만 자동으로 닫고 다시 일한다.
3. 재배치 시점: 서명된 선언이 PURE 면 지금처럼 바로 재배치(통지로 뒤처리). IDEMPOTENT · SIDE_EFFECTING · 모름은 옛 시도의 정지 증거
   (STOP_CONFIRMED)가 올 때까지 보류 → **증거가 오면 자동 해제 · 재배치**(지금은 사람 release-held-job).
4. 사람은 증거를 끝내 못 얻을 때만: 노드가 돌아오지 않음 · 런타임 밖 정지로도 정지를 확인 못 함.

## 전제 · 해야 할 것
- 규범 변경: 단계 1 "소유자가 확인하고 **명시적으로** 해제" → "기계 증거로 자동 해제 가능(증거가 없을 때만 사람)". 계약 v12 에서 검수 b12 ③ 이
  이 이유로 자동 해제를 뺐다 — 이번엔 정책을 바꾸는 것이므로 사용자 결정이 근거다.
- 계약 개정: 영속 통지(우편함) · 수신 확인 · 재처리 규칙 · 재접속 순서. RevokeLeaseNotice 재사용 가능성 검토(새 proto 여부는 필드 검토 뒤).
- 증거 기준을 엄격히: 느슨하면 살아 있는 옛 시도를 해제한다. 단계 4(런타임 밖 정지)가 이 설계의 실질 전제.

## 받아들인 반대 논리
- 검수 b11 ② "부재는 지금 멈췄다의 증거지 안 돌았다의 증거가 아니다" — 셋 다 받아들임. 자동 해제는 "지금 멈췄다" 까지만 보증하고,
  이미 일어난 외부 부작용은 해결됐다고 보지 않는다(부작용 작업의 재개 정책은 따로).

## 진짜 어쩔 수 없는 부분(합의)
- 노드가 끊겨 있는 동안(통지 도착 전)의 PURE 두 벌 실행
- 확인 전에 이미 일어난 외부 부작용 · 공유 저장소 쓰기
- 노드가 영영 돌아오지 않음
- 런타임 밖 정지로도 정지를 확인하지 못함
→ 이 경우만 사람 판단

## 뒤집힐 조건
- PURE 에서도 두 벌을 절대 허용하지 않는다면 → PURE 도 보류(C)
- 노드 접속 없이 옛 시도를 확실히 차단하는 외부 경계가 생기면 → 재배치 전 확인 요건 완화
