## 2. D1 ~ D3 가 막는 것

```text
D1 Lease 만료 뒤 보고를 받는가        단계 4 Coordinator 의 REPORT 처리(만료 검사 유무)
```

★ D3 가 단계 1 에 들어갈 수 있으므로 **D3 가 정해지기 전에는 단계 1 을 커밋하지 않는다** — proto 를 두 번 바꾸면
벡터 재생성 · 검수도 두 번이다. D1 · D2 는 단계 4 라 단계 1~3 과 병행할 수 있다.

## 4. 결정 · 최적안으로 가는 방향 (2026-09-14 16:07)

사용자 지시: D1~D3 은 권장대로 한다. **권장이 최적이면 그대로, 아니면 지금은 권장으로 가되 차후 최적안으로 가는 가닥을 잡는다.**
★ 아래 "최적인가" 판단은 **이 세션의 판단**이다 — 코덱스 확인 전(재검수 52 에 함께 묻는다).

```text
D1 받는다(과거 실행의 보고로 저장만)   최적으로 본다. 완성 조건 — 늦은 보고를 **과거 배정 기록**으로 검증하는 경로
                                     (지금 저장소는 현재 예약 일치를 요구한다). 단계 4 Coordinator 에 넣는다

    최적안: 보고서가 두 축을 **따로** 담는다
      종료 관측    프로그램이 무엇을 했나 — exit code · 종료를 관측했는가

    outcome 하나에 두 축을 합치면 실패 종류마다 값이 늘고(⑲ 다음에 복제 실패 · 정리 실패 …), 받는 쪽은 재시도 ·

    **순수 추가**하고, outcome 은 그 요약으로 남긴다(이번 값은 버리지 않는다 — 번호 재사용 금지)
```
