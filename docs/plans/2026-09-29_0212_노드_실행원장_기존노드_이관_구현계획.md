## 이 조각이 하는 것 — 한 줄

노드에 **실행 원장**(시도마다 시작 · 끝을 적는 SQLite 파일)을 두고, 이미 일을 돌린 노드를 그 원장으로 옮기는 **이관 명령**을 만든다. 중앙(Coordinator)과 주고받는
새 메시지는 **이 조각에 없다** — 원장이 로컬에서 "끝을 확인하지 못한 시도" 를 막는 데까지만 한다.

## 왜 이 순서인가

```text
계약 §5     원장은 "started-attempts 에 기록이 있는데 원장이 없으면 새 작업 거부" 를 요구한다 — 한 번이라도 실행한 노드는 기록이 있다(lib.rs:450 write_once ·
            지우는 경로 없음). 이관 없이 원장을 켜면 **모든 기존 노드가 멈춘다**
계약 호환성  "기존 노드 이관은 이 계약보다 먼저 들어와야 한다"
그래서      원장 + 이관을 한 조각으로, 기본은 **꺼짐**(`--run-ledger` 스위치). 켜기 전 절차: 이관 → 켜기
```

## 범위

```text
한다      (1) 원장 파일 `<루트>.run-ledger.sqlite3` — 열기 · 형식 · 세대 · 전수 대조 · fail-closed
          (2) 실행 순서 1~4(계약 §5): 원장 행 ACTIVE → 시작 기록(sentinel) → 기동 → 종료 보고 보관 뒤 CLOSED
          (3) 기동 때 남은 ACTIVE 행 풀기 — 컨테이너 행 네 갈래 중 알림 꺼짐 갈래(LOCAL_BLOCKED + 사건 표식) · 호스트 행은 CLOSED(지금과 같다)
          (4) 기동 관문 — LOCAL_BLOCKED · 풀지 못한 ACTIVE 가 있으면 새 작업 거부
          (5) `container-incidents --clear` 가 루트 잠금을 잡고, LOCAL_BLOCKED 행을 CLOSED 로 바꾼 **뒤** 표식을 지우고 폴더를 sync(계약 §5 · 단계 3 v7 사실 12)
          (6) 이관 명령 `gputeer run-ledger adopt-legacy -- <agent 인자>`
안 한다    AttemptRunNotice · ACK(FrameType 19 · 20) · OPEN · STOP_PENDING · ACKED 상태 · `--send-run-notice` · Coordinator 쪽 전부 — 다음 조각
          D5 호스트 경로 차단(단계 1 목록 15) — 별도 조각. 호스트 행은 정상 수명주기만
          운영 활성화 — 배포 파일(유닛 · agent.ps1)은 이 조각에서 **켜지 않는다**
```

## 원장 형식

```text
파일       <실경로 루트>.run-ledger.sqlite3 · 루트 잠금을 잡은 뒤에만 연다 · PRAGMA journal_mode=WAL 아님(DELETE) · synchronous=FULL · 열 때 integrity_check
meta       format_version(1) · generation(128비트 난수 hex) · created_at_unix_ms
           ★ 세대 짝: `<루트>.started-attempts/.run-ledger-generation` 파일(write_once)에 같은 generation 을 둔다. 원장을 새로 만들면(지웠다 · 잃었다) 짝이 안 맞아 거부
attempts   attempt_id(PK) · job_id · node_id · fence_epoch · executor('container'|'host'|'legacy') · runtime_program · runtime_kind · container_name ·
           container_id(확인한 뒤) · cgroup_path · state('ACTIVE'|'CLOSED'|'LOCAL_BLOCKED') · reason · stopped · logs_complete · container_left ·
           created_at_unix_ms · updated_at_unix_ms
           legacy 행: attempt_id 만 믿을 수 있다(시작 기록에는 `attempt_id=` 한 줄뿐 — lib.rs:462). 나머지 칸은 NULL · executor='legacy' · state='CLOSED'
전이       ACTIVE → CLOSED · ACTIVE → LOCAL_BLOCKED · LOCAL_BLOCKED → CLOSED(해제 명령만). 그 밖은 코드가 거부(시험)
```

## 열기 · fail-closed (계약 §5 "원장 자체")

`--run-ledger true` 일 때, 루트 잠금 · 실경로 정착(settle_checkpoint_root_with · lib.rs:3402) **직후**, 첫 Grant 전에:

| 상황 | 결과 |
|---|---|
| 원장 없음 · started-attempts 비었거나 없음 | 새로 만든다 · 세대 짝 파일을 쓴다 |
| 원장 없음 · started-attempts 에 기록 있음 | **거부** — "이관 명령을 먼저" 안내 |
| 원장 있음 · 세대 짝 파일 없음 · 또는 값이 다름 | 거부 |
| 열지 못함 · integrity_check 실패 · format_version 모름 | 거부 |
| started-attempts 의 시도 중 원장에 행이 없는 것 | 거부(논리적 누락 — 계약 b3 ⑦) |

거부는 지금의 기동 거부와 같은 모양(오류로 끝남 · 루프는 다음 회차에 다시 시도)이다. 스위치가 꺼져 있으면 원장을 열지도 만들지도 않는다 — **지금 동작 그대로**.

## 실행 순서 (계약 §5 "실행 순서")

```text
1 원장 행 ACTIVE(트랜잭션)          실패 → 띄우지 않는다
2 started-attempts sentinel        지금 코드(record_attempt_started_here · lib.rs:450 · :1491). 실패 → 띄우지 않는다 · 원장 행을 CLOSED(reason=not_started)
3 기동(create · start 또는 호스트 spawn)
4 종료 관측 → 종료 보고를 보관(persist_report_to_outbox · lib.rs:2525 — rename 뒤 sync_dir)한 **뒤** 원장 CLOSED
  보관함이 없는 구성(--report-over-session 꺼짐)은 보고를 보낸 **뒤** CLOSED — 그 구성은 기동 때 "보고 없음" 갈래로 간다(계약 그대로)
  컨테이너가 남아 사람에게 넘겼으면(needs_human · 사건 표식) 행은 LOCAL_BLOCKED(표식과 같이 풀린다)
```

## 기동 때 ACTIVE 행 풀기 (알림 꺼짐 — 계약 b14 ②)

| 행 | sentinel | 보고 보관함에 그 시도의 종료 보고 | 결과 |
|---|---|---|---|
| 컨테이너 | 없음 | — | CLOSED(시작 안 함 — sentinel 쓰기는 write_once 로 전원 차단을 넘는다) |
| 컨테이너 | 있음 | 있음 | CLOSED(보고가 다시 간다) |
| 컨테이너 | 있음 | 없음 | (1) 원장 트랜잭션 ACTIVE → LOCAL_BLOCKED (2) 그 뒤 사건 표식(write_incident) — 새 작업 거부 |
| 호스트 | 무엇이든 | 무엇이든 | CLOSED(지금과 같다 — D5 조각 전 · "보장하지 않는 것") |

★ 풀기는 지금의 "남은 컨테이너 정리"(lib.rs:656 부근)보다 **먼저** 한다 — 정리가 사람에게 넘길 컨테이너를 지우지 않게(지금 사건 관문과 같은 이유).

## 해제 — `container-incidents --clear` (계약 §5 · 단계 3 v7)

```text
지금        clear_incidents(container.rs:1531)는 루트 잠금을 잡지 않고, 지운 뒤 폴더 sync 를 하지 않는다
바꾼다      (1) 루트 잠금(실패하면 "Agent 가 떠 있다 — 멈춘 뒤" 안내) (2) 원장이 있으면 그 컨테이너 이름의 LOCAL_BLOCKED 행을 CLOSED(트랜잭션 먼저)
            (3) 표식 삭제 (4) sync_dir. 어느 단계에서 끊겨도 같은 명령을 다시 돌리면 풀린다 — CLOSED 행의 남은 표식은 지워도 되는 것으로 본다
원장 없음    지금처럼 표식만(스위치를 안 켠 노드)
```

## 이관 명령 — `gputeer run-ledger adopt-legacy -- <agent 인자>` (계약 §5 요구 넷)

```text
입력        agent-stub 과 **같은 인자**를 `--` 뒤에 받아 같은 파서(parse_config_from_args)로 읽는다 — 루트 · 런타임 · 노드 id 가 Agent 와 어긋나지 않게
순서        (1) 루트 잠금 · 실경로 정착(Agent 와 같은 함수) — 잠금 실패 = Agent 가 떠 있다 → 거부 ("멈춘 상태에서 명시적으로")
            (2) 원장이 이미 있으면 거부(두 번 이관하지 않는다)
            (3) 열린 사건 표식이 있으면 거부
            (4) 런타임이 설정돼 있으면 **실제 owner 라벨**(lib.rs:650 과 같은 파생 — 잠근 실경로 해시)로 남은 컨테이너를 **조회만** — 하나라도 있으면 거부.
                조회 실패도 거부(빈 라벨 · 실패로 "0개" 를 얻지 않는다)
            (5) started-attempts 의 시도마다 legacy 행(CLOSED) · 세대 짝 파일 · 원장 파일을 만든다 — 원장은 임시 이름에 다 쓴 뒤 이름을 바꾸고 폴더 sync
                (중간에 끊기면 원장 없음 = 다시 돌리면 처음부터)
            (6) 몇 개를 옮겼는지 · 원장 경로를 출력
안 한다      정리 · 삭제 · GC · Coordinator 연락
한계        이관 전 시도가 "돌고 끝났다" 는 근거는 이관 시점의 부재뿐이다 — 지금 동작보다 나빠지지 않지만 그 시도들의 불명은 복원하지 않는다(계약 그대로)
```

## 시험 (negative test — `RULE.md` §6)

```text
원장 열기     R1 스위치 꺼짐 → 원장 파일이 안 생긴다 · 동작 그대로(기존 시험 전부 통과)
             R2 새 노드 → 원장 · 세대 짝 생성  R3 기록 있는데 원장 없음 → 거부 · 안내 문구  R4 세대 짝 없음 · 다름 → 거부
             R5 손상 파일(무작위 바이트) · 모르는 format_version → 거부  R6 기록 중 행 없는 시도 하나 → 거부
실행 순서     R7 정상 완료 → ACTIVE → CLOSED · 보고 보관 뒤에만 CLOSED(보관 실패를 주입하면 ACTIVE 로 남음)
             R8 원장 쓰기 실패 주입 → 띄우지 않음  R9 sentinel 쓰기 실패 → 띄우지 않음 · 행 CLOSED(not_started)
기동 풀기     R10 ACTIVE + sentinel 없음 → CLOSED  R11 ACTIVE + sentinel + 보관 보고 → CLOSED  R12 ACTIVE + sentinel + 보고 없음(컨테이너) → LOCAL_BLOCKED +
             사건 표식 + 새 작업 거부  R13 호스트 ACTIVE → CLOSED  R14 LOCAL_BLOCKED 가 있는 채 재기동 → 거부 유지
             R15 풀기가 남은 컨테이너 정리보다 먼저(가짜 런타임 — 정리가 그 컨테이너를 지우지 않음)
해제         R16 루트 잠금 중 --clear → 거부 · 안내  R17 해제 → 행 CLOSED · 표식 삭제 · 다음 기동 통과  R18 행만 CLOSED 되고 표식 남음 · 표식만 지워지고 행 남음 → 다시 돌리면 풀림
이관         R19 Agent 가 떠 있을 때(잠금) → 거부  R20 원장 이미 있음 → 거부  R21 열린 사건 → 거부  R22 남은 컨테이너 있음(가짜 런타임 · 실제 owner 라벨) → 거부 ·
             **빈 라벨로 조회하지 않음**(가짜 런타임이 받은 인자 확인)  R23 런타임 조회 실패 → 거부  R24 정상 → legacy 행 수 = 기록 수 · 그 뒤 Agent 가 원장을 켜고 기동 통과
             R25 이관 중 끊김(임시 원장만 남음) → 원장 없음으로 보고 다시 돌리면 성공
전이         R26 CLOSED → ACTIVE 등 표에 없는 전이 → 코드가 거부
플랫폼        Windows(개발 기계) · 리눅스(CI · 비-root)에서 같은 시험. 권한 조건을 같이 적는다(CLAUDE.md §4)
```
