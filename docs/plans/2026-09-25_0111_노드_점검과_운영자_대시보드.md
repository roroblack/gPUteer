## 왜

노드를 붙이는 사람은 키 · 폴더 · Coordinator 연결 · 공유 저장소 · 패널 포트 · GPU · 컨테이너 런타임을 전부 맞춰야 하는데,
어긋나면 Agent 가 **돌기 시작한 뒤에** 제각각의 오류로 멈췄다. 운영자는 풀 상태를 `gputeer status` 텍스트 한 번으로만 봤다.

## 범위

### In

- `gputeer node-doctor` — Agent 를 띄우기 전 시작 조건 점검(OK · WARN · FAIL, FAIL 이 있으면 종료 코드 1). 아무것도 바꾸지 않는다
  (★ 재검수 89 — 처음 구현은 폴더를 만들고 같은 이름 파일을 덮을 수 있었다 · 결함 282. 고친 뒤: 만들지 않고, 확인용 파일은 배타 생성)
- `gputeer dashboard` — 127.0.0.1 전용 · 읽기 전용 웹 화면(`/` 표 · `/api/status` JSON). `status_report` 를 구조(`pool_status`)와
  텍스트로 나눠 두 곳이 같은 값을 쓴다
- 서비스 틀(systemd · PowerShell)에 선택 컨테이너 런타임 값

### Out

- 대시보드에서 무언가를 **바꾸는** 버튼(Job 취소 · 노드 해제) — 쓰기는 CLI 와 런북 절차에 둔다. 원격 공개도 하지 않는다
- 노드 설치 자체(패키지 · NVIDIA Container Toolkit 설치) — 점검은 "보이는가" 까지다
- 노드 쪽 SSH · 대화형 작업 환경 — 이 시스템의 작업은 배치 실행이다(별도 결정 필요)
