# 레거시 `--lease-db` 경로 명시적 opt-in 계획

## 목적

`--lease-db`를 생략하면 Coordinator가 의도적으로 레거시 호환 경로를
사용한다. 이 경로에는 저장소 기반 identity/revoked/만료 검사,
`max_total_duration_seconds`의 실제 경과시간 판정, 재시작 후 상태 복원이
없다. 운영자가 옵션을 빠뜨려도 이 위험한 경로가 조용히 시작되는 문제를
막기 위해 명시적 opt-in을 요구한다.

## 범위

- `CoordinatorConfig`에 레거시 모드 허용 bool을 추가한다. 기본값은 `false`다.
- `lease_db_path == None`이고 허용 bool이 `false`이면 Coordinator `run()`의
  TCP bind 전에 오류를 반환한다.
- 오류에는 레거시 모드에 revoke, 만료, max-duration 보호가 없다는 사실과
  opt-in 플래그 사용법을 포함한다.
- 허용 bool이 `true`이면 기존 레거시 동작을 그대로 수행하되 시작 경고를
  한 번 stderr에 출력한다.
- selftest의 legacy handshake 시나리오에는 opt-in을 자동으로 추가하고,
  opt-in 없는 시작 거부 negative scenario를 추가한다.
- proto, lease 저장소 정책, 레거시 핸드셰이크의 서명/replay/epoch/반복
  갱신 동작은 변경하지 않는다.

## 정책 대안 비교

설계 조사에서 검토한 선택지는 다음 세 가지다.

1. 기존처럼 묵시적으로 legacy 경로를 허용한다. 호환성은 가장 높지만,
   운영자가 `--lease-db`를 빠뜨릴 때 보호 기능이 조용히 사라진다.
2. `--lease-db`를 항상 요구해 legacy 경로를 제거한다. 안전성은 높지만,
   서명·replay·epoch·반복 갱신의 레거시 계약을 검증하는 기존 selftest와
   호환 사용자를 깨뜨린다.
3. legacy 경로는 보존하되 위험 수락 플래그를 명시적으로 요구한다.
   (선택) 정상 운영은 durable store를 사용하게 만들고, 기존 계약을
   검증하는 테스트와 의도적인 호환 사용은 opt-in으로 계속 유지한다.

3번을 선택한다. 이번 조각의 목표는 legacy 기능을 제거하는 것이 아니라
실수에 의한 조용한 downgrade를 시작 시점에 드러내는 것이다. 따라서
기본값 false, `--i-understand-legacy-mode-is-unsafe true` opt-in, 시작 경고의
조합이 범위와 호환성에 가장 맞다.

## 검증 방법

- `cargo fmt --all -- --check`
- `cargo build --workspace --exclude gputeer-runtime-windows`
- `cargo test --workspace --exclude gputeer-runtime-windows`
- `coordinator-agent-selftest`를 각 90초 하드 타임아웃으로 5회 연속 실행
- selftest 신규 negative scenario가 `--lease-db`와 opt-in 없이 Coordinator를
  spawn했을 때 bind/accept 전에 non-zero로 끝나는지 확인
- opt-in 검사만 임시 제거한 mutation 실행에서 negative scenario가 실패하는지
  확인한 뒤 검사 원복 후 재실행
- `python scripts/verify_evidence.py`

검증 중에는 `docs/evidence/DoD-NN_*.md`, `CLAUDE.md`,
`docs/history/HISTORY.md`를 수정하지 않는다.
