## 왜

작업을 내려면 지금은 명령줄 셋을 차례로 친다 — 제출자가 `gputeer submit`(플래그 20여 개), 운영자가 `import-manifest` · `plan-job`.
팀원이 쓰려면 **화면에서** 내고 올릴 수 있어야 한다.

## 결정 — 화면은 얇게, 판정은 이미 있는 명령이 한다

```text
제출자 화면   gputeer submit-ui   제출자 기계의 127.0.0.1. 폼 → `submit` 과 **같은 함수**로 서명 Manifest 를 만들어 파일로 남기고 내려받게 한다
                                  서명 시드는 시작할 때 파일로만 받는다 — 브라우저로 가지 않는다
운영자 화면   gputeer dashboard   전처럼 읽기 전용이 기본. `--allow-import true` 를 켜면 Manifest 파일을 올려 `import-manifest` · `plan-job` 과
                                  **같은 함수**로 반입 · 계획까지 한다(제출자 keyring 검증 그대로)
```

- 네트워크로 제출을 받는 새 경로(Job ingress)는 만들지 않는다 — 제출자가 파일을 운영자에게 건네는 지금 모양을 화면으로 옮길 뿐이다
- 둘 다 127.0.0.1 전용 · Host 가 loopback 이 아니면 거부 · 쓰는 요청(POST)은 시작할 때 만든 무작위 토큰 헤더가 있어야 받는다(다른 사이트의
  페이지가 브라우저로 보내는 요청을 막는다 — Owner Panel 과 같은 방식) · 요청 머리 · 몸 전체 시한과 크기 한도

## 범위

### In
- 공용 로컬 HTTP 조각(`local_http`) — 요청 전체 시한 · 머리 16KiB · 몸 한도 · Host 검사 · 응답 머리(캐시 · 프레임 · CSP)
- `gputeer submit-ui` · 대시보드 반입 동작 · 런북 §6 · §7
- 시험: 제출 → 파일 → 대시보드 반입 → Job QUEUED(실제 control DB) · 토큰 없음 · 잘못된 Host · 반입 꺼짐 · 잘못된 입력 거부

### Out
- 작업 취소 · 노드 해제 버튼(쓰기 조치는 이번에는 "반입" 하나) · 원격 공개 · 로그인
- 시험 자동화된 브라우저 조작(화면은 앱 내장 브라우저로 한 번 본다)
