## 문제

지금 소유자 정지는 `ContainerStopper::stop` → 런타임 CLI `kill`(시한 15초) → 새 조회로 멈춤 확인이다(`crates/agent/src/container.rs`). 런타임(데몬 ·
podman 잠금)이 멈추면 kill 도 조회도 시한을 넘기고, 소유자는 "멈추지 못했다" 만 본다. 컨테이너는 GPU 를 쥔 채 계속 돈다.

## 무엇을 구분해야 하나 — "GPU 를 비운다" 와 "정지를 증명한다" 는 다르다

```text
로컬 정지(§0.1)   소유자의 GPU · 메모리를 지금 비운다. 증거가 필요 없다 — 소유자 기계에서 소유자가 누른다
정지 증거(단계 1 MUST 3 · 단계 2 §4)
                 Coordinator 에 STOP_CONFIRMED 를 보내려면 "그 시도가 다시 돌 수 없다" 가 필요하다. 특히 불명 조건 (b)(종결되지 않은 기동 요청)는
                 프로세스를 죽여도 풀리지 않는다 — 멈춘 런타임에 쌓인 start 가 **나중에** 적용될 수 있다. 지금 증거는 "컨테이너를 지우고 새 조회가
                 '없음'" 뿐이다(CONTAINER_ABSENT_CONFIRMED)
```

★ 그래서 이 설계의 목표는 **로컬 정지**다. 런타임을 거치지 않고 프로세스를 끝내도 그것만으로 STOP_CONFIRMED 를 만들지 **않는다.** 새 증거 종류(예
cgroup 이 비었다)를 단계 2 계약에 더하는 것은 조건 (a)(종료 미관측 · 기동 요청은 종결)에서만 뜻이 있고, 그것도 별도 결정(S3)이다.

## 플랫폼별 — 누가 그 프로세스를 끝낼 수 있나 (전부 예상 · 재지 않았다)

| 구성 | 컨테이너 프로세스의 주인 | Agent(소유자 계정)가 런타임 없이 끝낼 수 있나 | 수단(예상) |
|---|---|---|---|
| **리눅스 · rootless podman**(런북 권장) | Agent 와 같은 계정(사용자 네임스페이스 — `--userns=keep-id`) | **예(예상)** | 기동 때 컨테이너 init PID 와 cgroup 경로를 원장에 적어 두고(단계 2 원장의 "cgroup 경로" 칸), 정지 때 cgroup v2 `cgroup.kill`(커널 5.14+)에 1 을 쓴다 — 그 cgroup 의 모든 프로세스가 끝난다. `cgroup.procs` 가 비었는지로 **로컬** 확인. cgroup 이 그 계정에 위임되지 않은 구성(cgroupfs 관리자 · systemd 사용자 세션 없음)이면 PID 로 `pidfd_send_signal`(PID 재사용 경쟁을 피한다) |
| **리눅스 · rootful docker** | root | **아니오** | Agent 계정이 root 프로세스에 신호를 못 보낸다. docker 그룹은 곧 root 지만 그 길은 멈춘 데몬 소켓이다. 정직하게 "런타임 없이는 못 멈춘다 — rootless podman 을 쓴다" 로 보인다 |
| **Windows · Docker Desktop(WSL2 백엔드)** | `docker-desktop` WSL 배포판 안의 root | **컨테이너 하나만은 아니오** | 마지막 수단: 엔진 VM 전체 종료(`wsl --terminate docker-desktop` — 예상, 배포판 이름은 판마다 확인). ★ **소유자의 다른 컨테이너도 전부 멈춘다** — 소유자가 경고를 보고 누르는 별도 버튼이어야 한다 |
| **Windows 호스트 · WSL 배포판 안 docker**(x600 구성) | 그 배포판의 root | **예일 수 있다(예상)** | `wsl -d <배포판> -u root -- …` 는 기본 설정에서 암호 없이 root 로 돈다 — 그 배포판에서 cgroup.kill · PID kill 이 가능하다. ★ root 사용이다 — 소유자 버튼에서만 · 그 배포판의 다른 것에 닿지 않게 cgroup 경로로 좁힌다 |
| **Windows · podman machine** | 머신 VM 안 | 컨테이너 하나만은 아니오 | 마지막 수단 `podman machine stop`(예상 — 이것도 podman 이다. 머신 CLI 가 멈추면 Hyper-V/WSL 쪽 종료) |

★ 재시작 정책은 두지 않는다(`create_args` 에 `--restart` 없음 — 런타임 기본값 "재시작 안 함"). 그래서 로컬로 끝낸 컨테이너를 런타임이 다시 띄우지는 않는다(예상).
멈춘 런타임에 **쌓인 start** 는 다르다 — 위 "정지 증거" 절.

## 제안

```text
1 기동 때 적는다     create · start 뒤 컨테이너 init PID · cgroup 경로 · (Linux) cgroup 관리자 종류를 원장(단계 2)에 — 런타임이 나중에 멈춰도 찾을 수 있게.
                    단계 2 가 승인 전이면 사건 표식 옆 파일에 같은 것을 적는다(형식은 원장 칸과 같게)
2 정지 순서         (i) 런타임 kill(지금과 같다 · 시한) → (ii) 시한을 넘기면 플랫폼별 로컬 정지(위 표) → (iii) 로컬 확인(cgroup.procs 비었다 · PID 없음)
                    → 소유자 화면에 "로컬로 멈췄다 · 런타임은 아직 모른다 · 사건으로 남긴다" 를 보인다
3 증거로 쓰지 않는다  로컬 정지는 STOP_CONFIRMED 가 아니다. 사건 표식은 남고(원장 OPEN), 런타임이 살아나 컨테이너를 지우고 "없음" 을 확인한 뒤에야 해제 명령이
                    STOP_CONFIRMED 를 만든다(단계 2 §4 그대로)
4 못 하는 구성       rootful docker · Docker Desktop(엔진 전체 종료 전) — "런타임 없이는 못 멈춘다" 를 그대로 보인다. 성공이라 하지 않는다
```

## 시험 · 실측 (negative test — `RULE.md` §6)

```text
T1 (가짜 런타임) kill 이 시한을 넘기면 로컬 정지로 넘어간다 · 로컬 정지를 성공으로 보고해도 STOP_CONFIRMED 는 만들지 않는다 · 사건 표식은 남는다
T2 (가짜 런타임) 로컬 정지 수단이 없는 구성 — "못 멈춘다" 를 보이고 성공이라 하지 않는다
M1 (x600 WSL · rootless podman) 데몬 · 잠금을 멈춘 상태(SIGSTOP 등)에서 cgroup.kill 로 GPU 를 비우는지 — nvidia-smi 로 프로세스가 사라지는지
M2 (x600 WSL · docker) `wsl -u root` 경로가 되는지 · 다른 컨테이너에 닿지 않는지 — 사용자의 기존 컨테이너가 있는 기계라 **gputeer- 접두어 것만** 대상으로
M3 (리눅스 비-root) cgroup 위임이 없는 구성에서 pidfd 경로
```

★ M1~M3 은 x600 에서 해야 하고, 사용자 허가(E: 만 · 사용자 컨테이너 불가침)의 범위를 넘지 않게 **gputeer- 접두어 컨테이너만** 다룬다. 실측 전에는
위 표의 "예" 를 전부 "예상" 으로 둔다.
