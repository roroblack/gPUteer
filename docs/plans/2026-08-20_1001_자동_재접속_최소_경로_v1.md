# 자동 재접속 최소 경로 v1

## 범위

2026-08-20 조사 결론의 하루 조각을 구현한다. 같은 Agent 프로세스가 TCP 연결을 잃었을 때 새 proto 메시지 없이 기존 Grant/Lease 검증과 Grant/ACK handshake를 처음부터 다시 수행한다.

- Agent: 연결 바깥의 fence watermark/replay 관련 상태를 유지하고, 연결 시도별 bounded retry, exponential backoff + full jitter, connect timeout, lease-aware deadline을 적용한다.
- Coordinator: `--max-connections`와 `--accept-timeout-ms`를 사용해 순차 accept loop를 구성하고, `--drop-connection-after-ack-once`로 첫 연결만 재접속 테스트용으로 끊는다.
- nonce: attempt 0은 기존 값을 보존하고, attempt가 증가하면 Grant/ACK/Renew nonce에 connection attempt를 포함한다.
- selftest: 기존 1–48을 유지하고 같은 Agent/Coordinator 프로세스의 신규 49–52를 검증한다.

`CoordinatorLeaseStore::get_or_issue()`는 수정하지 않았다. 재접속에서 같은 Lease를 돌려받기 위해 grant/identity 설정을 케이스 동안 고정한다. Renew 요청을 보낸 뒤 결과 전에 끊기는 경우는 durable request ledger가 범위 밖이므로 `AmbiguousRenew`로 종료한다.

## 전체 설계와의 관계

전체 자동 재접속 루프 7조각 로드맵 중 연결 오류 분류, bounded retry, 기존 handshake 재수행, Coordinator 반복 accept, nonce 분리, same-process selftest만 구현한 축소판이다. `AgentSessionHello`/`ResumeLeaseRequest`/`ResumeLeaseResult`, durable request ledger, 다중 Agent 경쟁, async runtime은 구현하지 않는다.

## 검증

- `cargo build --workspace --exclude gputeer-runtime-windows`
- `cargo test --workspace --exclude gputeer-runtime-windows`
- `coordinator-agent-selftest` 전체 52개를 각 케이스 hard timeout 120초, Coordinator accept timeout 5000ms로 실행한다.
- 기존 1–48의 결과와 신규 49 정상 재접속, 50 retry 소진, 51 revoke 중 재접속, 52 expiry 중 재접속을 확인한다.
- bounded retry를 제거한 mutation과 `max-connections` 강제를 제거한 mutation을 각각 짧은 timeout으로 실행한 뒤 원복하고 재검증한다.
