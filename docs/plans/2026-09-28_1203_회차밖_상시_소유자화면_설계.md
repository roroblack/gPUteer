## 불변식

```text
I1  루프 기동 순서: 인자 파싱 → 루트 잠금 · 실경로 → 패널 bind · 서비스 시작 → 되찾기 확인 → 기동 GC → (그 뒤에만) 자식.
    기동 GC 가 실패 · 지연하면 루프는 끝나지 않고 StartupFault 상태로 패널에 보이며 자식을 띄우지 않는다
I2  루프가 체크포인트 루트의 OS 잠금을 수명 전체 쥔다. 자식은 재잠금하지 않는다
I3  패널 생략은 내부 진입점 `agent-stub --loop-child` 하나뿐 — 아래 "부모 확인" 을 통과해야 한다. 단독 agent-stub 은 지금처럼 패널이 필수다
I4  제어 파이프 · round Job 핸들은 비신뢰 워크로드에 상속되지 않는다
I5  되찾기 · 회차 시작 · **작업 시작 허가** · 다시 켜기는 루프 잠금 아래 한 상태기계에서만 바뀐다(c1e ③)
I6  지금 시도의 정지는 디스크 · 큐 · 다른 정지를 기다리지 않는다 — 자식이 죽은 뒤의 정지도(c1e ④)
I7  루프가 회차의 작업을 끝낼 수단을 자식과 따로 쥔다. ★ **범위: 회차 울타리(리눅스 round cgroup · Windows round Job · 컨테이너)를 벗어나지 않은 작업.**
    같은 계정으로 도는 호스트 작업(S0 · RESTRICTED)은 작정하면 울타리를 벗어날 수 있다 — 리눅스는 상위 cgroup.procs 에 자기를 쓰고(지금 시험이 그 탈출을
    확인한다), Windows 는 같은 계정의 다른 경로(작업 스케줄러 · WMI 등)로 Job 밖에 프로세스를 만들 수 있다(예상). 그런 프로세스는 루프가 **보지 못한다** —
    정지 결과는 "울타리 안은 끝냈다 · 울타리 밖은 모른다"(아래 결과 표의 unknown)이고 성공이라 하지 않는다(§0.4 · c1e ②).
    컨테이너 작업은 호스트 cgroup 에 접근할 수 없어 이 탈출이 없다(예상 — 컨테이너 탈출이 없다는 전제). 탈출 방지(별도 계정 · cgroup namespace)는 이 설계 범위 밖
```

## 루프의 상태기계

```text
상태   Idle · Starting(자식 띄움 · GO 전) · RoundActive(GO 뒤 · 작업 준비 전 — Coordinator 인사 · Grant 검증 · ACK) ·
       Running(시작 허가 뒤) · StopPending · Reclaimed · StartupFault
       ★ "준비됨(Prepared)" 은 루프에 머무는 상태가 아니다 — WORKLOAD_PREPARED 를 받는 순간 잠금 안에서 허가 · 버림을 정한다(아래 시작 관문).
         자식 쪽에서는 PREPARED 를 보낸 뒤 허가를 기다리는 동안이 준비됨이다
```

| 지금 상태 | 사건 | 다음 상태 · 한 일 |
|---|---|---|
| Idle | 회차 시간 · 표식 없음 | Starting — round_id · 스냅샷 · 회차 울타리 준비 → 자식 |
| Starting | READY(digest 일치) · 표식 없음 | RoundActive — GO |
| Starting | REFUSED · EOF · 불일치 | Idle(울타리 정리 · 스냅샷 삭제) |
| RoundActive | WORKLOAD_PREPARED | **루프 잠금 아래** 되찾기 여부를 다시 보고: 아니면 Running 으로 바꾼 **뒤** START_WORKLOAD · 되찾기면 DISCARD_PREPARED → Reclaimed |
| RoundActive | WORKLOAD_NOT_STARTED(일 없음 · 거부) · EOF | Idle(울타리 정리) |
| Running | WORKLOAD_ENDED | Idle(울타리 정리 — 결과 줄은 "마지막 회차") |
| Running | EOF(자식 사망 · 결과 없음) | 감독 우선 경로로 울타리 안 작업을 끝낸다(아래) → Idle · 결과 unknown · 사건 기록 |
| 모든 상태 | **reclaim**(패널) | 아래 "되찾기" |
| StopPending | STOP_RESULT | Reclaimed(결과 보관) |
| StopPending | WORKLOAD_ENDED(STOP_RESULT 전) | 결과를 자식 판정 규칙으로 — 대개 already_exited · Reclaimed |
| StopPending | EOF | 감독 우선 경로로 끝냄 → Reclaimed · unknown |
| Reclaimed | resume(패널) | Idle — 표식 삭제 |
| StartupFault | 운영자가 원인 해결 뒤 패널 "다시 시도" | 기동 GC 재시도 → Idle 또는 StartupFault |

### 시작 관문 — 작업을 띄울지는 루프가 정한다 (c1e ③)

두 프로세스가 같은 잠금으로 "취소 확인 → 띄우기" 를 원자화할 수 없다. 그래서 자식은 작업을 **실행할 수 없는 상태로 준비만** 하고, 실제 시작은 루프의 허가를 받는다.

```text
준비(자식)     Windows   지금 경로 그대로 — CREATE_SUSPENDED · Job 편입 · 손잡이 준비. 재개하지 않는다
              리눅스     spawn 하되 pre_exec 안에서(cgroup 편입 뒤) 시작 관문 fd 를 읽고 막힌다. 바이트 1 을 받으면 exec · EOF 면 곧바로 _exit(127).
                        관문 fd 는 CLOEXEC 라 작업 자체에는 남지 않는다
              컨테이너   create 까지만(라벨에 round_id) — start 하지 않는다
              → WORKLOAD_PREPARED{round_id, attempt_id, job_id, submitter_device_id, entrypoint, container_name?} 를 보낸다
결정(루프)     잠금 아래: 되찾기가 없으면 상태를 Running 으로 **먼저** 바꾸고 START_WORKLOAD 를 보낸다. 되찾기면 DISCARD_PREPARED.
              ★ 이 순간 이후의 되찾기는 전부 STOP 경로다 — "허가를 보낸 뒤 되찾기" 와 "되찾기 뒤 허가" 가 루프 잠금 하나로 갈린다
시작(자식)     START_WORKLOAD → Windows 재개 · 리눅스 관문에 1 · 컨테이너 start → WORKLOAD_STARTED
버리기(자식)   DISCARD_PREPARED → Windows TerminateProcess(일시정지된 것) · 리눅스 관문을 닫음(EOF → _exit) · 컨테이너 rm → WORKLOAD_NOT_STARTED(소유자 되찾기)
자식 사망      준비된 것은: Windows 는 round Job 에 있어 루프가 끝낸다 · 리눅스는 관문 쓰기 끝이 닫혀 EOF → _exit · 컨테이너는 created 로 남아 round_id 라벨로 찾아 지운다
Coordinator   ACK 는 지금처럼 실행 전에 간다. 되찾기로 버리면 그 시도는 "시작 안 함(소유자 되찾기)" 로 보고한다 — 보고 방식은 단계 2 계약을 따른다
대가           한 번의 파이프 왕복(밀리초 단위 — 예상)
```

### 되찾기 — 어느 상태에서든, 정지가 먼저

```text
순서       ① 메모리 상태를 Reclaimed(또는 StopPending)로 **먼저** 바꾼다(루프 잠금 아래 — 이 순간부터 새 회차 · GO · START_WORKLOAD 없음)
           ② 지금 시도가 있으면 곧바로 정지를 보낸다(우선 경로)
           ③ 표식을 영속으로 쓴다. 실패해도 ①② 는 되돌리지 않는다 — 응답 · 상태에 reclaim_durable=false 를 보이고 30초마다 다시 쓴다.
              ★ 표식이 없는 채 루프가 죽으면 다음 루프는 되찾기를 모른다 — 화면에 적는다("되찾기가 디스크에 기록되지 않았다 — 다시 시도 중")
상태별     Idle → Reclaimed · Starting → STOP_BEFORE_GO · Reclaimed · RoundActive → CANCEL_ROUND · Reclaimed(자식은 다음 준비 전에 멈춘다 ·
           이미 PREPARED 를 보냈으면 루프가 그것을 받는 대로 DISCARD_PREPARED) ·
           Running → 우선 정지 · StopPending · StopPending · Reclaimed → 그대로(같은 접수 번호) · StartupFault → Reclaimed(자식이 없다)
```

### 우선 정지 경로 — 자식이 살아 있을 때 · 죽은 뒤 모두 (c1e ④)

```text
자식 생존   지금 시도의 STOP 을 제어 파이프에 즉시 쓴다 · 같은 시도는 같은 접수 번호(single-flight)
자식 사망   **감독 우선 경로** — 남은 컨테이너 정지 큐(동시 2 · 대기 8)와 작업자 · 허가 수를 공유하지 않는 전용 작업자 하나:
            리눅스 round cgroup kill · Windows round Job 종료 · 컨테이너는 `gputeer.round=<round_id>` 라벨로 조회해 kill → 확인
            ★ 런타임 CLI 자체가 멈추면 이 경로의 컨테이너 부분도 결과가 unknown 이다 — 런타임을 거치지 않는 정지는 단계 4
큐 포화 · 표식 실패 · 조회 지연 어느 것도 이 경로를 막지 않는다
```

### 회차 울타리 — 만들기 · 끝내기 · 치우기 (c1e ① ⑥)

```text
리눅스   루프가 회차마다 `<위임 부모>/gputeer-round-<round_id>` 를 만든다. **자식(agent-stub)은 그 밖에 둔다** — round 는 프로세스를 직접 담지 않고
         작업 cgroup 만 담는다(내부 프로세스 금지 규칙 — 그래야 memory 를 하위에 위임할 수 있다). 자식은 작업 cgroup 을 그 안에 만든다.
         ★ 자식이 받는 round 경로의 검사 — "깊이 2 허용" 으로 넓히지 않는다. 받아들이는 것은 정확히:
           canonical(round 경로)의 부모 == 루프가 잠근 canonical 위임 부모(스냅샷에 적힘) · 이름 == `gputeer-round-<round_id>` · round_id 가 INIT 메시지의 것과 같음 ·
           경로는 **제어 채널**(INIT)로만 받는다(argv 아님). 다른 round · 임의 깊이 2 · 심볼릭 링크 교체 → 거부
         끝내기: round 의 cgroup.kill(하위 전체)
         치우기: round 의 `cgroup.events` 가 `populated 0` 이 된 것을 확인 → 알려진 작업 cgroup 을 아래에서부터 rmdir → 마지막에 round rmdir.
         (round 의 cgroup.procs 는 처음부터 비어 있다 — 그것으로 판정하지 않는다.) 확인 실패 · 시한 초과면 지우지 않고 사건
Windows  루프가 회차마다 round Job(KILL_ON_JOB_CLOSE)을 만들어 자식을 넣는다(CREATE_SUSPENDED → 편입 → 재개). **round Job 핸들은 루프만 쥔다 —
         상속되지 않는 핸들이고 자식에게 복제해 주지 않는다**(자식이 쥐면 루프가 죽어도 Job 이 닫히지 않는다). 자식이 띄우는 작업은 round Job 을
         물려받고 작업 Job 에 중첩 편입된다(Windows 8+ 중첩 Job — 문서상 가능 · 재지 않았다 · 지금 코드에 빠져나가는 옵션이 없는 것은 확인).
         자식이 죽으면 TerminateJobObject(round Job, EXIT_CODE_OWNER_STOPPED) · 루프가 죽으면 KILL_ON_JOB_CLOSE
컨테이너  create 때 `gputeer.round=<round_id>` · `gputeer.loop=<loop_instance_id>` 라벨(바뀌지 않는다). 자식 사망 뒤 감독 우선 경로가 이 라벨로 찾는다
```

### 파이프 상속 금지 (c1e ⑤)

```text
Windows  자식은 시작 직후 자기 쪽 파이프 핸들의 상속 비트를 끈다(SetHandleInformation). 작업 spawn 은 PROC_THREAD_ATTRIBUTE_HANDLE_LIST 로 명시한 핸들만 넘긴다
리눅스   루프는 pipe2(O_CLOEXEC)로 만든다. 자식 spawn 의 pre_exec 에서:
           (1) 두 원본 fd 를 F_DUPFD 로 10 이상 번호에 먼저 옮긴다 — 원본이 이미 3 · 4 이거나 서로 엇갈린 경우(3→4 · 4→3)를 없앤다
           (2) dup2 로 3 · 4 에 놓는다 (3) 3 · 4 에 fcntl(F_SETFD, 0) 로 CLOEXEC 를 **명시적으로** 끈다 (4) 임시 fd 를 닫는다
           (모두 async-signal-safe 호출). agent-stub 은 시작 즉시 3 · 4 에 FD_CLOEXEC 를 다시 켠다. 작업 spawn 전 제어 fd 가 CLOEXEC 인지 확인 — 아니면 실행하지 않는다
```
