### 루프의 상태기계 — spawn · 되찾기 · 다시 켜기를 한 경계에서 (c1b ③)

```text
상태        Idle · Starting(자식 띄움 · GO 전) · Running(GO 뒤) · StopPending(정지 접수) · Reclaimed(되찾음 — 회차를 띄우지 않는다)
generation  상태가 바뀔 때마다 1 오르는 번호. 모든 명령 · 접수 번호 · 표식에 싣는다
경계        루프 안의 잠금 하나 — 회차 시작 결정 · 되찾기 표식 쓰기 · 다시 켜기(owner-resume)는 모두 이 잠금 아래에서만 상태를 바꾼다
표식        되찾기 표식 파일에 generation 을 적는다. 회차 시작 결정은 "Reclaimed 아님" 과 "표식 없음" 을 **잠금 안에서** 함께 본다
            → "표식 없음" 을 본 직후 정지 요청이 표식을 써도, 이미 결정된 자식은 GO 전이라 일을 받지 않는다(GO 는 잠금 안에서 다시 확인한 뒤 보낸다)
다시 켜기   owner-resume 은 루프가 떠 있으면 **루프 RPC**(127.0.0.1 패널의 POST /api/resume — 토큰)로만 한다. 루프가 없을 때의 CLI 는 파일 잠금 + 표식의
            generation 비교(CAS)로 지운다. StopPending 동안 다시 켜기는 거부(409) — 정지 결과가 나온 뒤에 한다
```

### 자식 기동 — GO 전에는 아무것도 하지 않는다 (c1b ③ ⑥)

```text
1 루프가 제어 파이프 두 개를 만들고(자식 쪽 끝만 상속 · 루프 쪽 끝은 비상속) 자식을 띄운다
  Windows  CREATE_SUSPENDED 로 띄움 → Job Object(KILL_ON_JOB_CLOSE)에 편입 → Job 핸들이 비상속인지 확인 → ResumeThread
           ★ 편입 전에 루프가 죽어도 자식은 멈춘 채라 아무것도 하지 않는다(고아가 돼도 일을 받지 않는다 · 사람이 보면 끝낸다)
  리눅스   systemd 유닛의 cgroup(KillMode=control-group — 루프 유닛이 멈추면 같이 끝난다 · 예상, 재지 않았다) + 자식이 prctl(PR_SET_PDEATHSIG)로 부모 사망을 받는다
2 자식이 기동 관문(되찾기 · 사건 · 쓰기 시험 · 남은 컨테이너 정리)을 지나면 제어 파이프에 READY(설정 digest 포함)를 보낸다. 거부하면 REFUSED(사유)
3 루프는 잠금 안에서 상태가 여전히 Starting 이고 되찾기가 아니며 설정 digest 가 같으면 GO 를 보낸다. 아니면 STOP_BEFORE_GO 를 보내고 자식은 끝난다
4 자식은 GO 를 받은 뒤에만 Coordinator 에 붙는다. 제어 파이프가 닫히면(루프 사망) 새 작업을 시작하지 않고, 도는 작업이 있으면 그대로 두되 끝난 뒤 다음을 받지 않는다
```

### 제어 프로토콜 — 전용 파이프 · 버전 · 상한 (c1b ②)

```text
형식      한 프레임 = 4바이트 길이(big-endian) + JSON 본문(UTF-8). 본문 상한 16KiB · 필드 문자열 상한 1KiB. 넘거나 깨지면 그 연결을 끊고 사건으로 남긴다(성공으로 읽지 않는다)
버전      첫 프레임 HELLO{version:1, ...}. 모르는 버전이면 루프가 STOP_BEFORE_GO
자식 → 루프  HELLO{generation} · READY{config_digest} · REFUSED{reason} ·
            WORKLOAD_STARTED{attempt_id, job_id, submitter_device_id, entrypoint, started_at_unix_ms} ·
            CHECKPOINT_COMMITTED{attempt_id, at_unix_ms} · WORKLOAD_ENDED{attempt_id, outcome} ·
            STOP_ACCEPTED{request_id, attempt_id} · STOP_RESULT{request_id, attempt_id, result, detail}
루프 → 자식  GO{generation} · STOP_BEFORE_GO · STOP{request_id, attempt_id, generation}
규칙      request_id 는 루프가 만든 단조 번호. 모르는 · 중복 · 순서 역전(ENDED 뒤 STARTED 등) · 다른 generation 프레임은 버리고 사건으로 남긴다.
          STOP 은 WORKLOAD_STARTED 로 알려진 **지금 attempt** 에만 보낸다 — 다른 attempt 면 루프가 409
```

### 지금 시도 정지 — 비동기 · 표식 먼저


### 남은 컨테이너 정지 — 자식 없이 루프가 (O3)

라벨로 찾은 컨테이너를 **확인한 ID 로** 멈추고(kill → 새 조회로 멈춤 확인) 결과를 위 세 이름으로 보인다. 지우지 않고 · 로그를 거두지 않고 · 사건 표식을 해제하지 않는다.
target 별 single-flight. 멈춘 사실은 사건 옆 기록으로 남긴다.

### 설정 — 한 번 만든 스냅샷 (c1b ④)

루프가 자기 인자로 Agent 설정을 **한 번** 만든다(지금 agent-stub 과 같은 파서 — 시드 파일 읽기 · 런타임 조합 검증 · 루트). 루프 모드에서는 `--checkpoint-root` 가
필수다. 루프는 그 결과를 **불변 설정 스냅샷 파일**(시드 자체는 넣지 않는다 — 시드 파일 경로 · 공개키 지문만)로 쓰고 자식은 그것만 읽는다(`--config-snapshot <파일>`).
digest 는 스냅샷 바이트의 BLAKE3 — 자식 READY 에 싣고 루프가 대조한다. 자식은 시드 파일을 읽어 공개키 지문이 스냅샷과 같은지 확인한다(시드가 두 사이에 바뀌면 거부).
배포 파일(agent.ps1 · 유닛)은 `--` 뒤 인자를 루프 앞으로 옮긴다(이관 — 이 조각 범위 · T14).

### 두 번째 홉의 보안 경계

루프 ↔ 자식은 HTTP · 토큰이 아니라 **부모만 쓰기 끝을 가진 비상속 OS 파이프**가 경계다. 다른 로컬 프로세스는 그 파이프에 닿지 못한다(같은 사용자의 프로세스가

| **공통 제약(단계 4)** | 런타임을 거치지 않는 정지는 양쪽 모두 플랫폼 도우미가 필요하다(Windows Docker Desktop 은 WSL 쪽) | 같다 |

**권고: A′.** B 의 장점(루프 crash 격리)은 크지만, 지금 시도의 상태 · 정지를 두 프로세스가 나누는 경쟁 설계가 더 크다. Windows 재시작 정책(O4)으로 A′ 의
crash 공백을 줄인다.
