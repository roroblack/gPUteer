## 문제 — 지금 코드에서 확인한 것

```text
1 패널은 회차 자식(agent-stub) 안에서 뜬다            crates/agent/src/lib.rs:712~733 (bind → serve_forever 스레드)
  agent-loop 는 회차마다 자식을 새로 띄운다           crates/cli/src/agent_loop.rs 머리말 — 회차 사이에 남는 것은 디스크뿐
  → 회차가 끝나면 패널도 끝난다. 일이 없어 기다리는 동안(--interval-ms)에도 패널이 없다

2 자식의 기동 순서                                  lib.rs:632~733
    되찾기 표시(OWNER_RECLAIMED) → 사건 관문(:656 open_incidents — 열려 있으면 거부) → 표식 폴더 쓰기 시험 → 남은 컨테이너 정리(:689)
    → 패널
  → 사건이 열려 있거나 남은 컨테이너 정리가 실패하면(런타임 무응답 포함) **패널을 열기 전에** 끝난다. 소유자는 CLI
    (`gputeer container-incidents`)로만 본다. 사람이 봐야 하는 상황일수록 화면이 없다

3 정지 손잡이는 같은 런타임 CLI(kill)다              container.rs ContainerStopper::stop
  → 런타임이 응답하지 않는 동안 눌러도 못 멈춘다 — 이것은 **단계 4**(런타임을 거치지 않는 정지)의 일이다. 이 설계는 그것을 풀지 않는다
```

## 요구 (완료 기준)

```text
R1  agent-loop 가 떠 있는 동안 패널이 계속 응답한다 — 회차 사이 · 기다리는 동안 · 자식의 기동 거부(사건 · 되찾기 · 정리 실패) · 런타임 무응답 중에도
R2  보여 준다: 지금 도는 시도(있으면 기존 손실 추정) · 열린 사건 표식(이름 · 종류 · 시각 · 내용 첫 줄) · 되찾기 표시 여부 · 마지막 회차의 결과 줄
    · 이 Agent 라벨의 남은 컨테이너(런타임이 시한 안에 답하면 — 못 답하면 "조회 못 함" 을 그대로)
R3  할 수 있다: (a) 지금 시도 정지(지금과 같은 의미 · 같은 결과) (b) 런타임이 답하지 않아 못 멈추면 **성공이라 하지 않고** 사유와 사람이 할 일을 보인다
R4  패널 요청 처리가 런타임 CLI 를 기다리지 않는다 — 런타임 조회는 백그라운드 · 시한 · 마지막 결과만 보인다
R5  127.0.0.1 전용 · 토큰 · Host 검사 — 지금 규칙 그대로(owner_panel.rs)
```

## 선택지

| | 무엇 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A** 루프가 패널을 쥐고 자식에 중계 | agent-loop 가 기동 때 패널을 먼저 연다. 자식에는 포트 0 을 넘겨 자식 패널의 주소 줄(`OWNER_PANEL listening=…`)을 루프가 읽는다(이미 줄 단위로 읽는다 — 결함 560). `/api/workloads` · `/api/stop` 은 **지금 자식**에 넘기고, 자식이 없으면 루프 자신의 정보(사건 · 되찾기 · 마지막 결과)만 | 자식의 정지 · 손실 추정 코드와 시험을 그대로 쓴다. 구조(회차 = 프로세스)를 안 바꾼다. Coordinator 와 무관하다 | 루프가 죽으면 패널도 없다(서비스 관리자가 다시 띄울 때까지 공백 — 정직하게 적는다). 중계 코드가 생긴다(요청 크기 · 시한 규칙을 한 번 더). 루프가 자식 설정 일부(시드 · 체크포인트 루트)를 알아야 한다 — O2 |
| **B** 별도 상시 프로세스 `gputeer owner-panel` | 디스크만 읽는다(사건 폴더 · 되찾기 표식 · 자식이 쓰는 "지금 시도" 상태 파일 · 단계 2 가 들어오면 노드 원장). 정지는 라벨로 찾은 컨테이너에 런타임 kill · 되찾기 표식 | agent-loop · 자식 · Coordinator 의 죽음 모두와 무관 — §0.1 문장에 가장 가깝다. 단계 4(호스트에서 직접 끝내기)를 얹을 자리 | 서비스가 하나 는다(설치기 둘 · 작업 스케줄러 · systemd 유닛 · 런북). 자식의 메모리 상태(손실 추정의 step · 시각)를 파일로 내보내야 한다. 정지를 두 프로세스가 할 수 있어 경쟁(멱등 · 결과 판정)을 새로 설계해야 한다 |
| **C** Agent 를 상주 데몬으로 | 회차 루프를 한 프로세스 안에 | 패널이 자연히 산다 | `agent_loop.rs` 머리말이 기각한 이유 그대로(회차를 건너는 상태 누수 · 연결 번호 · replay · 잠금) · 기존 시험 대부분을 다시 — **권하지 않는다** |

**권고: A 를 먼저, B 는 단계 4 와 함께 다시 판단한다.** R1~R5 는 A 로 채운다. A 가 못 채우는 것은 "루프 자체가 죽은 동안" 뿐이고, 그때는 자식도 없어
새로 시작되는 작업이 없다(도는 컨테이너는 남을 수 있다 — 그것을 끝내는 길은 어차피 단계 4 다). B 는 단계 4 의 "런타임을 거치지 않는 정지" 가 필요로 하는
권한 · 플랫폼 등급이 정해진 뒤에 판단하는 편이 설치 표면을 한 번만 늘린다.

## A 의 세부

```text
기동       agent-loop 가 첫 회차 **전에** 패널을 연다. 못 열면 루프를 시작하지 않는다(OWNER_PANEL_REFUSED — 지금 자식 규칙과 같다)
포트       운영자가 준 포트는 루프가 쥔다. 자식에는 --owner-panel-port 0 을 루프가 붙인다
           ★ 지금 루프는 `--` 뒤 인자를 해석하지 않는다(두 곳에서 해석하면 규칙이 갈라진다 — 머리말). 그래서 루프가 자식 인자를 **자기 식으로**
             읽지 않고, Agent 크레이트의 **같은 파서**(agent-stub 이 쓰는 공개 함수 `parse_config_from_args` — lib.rs:4425)를 불러 읽는다 — 해석은 한 곳, 호출이 둘이다(O2)
           `--` 뒤에 --owner-panel-port 가 따로 있으면 루프가 거부한다(자식이 고정 포트를 잡아 충돌하지 않게)
토큰       지금처럼 시드에서 파생(derive_owner_panel_token) — 루프도 같은 시드로 같은 토큰을 얻는다(즐겨찾기가 재시작을 넘는다 · 기존 시험)
중계       루프 → 127.0.0.1:<자식 포트> 로 같은 요청을 보낸다. 시한(예 5초) · 응답 크기 상한 · 자식 응답을 **그대로** 돌려준다(자식이 "못 멈춤" 이면
           성공으로 바꾸지 않는다). 자식이 끝났으면 자식 주소를 지운다(끝난 회차의 포트를 다른 프로그램이 잡을 수 있다)
사건       루프가 사건 폴더를 읽는다(container::open_incidents · 읽기 실패는 "모름" 으로 보인다 — 결함 499 와 같은 방향)
남은 컨테이너  루프의 백그라운드 스레드가 주기적으로(예 30초) 라벨 조회(container ps · 시한). 요청은 마지막 결과와 그 시각만 읽는다(R4)
정지       자식이 있으면 자식에 중계. 없으면 "도는 작업 없음"(409) — 성공이라 하지 않는다
           남은 컨테이너(자식 없음)를 패널에서 멈추는 것은 **이 설계에 넣지 않는다** — 지금 규칙은 사람이 확인하고 해제한 뒤 다음 기동이 정리한다.
           패널이 그것을 대신하면 사건 표식의 뜻(사람이 본다)이 바뀐다 — O3
되찾기     지금은 패널 정지 = 되찾기(lib.rs:1687 — 정지하면 되찾기 표시를 쓴다). 루프는 표시가 있으면 회차를 띄우지 않고 기다린다(지금은 매 간격마다
           자식이 떠서 OWNER_RECLAIMED 로 끝난다 — 로그만 쌓인다. `agent_loop.rs` 에서 "RECLAIM" 을 찾았고 0건이다 — 루프는 거부를 "일 없음" 과 가르지 않는다)
```

## 시험 (negative test — `RULE.md` §6)

```text
T1  자식이 기동에서 거부(열린 사건)해도 패널이 응답하고 그 사건을 보인다 · 대조군: 사건 없음 → 목록 빔
T2  런타임 무응답(가짜 런타임의 ps 가 답하지 않음) 중 패널 응답이 시한보다 훨씬 짧다 · "조회 못 함" 이 보인다
T3  자식이 없을 때 정지 요청은 성공으로 답하지 않는다(409)
T4  중계: 자식이 "못 멈춤" 이면 루프도 그대로 전한다 · 자식이 끝난 뒤 그 포트로 중계하지 않는다
T5  `--` 뒤에 --owner-panel-port 가 있으면 루프가 시작하지 않는다
T6  127.0.0.1 외 Host · 토큰 없음 · 틀린 토큰 — 루프 패널도 거부(기존 시험을 루프 패널에 다시 건다)
T7  되찾기 표시가 있으면 루프가 자식을 띄우지 않는다 · 지우면(owner-resume) 다시 띄운다
```

## 하지 않는 것

- 런타임을 거치지 않는 정지(단계 4) — R3(b) 는 "못 멈췄다" 를 정직하게 보이는 데서 멈춘다
- Coordinator 에 불명 · 정지 확인을 알리는 것(단계 2 계약) — 계약이 승인되면 패널의 "정지 확인" 버튼이 그 알림의 출발점이 된다(그때 다시 본다)
- 원격 접속 · 여러 노드 한 화면 — 127.0.0.1 규칙 그대로
