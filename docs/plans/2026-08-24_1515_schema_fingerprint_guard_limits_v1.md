# Schema fingerprint guard limits v1

## 목적

`crates/protocol/tests/schema_fingerprint.rs`의 경량 proto 파서는 필드 집합을
지문화하지만, 중첩 `message`와 `reserved`를 안전하게 표현하지 못한다. 현재
스키마에는 두 구문이 없으므로 기존 가드는 이 한계가 도입되는 순간에도 조용히
계속 실행될 수 있었다.

이번 변경의 목표는 중첩 메시지를 지원하는 범용 파서를 만드는 것이 아니다.
지원하지 않는 구문이 `PROTO_FILES`에 들어오면 지문 계산보다 먼저 명확히
실패하게 하고, 현재 파서의 실제 동작을 합성 입력으로 고정하는 것이다.

## 설계

### 지원 구문 사전 검사

주석과 문자열을 제외하고 식별자 및 중괄호만 읽는 최소 lexer를 테스트 파일에
추가한다. 이를 사용해 다음을 검사한다.

- 메시지 스코프 안에서 다시 선언된 `message`를 중첩 선언으로 판단한다.
- `reserved` 키워드가 나타나면 도입을 거부한다.
- 오류에는 파일과 줄, 현재 파서가 위험한 이유, 도입 전에 해야 할 작업을 담는다.

`parse_proto`가 파일을 읽은 직후 이 검사를 호출하므로 기존 지문 테스트를
개별 실행해도 조용히 잘못 파싱하지 않는다. 별도 테스트도 `PROTO_FILES` 전체를
검사해 의도를 드러낸다.

lexer는 `//`, `/* ... */`, 따옴표 문자열 안의 키워드를 무시한다. 완전한 proto
파서가 아니라 지원 한계 탐지기이며, 중첩 메시지를 지원하도록 확장하지 않는다.

### 파서 합성 입력

파일 읽기와 파싱을 분리해 `parse_proto_source(file, src)`가 문자열을 받도록 했다.
production proto 파일과 지문 파일은 변경하지 않는다.

유효한 `reserved` 문법에는 `=`가 없다. 기존 코드는 `=` 분해에 실패해 결과적으로
예약 선언을 건너뛰었지만, 그 뒤의 명시적인 `reserved` 분기는 유효한 입력에서
도달할 수 없었다. 분기를 `=` 분해 앞으로 옮겨 숫자 범위 예약과 이름 예약을
합성 입력으로 검증한다. 파싱 결과는 기존과 동일하다.

중첩 합성 입력은 지원 검사 없이 원래 파싱 함수에 직접 전달한다. 그 결과 Inner
필드는 `Outer`에 기록되고, Inner가 Outer와 같은 번호를 쓰면 Inner 선언이 Outer
선언을 덮어쓰며, `Inner` 키는 생성되지 않는다. 이 실패 양상을 회귀 테스트로
고정하되 실제 파일 경로에서는 사전 검사가 먼저 거부한다.

## oneof 이동

이번 변경에서는 필드의 `oneof` 안팎 이동을 탐지하지 않는다. 현재 지문 본문은
번호·타입·이름만 기록하므로 이동 전후 입력이 동일하다. 이를 강제하려면 oneof
소속을 지문 표현에 추가해 기록 지문을 변경하거나, 별도의 영속 기준선을 새로
도입해야 한다. 지문 값 변경이 금지된 이번 작업에서 임시 하드코딩 기준선을
추가하는 것은 두 기준선의 동기화 문제를 만들므로 범위 밖으로 남긴다.

## 뮤테이션과 결과

실제 `proto/` 파일 대신 합성 문자열 두 건을 사용한다.

1. `Outer` 안에 `Inner`를 추가한 입력은 중첩 메시지 오류를 반환하며, 오류가
   Outer 소속 기록과 번호 충돌 덮어쓰기 위험 및 파서 확장 요구를 설명한다.
2. `Synthetic`에 `reserved 2, 4 to 6;`를 추가한 입력은 예약 선언이 지문에
   나타나지 않는다는 오류와 지문 표현·회귀 테스트 확장 요구를 반환한다.

추가로 합성 파서 테스트에서 `reserved` 숫자/이름 선언이 필드로 기록되지 않고
정상 필드만 남는 것을 확인했다. 중첩 합성 입력에서는 번호 1의 Outer 필드가
Inner 필드로 덮어써지고 번호 2의 Inner 필드도 Outer에 들어가는 것을 확인했다.
