## 왜 지금

신뢰망 풀은 돈다. 그런데 **작업이 노드 소유자와 같은 권한 · 같은 파일시스템 · 같은 네트워크에서** 돈다.
지금 걸린 것은 메모리 상한(Job Object · cgroup)뿐이고, 둘 다 "작정한 코드는 못 막는다" 고 이미 적어 뒀다
(`CLAUDE.md` §5 "가장 위험한 공백"). 규범은 이 자리를 컨테이너(S3)로 채운다고 정해 두었고, 계약도 이미 있다 —
`JobManifest.env`(`ExecutionEnvironment`)의 `kind == OCI_IMAGE` · `image_ref` · `oci_source_digest`.
**계약은 있는데 그것을 실행하는 코드가 없다.**

## 결정 — 직접 네임스페이스를 짜지 않고 컨테이너 런타임(podman · docker)을 부른다

| 길 | 얻는 것 | 잃는 것 |
|---|---|---|
| A. 네임스페이스 직접(unshare · pivot_root · seccomp) | 외부 의존 없음 | 읽기 전용 rootfs · seccomp · 장치 허용 목록을 전부 새로 짜야 한다 — 검증된 도구를 다시 만드는 일 |
| **B. podman/docker CLI 를 부른다** | 기준선 그대로(`LinuxContainer` = rootless podman) · 검증된 격리(읽기 전용 rootfs · 기본 seccomp · cap drop · netns · pidns) · Windows 에서는 Docker Desktop(WSL2)이 같은 CLI 로 `Wsl2Container` 가 된다 · CI 러너에 docker 가 있어 **실제 격리를 CI 가 잰다** | 노드에 런타임 설치가 필요하다(→ 다음 조각: 설치 자동화) · 런타임 자체의 신뢰(docker 그룹 = root 와 같다 — rootless podman 을 권한다) |

B 를 고른다.

## 범위

### In (조각 1)

- Agent opt-in `--container-runtime <podman|docker 실행 파일>`. 주지 않으면 전과 같다(OCI_IMAGE Job 은 거부 — 아래)
- `manifest.env.kind == OCI_IMAGE` 인 Job 을 컨테이너로 실행한다:
  - 이미지는 **`oci_source_digest`(sha256)로 고정**해 부른다 — `image_ref@sha256:<hex>`. digest 가 없으면 거부(태그는 움직인다)
  - `--read-only` · `--tmpfs /tmp` · `--cap-drop ALL` · `--security-opt no-new-privileges` · 런타임 기본 seccomp
  - `--memory` = `--memory-swap` = 커밋 상한(스왑으로 새지 않게 — cgroup 경로의 2026-08-30 교훈과 같다) · `--pids-limit`
  - 네트워크: `network.runtime_allow_hosts` 가 비었으면 `--network none`. 비어 있지 않으면 **거부**(허용 목록을 강제할 수단이 없다 — 강제 못 하는 것을 선언하지 않는다)
  - ~~작업 폴더만 쓰기로 붙인다(`/gputeer/work`)~~ ★ 재검수 88 — 작업 폴더 전체를 붙였고 이어받기 읽기 전용은 구현되지 않았다(결함 273 · 279).
    고친 뒤: 체크포인트 폴더만 쓰기(`/gputeer/checkpoints`) · 이어받기 폴더 읽기 전용(`/gputeer/resume`) · 환경 변수는 컨테이너 안 경로로 바꿔 준다
  - 이름은 attempt 별(`gputeer-<attempt 파생>`) — cgroup 이름과 같은 이유
- 수명: `create` → `start` → `wait` → `inspect`(종료 코드 · OOMKilled) → `rm -f`. `run` 의 종료 코드는 런타임 오류(125~127)와 작업 종료가 섞여서 쓰지 않는다
- 소유자 정지: `kill` → `rm -f`(§0.1 — Owner Panel 의 정지 손잡이가 컨테이너에도 닿는다)
- `OCI_IMAGE` 가 아닌 Job 은 전과 같다. `--container-runtime` 없이 `OCI_IMAGE` Job 이 오면 **ACK 전에 거부**한다(호스트에서 조용히 돌리지 않는다)
- 시험: 인자 조립 순수 시험(개발 기계) · 가짜 런타임으로 수명 · 정지 · 거부 경로(개발 기계) · **실제 docker 로 격리 확인**(CI 리눅스 — 읽기 전용 루트 · 네트워크 없음 · 메모리 초과 시 OOMKilled · 붙인 폴더 밖 쓰기 불가)

### Out

- GPU 를 컨테이너에 넘기기(CDI `nvidia.com/gpu=<uuid>` · `--gpus`) — x600 실측이 필요하다(조각 2)
- `image_digest`(BLAKE3 CAS) 대조 — 지금은 `oci_source_digest`(런타임이 내용으로 검증하는 sha256)만 쓴다. BLAKE3 대조는 CAS 가 생긴 뒤
- 이미지 받기 정책(사설 레지스트리 · 인증 · 오프라인 캐시) — 조각 1 은 런타임 기본(`--pull=missing`)
- 네트워크 허용 목록 강제(중계 프록시 — 정지 보장 1층과 같은 자리)
- 노드 설치 자동화 · UI — 별도 계획

## 기준선과 다른 점

- 기준선은 rootless podman 을 적었다. 조각 1 은 podman 과 docker 를 같은 CLI 모양으로 받는다(Windows 노드는 Docker Desktop 이 WSL2 로 돈다).
  docker(rootful) 를 쓰면 **docker 그룹이 곧 root** 라는 사실을 런북에 적고, 권장은 rootless podman 이다.
