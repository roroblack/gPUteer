# rustfmt 서식 드리프트 정리 계획 (★ 2026-08-27 실행 완료)

## 상황

`rustfmt` 를 이 저장소에 처음 설치한 뒤 `cargo fmt --all -- --check` 를
돌려보니 **약 69개 파일**이 표준 서식과 어긋나 있다. 들여쓰기·줄바꿈
위치 수준이며 **동작에는 영향이 없다**.

그동안 여러 조각에서 코덱스가 "`cargo fmt --check` 를 실행하지 못했다"
고 보고해 온 것도 컴포넌트가 설치돼 있지 않았기 때문이다. 지금은
`rustfmt` 와 `clippy` 둘 다 설치돼 있다.

## 결정 — 지금은 하지 않는다

전체 재포맷은 수백 개 hunk 규모다. 그 커밋이 들어가면 이후
`git blame` 이 대부분의 줄을 "서식 정리" 로 가리켜, **기능 변경의
이력을 덮는다.** 이 저장소는 각 변경의 의도와 검수 이력을 추적하는
것을 규율로 삼고 있으므로 그 손실이 서식 일관성보다 크다.

실제로 이 저장소에서 `cargo fmt` 가 의도치 않게 워크스페이스 전체
46개 파일을 재포맷하는 사고가 한 번 있었고, 복구에 시간이 들었다.
그래서 이후 작업 프롬프트에는 `cargo fmt` 실행 금지를 명시하고 있다.

## 하게 된다면 — 순서

1. **서식만 하는 단일 커밋**으로 분리한다. 다른 변경을 절대 섞지
   않는다. 커밋 메시지에 "동작 변경 없음" 과 재현 명령을 적는다.
2. 그 커밋 해시를 **`.git-blame-ignore-revs`** 에 등록한다.
   ```
   git config blame.ignoreRevsFile .git-blame-ignore-revs
   ```
   이러면 `git blame` 이 그 커밋을 건너뛰어 이력 손실이 사라진다.
   이 파일이 없으면 1번의 대가가 그대로 남으므로 **같은 커밋에서**
   함께 넣는다.
3. **재발 방지** — CI 에 `cargo fmt --all -- --check` 를 추가한다.
   이 단계가 없으면 드리프트가 다시 쌓이고 같은 결정을 반복하게
   된다.
4. 적용 직후 워크스페이스 전체 테스트로 무회귀를 확인한다. 서식
   변경은 동작을 바꾸지 않아야 하므로, 하나라도 실패하면 그것은
   서식 문제가 아니라 진짜 결함이다.

## 하지 말 것

- 다른 작업 도중 `cargo fmt` 를 실행하는 것. 범위가 섞이면 되돌리기
  어렵다(실제 사고 사례가 있다).
- `--check` 없이 부분 실행하는 것. 크레이트 단위로 나눠 커밋하면
  `.git-blame-ignore-revs` 항목이 늘어나기만 한다.

## 현재 상태

★ **2026-08-27 실행 완료** — 사용자가 "이런건 백업 띄어두고
작업해야지" 라고 지시해 백업 후 진행했다. 위 4단계를 그대로 따랐다.

```text
백업      git tag backup/pre-rustfmt-2026-08-27 (7c818cc)
          + scratchpad 에 91개 .rs 물리 사본
1 서식만  e98db9a — 75개 .rs 파일, 다른 변경 미혼합
2 blame    .git-blame-ignore-revs 신규 + 그 해시 등록
          (자기 해시를 자기 커밋에 넣을 수 없어 다음 커밋에서 등록)
3 재발 방지  CI 에 cargo fmt --all -- --check 단계 추가
4 무회귀    서식 전후 584 passed 동일, selftest 73/73,
          canonical 48개 백터 일치, 빌드 경고 0
```

실측으로 확인한 것: `git blame` 이 서식 커밋을 건너뛰고 원래
커밋(예: `a210eac8`, 2026-08-21)을 가리킨다 — 이 계획이 걱정하던
이력 손실은 실제로 발생하지 않는다.

★ 검증 과정의 교훈 — 문자열 정규화로 "서식만 바뀜는가" 를
확인하려던 시도가 두 번 오킐0을 냈다. 첫 번째는 스크립트가 출력
인코딩 오류로 죽어 부분 출력끼리 비교됐고, 두 번째는 rustfmt 가
정당하게 하는 `map_err(|_| { X })` -> `map_err(|_| X)` 를 정규화기가
모델하지 못해 25건을 "내용 변경" 으로 불렀다. **Rust 파서 없이
문자열로 이 검증을 할 수 없다** — 실제 근거는 테스트 수치 일치다.

되돌리려면:

```bash
git reset --hard backup/pre-rustfmt-2026-08-27
```
