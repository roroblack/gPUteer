# 2부 — B+E 구현 단계 5a: RENEW 세션(Coordinator) (계획서 §9)

```text
read_session_hello -> mode 로 가른다 — FRESH(connection_attempt 대조 뒤 Grant) · RENEW(serve_renew_session) · 그 밖 HELLO_REJECTED
serve_renew_session — --lease-db 필수 · 저장된 Lease 의 보유자 · 세대 · 만료로 판정 · 낮은 세대 SUPERSEDED · 높은 세대 거부 ·
                      build_renew_result · 한 건 응답하고 닫는다
테스트 · 뮤테이션    새 연결 갱신 · SUPERSEDED · 저장소 없는 RENEW 거부 · M22~M27
```

물을 것:
4. RENEW 세션이 FRESH 연결 안의 갱신과 **같은 규칙**을 쓰나 — revoke · max_total_duration · 만료 경계(`<=`) · 요청 nonce echo ·
   Agent 쪽이 기대하는 결과 검증(서명 · coordinator_id · 중첩 Lease 독립 서명)을 통과할 결과인가.
5. RENEW 의 connection_attempt 를 대조하지 않은 판단 — 재생 · 교차 세션 혼동의 여지가 생기나(요청 nonce · Hello nonce 로 충분한가).
6. `build_renew_result` 오류를 전부 Storage(fail-closed)로 둔 것 — 상대가 유발할 수 있는 오류가 섞여 리스너를 멈출 수 있나.
7. 순차 Coordinator 가 FRESH 연결을 붙잡는 동안 RENEW 연결은 대기열에 있다 — 이 구조로 5b(Agent 실행 중 갱신)가 성립하나.
   이번에 하지 않은 것(5b · 생존 관측 기록 · REPORT 세션 · 88 · 리눅스)을 했다고 적은 문장이 있나.
