주장하는 자리**를 찾아 달라.

# 물을 것 — 네 가지

1. **"되는 것" 목록이 실제로 재현된 것인가.** 특히 **가둠**(컨테이너
   안에서 호스트 파일을 못 읽는다)이 핵심이다. 이 테스트에는 이력이
   있다 — **첫 판은 컨테이너 밖에서도 통과하는 공허한 테스트였다**
   (`cmd /c exit 42` 의 종료 코드만 봤다). 지금 판이 그 함정을 정말
   벗어났는지, **대조**(밖에서는 읽힌다)가 실제로 있는지 확인하라.

2. **소거한 가설 넷에 각각 대조가 있나.** 문서는 네 가설(상위 경로 권한 ·
   컨테이너 TEMP · capability 주입 · 다른 Python 배포판)을 소거했다고
   적었다. 각각이 **"해 봤는데 안 됐다"** 인지 **"바꿨는데도 같은
   실패였다"** 인지 원문에서 확인하라. 전자는 소거가 아니다.

3. **결론이 측정을 넘어서지 않는가.** 문서 안에
   **package identity 가설**이 나온다. 그것이 어디에서는 "추측이며 확인
   안 했다" 라고 적혀 있는데, **다른 자리에서 결론처럼 쓰이고 있지
   않은가**? 한 문서 안에서 같은 것을 두 가지 무게로 말하면 읽는 사람은
   무거운 쪽으로 기억한다.

4. **`status: INCONCLUSIVE` 가 맞는 판정인가.** 근거는 "S2 를
   EXPERIMENTAL 로 유지" 쪽으로 기운다고 적혀 있다. 그런데도 확정하지
   않은 이유가 **정당한가**, 아니면 판정을 미루는 핑계인가? 반대로,
   지금 자료로 `FAIL-SCOPE` 를 쓸 수 있다고 볼 근거가 있나?
