# 2. 결함 ㊱ 수정 — out_file 임시 이름에 프로세스 전역 번호

```text
전   <대상>.tmp.<pid>.<n>          호출마다 n = 0 부터 — 같은 프로세스의 동시 쓰기가 같은 이름을 두고
                                   만들고 지우기를 번갈아 했다. Windows 에서 그 순간 create_new 가
                                   PermissionDenied 를 돌려주는 것을 경쟁 실험이 관측했다
지금 <대상>.tmp.<pid>.<seq>.<n>    seq 는 호출마다 받는 AtomicU64. n 은 앞 실행의 잔여를 비켜 가는 데만 쓴다
택하지 않은 것  PermissionDenied 를 다음 번호로 넘기기 — 권한 없는 디렉터리에서 64번을 헛돈다
```

테스트: `a_temp_name_is_not_reused_within_a_process`(지운 이름을 다음 호출이 다시 쓰지 않는다) ·
`leftover_temps_under_the_current_name_are_kept`(지금 이름의 남은 파일을 안 건드린다 — 번호가 전역이라
앞으로 받을 범위 256개에 미리 깐다). 뮤테이션: 이름을 이전 모양으로 되돌리면 회귀 테스트가 실패했다.
측정: 수정 뒤 경쟁 테스트 20회 모두 통과(수정 전 10회 중 3회 실패 — 교대로 재지 않았다).

# 물을 것 — 넷

1. **42 의 지적이 닫혔나.** 고친 문장이 또 새 단정을 만들지 않았나.
2. **㊱ 수정이 맞나.** 같은 프로세스 안에서 두 호출이 같은 이름을 시도할 수 있는 경로가 남았나 ·
   다른 쓰기의 파일을 건드리는 경로가 생겼나 · 번호가 넘치거나 되돌아가는 경우.
3. **새 테스트가 판별력이 있나.** 특히 `leftover_temps_under_the_current_name_are_kept` 가 다른 테스트와
   번호를 나눠 쓰는데도 뜻을 유지하는가.
4. **측정 기록이 범위 안인가** — 20회 통과가 무엇을 말하고 무엇을 말하지 않는지.
