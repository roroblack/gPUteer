# AI 도구 운용 — 역할 분리와 교차검증

> 규범: `RULE.md` §3.6 (역할 분리, 도구 중립) · `CLAUDE.md` §4 (검증 원칙)
>
> ★ `RULE.md` 가 이 문서를 가리키고 있었는데 **파일이 없었다.**
> 독립 검수(2026-08-16)가 찾았고, `scripts/check_docs.py` 에 경로 존재 검사를 넣었다.

## 왜 이 문서가 있는가

`RULE.md` 는 **역할**만 정하고 도구를 정하지 않는다.
그러나 실제로 어떤 도구를 어떻게 쓰는지는 재현에 필요하다 —
"독립 검수를 받았다" 는 서술만 있으면 다음 사람이 같은 일을 할 수 없다.

## 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **구현자** | 계약 → 구현 → 테스트 → evidence | 자기 구현을 자기 테스트로 인증 |
| **독립 검수자** | **반박**. 구체적 반례 제시 | 구현 |
| **통합 책임자** | 공용 파일 변경 승인 (`RULE.md` §4.2) | — |

★ **한 사람(또는 한 모델)이 세 역할을 다 하면 교차검증이 아니다.**
`CLAUDE.md` §4 — "중요한 판단은 독립 검수자와 교차검증한다."

## 독립 검수 — 실제 절차

2026-08-16 세션에서 쓴 방식이다.

```bash
codex exec --sandbox read-only -c model_reasoning_effort=high - < <프롬프트 파일>
```

`--sandbox read-only` 를 **반드시** 쓴다. 검수자가 코드를 고치면 검수가 아니다.

### 프롬프트에 반드시 넣을 것

```text
1. "동의가 아니라 **반박**을 원한다" 를 첫 줄에 적는다
2. 읽을 파일을 **구체적으로** 나열한다 (추측으로 답하지 않게)
3. 공격 지점을 질문 형태로 준다 — "괜찮은가?" 가 아니라 "무엇이 틀렸나?"
4. **"못 찾았으면 못 찾았다고 하고 어디까지 확인했는지 적어라"**
   -> 이것이 없으면 없는 문제를 지어낸다
5. 각 지적에 파일:줄 번호와 구체적 반례를 요구한다
```

### 지적을 받은 뒤

★ **액면 그대로 받지 않는다.** `RULE.md` §3.1 — 오진 위에 수정을 쌓지 않는다.

```text
1. 각 지적이 실제로 성립하는지 **테스트로 먼저 확인**한다
2. 성립하는 것만 고친다
3. 성립하지 않으면 그 사실을 기록한다 (검수자가 틀릴 수 있다)
4. 성립하는데 안 고치기로 했으면 **그 이유를 evidence limitations 에 적는다**
   — 숨기지 않는다
```

실제로 2026-08-16 세션에서:

```text
검수자가 맞은 것        canonical 규칙 3건 · replay nonce 결속 · 경로 탈출 ·
                        내 테스트 5건의 공허성 · 내 문장의 과장
내가 먼저 틀린 것       "artifact 0건 누락" 이라고 답한 내 확인 스크립트가
                        frontmatter 파싱 버그로 오답을 냈다.
                        검수자를 반박하려다 내 스크립트가 틀렸음을 발견했다
```

### 프롬프트 크기 주의

큰 프롬프트(파일 6개 이상 나열 + 질문 6개)에서 **캐시 오류로 분석이 안 나온 적이 있다.**
파일 1~2개 · 질문 4개 이하로 쪼개면 안정적이다.

## 검수 결과를 어디에 남기는가

```text
docs/evidence/DoD-NN_*.md    지적 → 실측 확인 → 시정 여부를 evidence 로
                             negative_tests 에 "무엇을 확인했는가"
                             limitations 에 "무엇을 안 고쳤는가"
docs/decisions/ADR-NNN_*.md  설계 판단이 바뀌면
docs/history/HISTORY.md      세션 기록
```

★ **검수 원문을 저장소에 넣지 않는다.** 수십만 바이트이고 대부분 파일 덤프다.
evidence 에 **재현 명령과 결론**을 적는다 — 그것이 재현 가능한 기록이다.

## 한계 — 이 절차가 막지 못하는 것

★ 독립 검수자의 최종 판정을 그대로 옮긴다.

> 이 저장소의 가드는 "잘못된 사람이 문서 형식을 어겼는가" 는 어느 정도 잡지만,
> **"잘못된 사람이 형식을 지키면서 틀린 주장을 제출했는가" 는 거의 잡지 못한다.**

```text
검수자가 한 모델뿐이다        다른 검수자는 다른 것을 본다
evidence 에 검증자 신원이 없다  누가 실행했는지 기록되지 않는다
raw_output 이 요약이다        _raw/ 원문과 byte 대조가 강제되지 않는다
검수 자체가 선택적이다        "독립 검수를 받아라" 를 강제하는 검사가 없다
```

## 2026-08-17 — 네 항목을 검수자와 함께 다뤘다 (ADR-030 · `RULE.md` §7.3)

★ 검수자와 **설계를 논의**했다. "해결됐다" 가 아니라
  **"어디까지 기계가 막고 어디부터 사람의 책임인가" 를 갈랐다.**

| 항목 | 기계가 막게 된 것 | 여전히 못 막는 것 |
|---|---|---|
| **검수자 단일** | `executor_id != reviewer_id` · `review_context == fresh-read-only` | 두 모델이 같은 학습 편향을 공유하는 것 |
| **검증자 신원 없음** | `executor_*` · `reviewer_*` 필수 · 제로폭/비ASCII 위장 거부 | 기록된 신원이 **사실인지** — 인증이 아니라 provenance 다 |
| **raw_output 대조 없음** | `raw_output_artifact` + `sha256` + byte 수 대조 | 요약이 원문을 **정직하게** 요약하는가 · 둘을 함께 고친 경우 |
| **검수가 선택적** | `P0-*`·`DoD-*` 의 `PASS` 는 검수 receipt 없으면 오류 | 검수자가 **정직했는가** |

### 검수자가 정정한 것

**BLAKE3 를 쓰려던 계획이 틀렸다.**
`verify_evidence.py` 는 Python 표준 라이브러리만 쓰는데 stdlib 에 BLAKE3 가 없다.
`cargo` 나 외부 패키지에 의존시키면 **검사기를 못 돌리는 환경**이 생기고,
검사기를 못 돌리면 규칙도 없다. → `hashlib.sha256` 을 쓴다.

### 검수자가 실제로 뚫은 것 (구현 직후 2차 검수)

v2 를 만들고 나서 **같은 검수자에게 우회 경로를 찾게 했다.**
검수자가 실제로 실행해 다음을 통과시켰다 — 전부 고쳤다.

```text
치명  유예 목록에 한 줄 추가하면 새 v1 evidence 가 검수 없이 통과
      -> 목록의 sha256 을 코드에 상수로 박았다. 늘리려면 diff 에 드러난다

중대  review_outcome 을 두 번 적으면 마지막 값이 이긴다
      -> 중복 키 자체를 거부한다

중대  reviewer_id 끝에 U+200B 를 붙이면 눈으로 같은 두 신원이 된다
      -> 신원 필드의 제로폭·제어·비ASCII 문자를 거부한다

중대  파일명을 ENV-99.md 로 바꾸면 검수 강제가 사라진다 (id 는 DoD-09)
      -> id 로도 판정하고, id 와 파일명 불일치 자체를 오류로 만든다

중대  review_artifact 로 소스 파일을 적으면 길이·정규식을 자연히 만족한다
      -> _raw/ 아래만 허용한다

중대  ("LGTM. " * 40) + "fake.py:1" 이 통과한다
      -> 인용한 파일이 저장소에 실재하는지까지 본다

중대  NTFS ADS(`x.txt::$DATA`) · 8.3 단축이름 · symlink 로 다른 파일을 가리킨다
      -> realpath 로 풀어 저장소 안인지 대조하고, 콜론을 거부한다
```

★ **검수자는 내 부정 테스트의 공허성도 5건 지적했다.**
`check_file()` 만 부르고 종료 코드를 안 봤다 · 부분문자열 하나로 판정했다 ·
파일명 우회를 실제로 시험하지 않고 전역 상수를 바꿨다 — 전부 고쳤다.

> 검사기를 만들면 **그 검사기도 검수를 받아야 한다.**
> 강제 장치가 강제하는지 증명하지 않으면 "통과했다" 와 "아무것도 안 본다" 가 같다.

### 남은 것

```text
기존 evidence 13건에 독립 검수 기록이 없다 (schema v1 유예)
  -> verify_evidence.py 가 매번 그 숫자를 출력한다. 줄이는 것이 진전이다.

검수 품질 자체는 자동 판정할 수 없다
  -> 정기적으로 몇 건을 사람이 다시 읽는 샘플링이 현실적인 차선책이다.
```
